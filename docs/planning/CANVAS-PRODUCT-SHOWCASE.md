# Forma canvas showcase — Spend and Jacket Reminder

The two demos show how an app gets context. Spend starts with an uploaded file. A user can explore its transactions in an app and ask a calculator to use that same data. Jacket Reminder starts with an intent. The user connects a Weather widget and two delivery widgets, then asks the app to act on those connections.

The preserved local branch is `showcase/spend-and-jacket`. Everyday development is on `main` ([ADR-019](../architecture/ADR-019-MAIN-TRUNK-AND-RESERVATION-CAP.md)). The last product commit before the Spend rehearsal was `6f7f7d3`. To replay the prepared paths, use the showcase branch with the pitch preview at `http://localhost:4001/canvas`, bring your own September spreadsheet, and use the steps below. The branch preserves the implementation. Uploaded files, sign-in state and browser placements live outside Git.

## From an upload to an app

1. Upload a CSV or XLSX directly onto the canvas. Its file card appears immediately. Double-click to open the original in a full-size sheet viewer. Large sheets page in both directions. Closing the card removes its placement, and **Library → Cards → Add** brings it back. Dragging the card onto a folder copies the file there.
2. Ask a question in the file card. At this point the question is about the selected original. Choose **Make an app**, inspect the inferred column types, describe the purpose and confirm the build. When placement succeeds, an app card takes the file card's position. Cancelling or failing the build leaves the file available.
3. Open the app. **Card** shows its identity, **Browse** shows one component at a time, and **Open** shows the full component layout. All three are views of one saved app. The arrow moves the whole object, the hand pans the canvas, and holding Space temporarily pans while using the arrow. Buttons, text fields and scroll areas inside the app retain their own interactions.
4. Use the single **App assistant** control to open the companion beside the app. **Sources → View original** opens the large viewer. Ask can target app records or a specific source file. **Summary** brings back the app's explanation. **Save answer** keeps a private snapshot in **Saved**. **Place on canvas** lays out a linked answer card, and **Put all away** files this app's answer cards without deleting the snapshots. A fresh question can produce a new answer as the data changes.
5. In an ordinary supported spreadsheet app, choose **Ask → Change data**, select **Add** or **Update**, choose the target record for an update, then describe the change. Review the proposed field values and confirm. The app executes its declared action against its independent records, rechecking permissions and record versions. The original file remains available exactly as uploaded. The builder handles changes to app structure, layout and theme.

Viewing and importing have different limits. Original files up to 20 MiB can be viewed in windows of 50 rows by 32 columns, subject to parser limits. An editable app copy accepts up to 32 imported fields per table and up to 100,000 rows and 64 MiB of typed values per app. A wide file can therefore open in the viewer even when a build is refused. ## Spend, its calculator and its shared page

1. Upload `september.csv`. Ask **Tell me about this data**, then **What category is it?** The first answer describes the transactions, actual date range and money moving in and out. The second identifies personal finance and explains how transaction descriptions support estimated categories.
2. Choose **Make an app**, enter “Make me an app to track my spending and understand what money is coming in and out,” and build **Spend**. Open the assistant to see both file questions carried forward and a summary using the loaded amounts.
3. Start with the full date range, then choose a month or custom range. Search merchant names or original descriptions and filter by estimated category and flow. The same selection drives the totals, trend, category breakdown, top merchants and transaction table. Sort and page through the table. Open a transaction to see its complete original description. **See how it works** explains the category rules. Unmatched descriptions stay Uncategorized.
4. Compare **Total outflows** with **Spending over time**. Outflows include every negative amount at its positive magnitude. Spending charts exclude likely transfers by default. The transfer toggle shows their effect on the charts. Positive amounts are labeled inflows. Net cash flow is inflows minus outflows.
5. Enter `/calculator`, then `/calculator matrix` to change its appearance. Enter `/calculator @spend add all the money I spent`. The picker identifies Spend as an **App**. The calculator reads the complete linked source and labels its result as all outflows across all dates, including likely transfers. This scope explains why its result can differ from a filtered chart.
6. Choose **Open page** for the app's own `/w/{app}/{work}` URL. **Share app** creates a private link for a named recipient. **Open shared app** shows the same dashboard at `/s/{share}`. The owner can preview it, and an accepted recipient can read the authorized single-file projection. Revocation withdraws access.

The September filename selects a prepared read-only dashboard and prepared answer wording. Both the dashboard and calculator fetch all authorized source pages, check completeness and compute in integer cents. The file questions, summary and chart values consequently reflect the uploaded data. The conversation handoff is member- and file-scoped in the browser. General cross-app mentions and natural-language calculator requests extend beyond this specific interaction. The showcase branch records the rehearsal in `docs/planning/SPEND-LOCAL-DEMO.md` and the general reference design in ticket APP-172.

## Weather, Jacket Reminder, Email and SMS

1. Place `/weather New York`. Ask the canvas to **create an app that reminds me to wear a jacket in the morning when it’s cold**, or enter `/jacket` to bring up Jacket Reminder.
2. Drag Weather's output to Jacket's weather input, or select the output and then the input. Place `/email` and `/sms`. Connect Jacket's reminder output to each widget's message input. A single output can feed multiple destinations. Each input accepts one compatible source.
3. As each connection lands, its context controls appear. In Jacket's **App assistant → Ask**, enter **Remind me to wear a jacket every morning when it’s cold. Send an email and a text.** Review the proposed temperature, time, timezone and connected destinations. The default is below 50°F at 7 a.m. Confirm **Set reminder**.
4. Watch Jacket read Weather, evaluate the condition and write a preview to each connected channel. Email displays the message in its preview list and SMS displays it in a conversation. The app reports **Reminder set** after the steps succeed. For a repeatable cold-weather demonstration, leave the labeled 42°F sample preview selected. **Run now** evaluates the actual widget reading and produces a message only below the threshold.
5. Disconnect a destination or change the rule. Jacket requires another review before execution. If a connection changes mid-run, the app stops further work and keeps any previews already written visible. Moving an app, switching its view or panning the canvas preserves its connections.

**Widgets as visual APIs.** Weather exposes a reading at an output port. Jacket accepts that reading at an input port and produces a reminder message at its own output. Email and SMS each accept that message at an input. Someone looking at the canvas can trace which data the app used, which destinations it could address and where the result appeared. The wire supplies context, the app owns the condition, and the user's confirmation authorizes the proposed operation.

The showcase implements typed connections, freshness checks, deterministic rule parsing, progress, and member-scoped browser persistence. Channel messages are local previews. Real provider consent, external delivery, receipts and durable scheduled jobs are separate product work. The showcase branch records the rehearsal in `docs/planning/CONNECTED-WIDGETS-LOCAL-DEMO.md` and the connector design in ticket APP-173.

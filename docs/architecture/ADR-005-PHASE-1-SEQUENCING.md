Date: 2026-10-29. Owner: GenUI (Claude session succeeding Codex per [CLAUDE-HANDOFF](../../CLAUDE-HANDOFF.md)). Status: accepted implementation direction, recorded for Victor's veto; no ticket acceptance, hosted result or phase pass is claimed by this record. [ADR-003](ADR-003-PUBLIC-BETA-ACCESS.md) and [ADR-004](ADR-004-TENANT-TRANSACTIONS.md) remain controlling for behavior; this decision changes only how the remaining PH01 work is cut and ordered.

## Problem, with evidence

1. The board tool refuses any ticket in Selected, In progress, In review or Done while a predecessor is not Done (`Tickets/_tools/board.py:97`), and forces the consumer of an open external gate to stay Blocked (`board.py:116`).
2. FORMA-247's gate condition in [external-dependencies.json](../../Tickets/external-dependencies.json) includes "verified-mailbox activation". FormaStack's [mail follow-on plan](../../evidence/APP-006/upstream-auth-source/MAIL-VERIFICATION-FOLLOW-ON-PLAN.txt) (SHA-256 `680987a5…`) step 1 requires GenUI's ordinary sign-in, pending-verification and backend-resend contract, which the tickets place in APP-009/074. APP-009 depended on APP-006, APP-006 is Blocked on FORMA-247, and FORMA-247 cannot clear without APP-009/074. The graph was circular.
3. ADR-004 made APP-008 Done depend on actual RDS isolation, reuse, race and recovery qualification. That managed work still needs a finished test entry, a separate qualification image and supervisor, an operator seed package, a two-process race coordinator, a paid window outside the auth rehearsal and exact-source CI ([managed plan](../../evidence/APP-008/managed-plan.md), [preparation slices](../../evidence/APP-008/managed-harness-preparation.md)). Because APP-073 and APP-010 depend on APP-008, and APP-009/012/013/014 depend on them, every remaining PH01 ticket was serialized behind cloud operations.
4. GitHub Actions refuses every job before execution with the annotation "The job was not started because recent account payments have failed or your spending limit needs to be increased. Please check the 'Billing & plans' section in your settings" (run 40812964992, job 123247361921; [retained receipts](../../evidence/APP-008/ci/677d7bd-billing-block.json)). Only the `getforma-dev` organization billing administrator can clear it. No reviewed source can land until then.
5. APP-012's fourth acceptance item and APP-073's first acceptance item require the actual public beta API and the managed database respectively, so those local-first tickets could not finish without hosted windows either.

## Decision

1. **Split APP-008.** APP-008 keeps its three acceptance tests, all of which are provable and already proven on the local real PostgreSQL 16.13/TLS harness (156 schema cases, 36 TLS/pool cases, HTTP smoke; see the ticket log). It moves to In review now and to Done after exact-source CI and landing. New **APP-075** inherits ADR-004 slice 3's managed obligations verbatim from the managed plan: isolated qualification executable/image and supervisor, operator seed package, race coordinator, the full RDS matrix, recovery and cleanup. PH01 cannot pass without APP-075; APP-008 Done is local acceptance only and says so.
2. **APP-009 consumes the pinned identity contract, not the hosted deployment.** Its dependencies become APP-008 and APP-073. It builds on the independently reviewed local verifier (CI at `49389c6`, [review](../../evidence/APP-006/review.md)) and the hash-bound [GenUI identity contract](../../evidence/APP-006/upstream-auth-source/GENUI-IDENTITY-CONTRACT-2026-10-28.md). All of its acceptance items are provable with a synthetic issuer on loopback, as the verifier spike already demonstrated. The hosted exercise of the same code path remains APP-074's first acceptance item, and APP-006 stays Blocked until FORMA-247 clears. APP-009 additionally owns the sign-in, verification-pending and backend-resend route contract in [ADR-006](ADR-006-SIGNIN-AND-VERIFICATION-PENDING.md), which FormaStack needs to finish mailbox verification.
3. **APP-012 is local-first.** Its dependencies become APP-003, APP-005, APP-009, APP-010 and APP-011. Its fourth acceptance item (actual public beta API denials and dispatch counters) moves verbatim to APP-076. The admission gate is still consumed locally: APP-012 admits, executes and delivers only through APP-009 sessions and APP-073 entitlement checks.
4. **APP-073 proves its ledger on the local real role/tenant harness.** Its first acceptance item names that harness; the managed application of the admission migration and operator command on RDS moves to APP-076.
5. **New APP-076 owns the Phase 1 integrated managed trial.** It depends on APP-074, APP-012, APP-013, APP-014 and APP-075 and owns: applying every reviewed post-schema-2 migration on RDS with an idempotent repeat; the moved APP-012 and APP-073 managed items; the end-to-end hosted journey invite → verified sign-in → current entitlement → authorized query → visible receipt → explicit command → atomic outcome/audit → restart/reopen on `https://beta.getforma.dev`; both race orders and the admission races on RDS; rollback by disabling admission; cleanup and ledger reconciliation. Its receipts feed `evidence/phases/PH01/GATE.md`.
6. **Ticket order.** APP-075 and APP-076 take orders 75 and 76 because the board requires every dependency to have a lower order; renumbering the 60 later tickets is deferred as noise.
7. **External gate split (pending FormaStack's ticket id).** FORMA-247's own acceptance rows cover deployed identity, client/callback, invite-only hosted registration, token-free PKCE, canary isolation and rollback; GenUI's register bundled verified-mailbox activation into the same gate, so a successful identity rehearsal could never unblock APP-006. When FormaStack names the FORMA ticket that owns the mailbox follow-on, the register gains that gate with consumer APP-074 and FORMA-247's condition narrows to its own rows; nothing is waived, the mailbox proof simply blocks APP-074 instead of APP-006.
8. **The Done standard is unchanged:** independent review, exact-source CI and landing. If organization billing stays blocked, Victor may separately decide to accept recorded local runs of each workflow's exact commands as interim landing evidence; this record does not adopt that fallback. (Superseded the same day: Victor directed that the repository become public with an all-rights-reserved notice so GitHub Actions run free of the billing block; it returns to private after deployment.)

## What is not weakened

Every acceptance sentence that moved is reproduced verbatim in its new owner with a "moved by ADR-005" note; none is deleted or softened. The PH01 exit criteria are unchanged and the board already requires all phase tickets Done, so the gate now requires eighteen tickets. No hosted, managed or three-browser acceptance may be claimed from local evidence. Local synthetic issuers, fixture registries and the `cfg(test)` identity factory remain confined to test builds, as ADR-004 requires. The $100/month limit, the once-counted $5 auth allowance, the single-operator rule and the no-LLM-before-APP-043 rule are unchanged.

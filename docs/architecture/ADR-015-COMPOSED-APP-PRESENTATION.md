# ADR-015: Compose components into one app experience

Status: accepted product direction; implementation remains Backlog in APP-155–161. Date: 2026-11-01. This extends APP-142/144/146/147 and preserves [ADR-014](ADR-014-LIVE-APP-SHARING.md). It does not change the November 2 clean-trial acceptance or claim the new behavior is deployed.

## Context

Victor supplied eight mobile screenshots of an expense tracker generated from a Matrix-themed prompt. They show an app header and primary action, explanatory text, small metrics, a budget control, a trend chart, ranked restaurants, a filterable record list, and a form opened by “Log meal.” The same product appears inside a builder preview and at a standalone URL. A separate preview/wake banner shows that its data service is unavailable. These are visual references, not evidence of the other product's implementation, permissions or hosting architecture.

Forma already has admitted parts, exact saved-work identity, Unite/Focus, member and guest documents, audited forms and live sharing. Its current default layout is a bounded grid, forms are inline, and appearance changes are session-only. Those capabilities do not yet provide a persisted app shell, declared button-to-component actions or general record-backed dashboard calculations.

## Decisions

1. **The app is the product; a component is a part; a card is its canvas presentation.** Keep the exact organization, app, work and publication identities. Unite, standalone use and connected sharing present the same authorized component tree and data. They do not create a new app or copy records.
2. **Compose a coherent page.** Use an app header with identity and a primary-action area, optional introduction, ordered sections, summaries, and working areas. A metric can be compact, a chart prominent and a record list full-width. Components need not each repeat canvas borders, drag handles or toolbars. Authoring controls belong to the surrounding builder; secondary contextual actions remain available without dominating app use. The first slice is one responsive document with section navigation where useful, not a new multi-page router.
3. **Persist presentation as admitted, versioned data.** A closed presentation contract declares regions, ordering, bounded sizing and component placements. Old definitions receive a deterministic default using their existing layout. Embedded, member `/w/{app}/{work}` and shared `/s/{share}` presentations use the same trusted renderers and semantic order. Responsive layout follows available container width, including a narrow app inside a wide canvas. Preserve native SSR and complete PageResponse policy; do not import the entire canvas controller into standalone pages.
4. **A button opens an existing component; opening does not write.** The first action kinds are bounded same-work component navigation and opening a component in a dialog, including an admitted command form (a sheet on narrow screens). The builder supplies a target picker and previews the result. Targets must resolve to admitted component IDs; missing, removed, unavailable, cross-work or permission-filtered targets refuse. An action-only form may intentionally stay off the page until opened. No generated event handlers, arbitrary endpoints or executable markup. Existing `links {from_view,to_view,input_id}` retain their data relationship meaning; a new action contract requires explicit compatibility review.
5. **Submitting remains an explicit, audited command.** Reuse the existing form state, command metadata, CSRF, version premises and idempotency handling. Opening, closing, resizing or reopening must not submit, clear an unexplained draft or invent a new outcome. A dialog has a name, focus containment/restoration, inert background, Escape and dirty-draft handling. Canvas shortcuts yield to form field navigation. Unknown write outcomes reconcile before retry. Publication changes or permission loss invalidate stale action targets.
6. **Appearance does not grant authority.** Shared guests remain view-only under ADR-014, even if the owner's app has a write button. Guest projection omits unavailable write actions and private form content. Existing independent member write grants are evaluated through their own authorized route. Button wiring is not a guest-write feature, export grant or platform invitation. Theme/layout/action changes inside an admitted publication retain ADR-014's pinned-definition rule: a changed definition or binding pauses the old share until it is renewed. Ordinary record updates remain live. Personal viewport preferences are not publication edits.
7. **Themes are bounded and durable.** Store publication-owned theme defaults using finite semantic color, typography, spacing, density and surface tokens, with safe presets. “Matrix-inspired” can select a terminal-style preset; it cannot introduce arbitrary CSS, fonts, scripts or unreadable contrast. Theme previews cover all three presentations and permission projections. Personal accessibility preferences, including reduced motion, win over decoration. No theme may hide freshness, errors or authority states.
8. **Dashboard numbers require real data paths.** Promote record lists to admitted components and add scoped filters and bounded record aggregations through their owning query contracts. Declare currency, time zone, date boundaries, pagination/truncation, zero/empty semantics and receipts. The existing expense ledger's “live records, last 200” aggregate is not an all-time query engine. Loading, unavailable and partial results never masquerade as zero. A client filter is not row-level security. Receipt-image interpretation and CSV export remain separate capabilities.
9. **Keep the URL independent of future compute lifecycle.** Do not put today's shared service to sleep per app. It serves many apps and currently holds session/event state in process. APP-161 first measures costs and compares cache eviction, isolated execution and other options. Any later design must keep authorized entry available, label snapshot freshness, reauthorize before release, preserve the five-second sharing lease, deduplicate bounded wakes and protect commands/jobs from loss or replay. A screenshot of a wake button is not a reason to create one server per saved work.

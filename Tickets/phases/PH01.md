# PH01: Foundations and first saved workflow

Team: GenUI. Progress: **active**. Exit gate: **pending**.

Predecessor phases: None — start here.

## Outcome

One authenticated user can query authorized data, inspect its receipt, save a decision and reopen it safely.

## Entry

The preserved design and published Forma 3.2 baseline are available. Begin APP-001; use independent isolated spikes while upstream integration gates are open.

## Deliverables

- Adopted typed contracts and measured native/parser/query qualification on Forma 3.2 (APP-001–006).
- Reproducible app scaffold, synthetic managed-store environment, tenant schema and session boundary (APP-007–009).
- Admitted definition, deterministic fixtures, query receipt, atomic command/outcome/audit and retry/conflict harness (APP-010–014).
- Invite-first beta entry at beta.getforma.dev: owner-issued codes, persisted trial entitlement, tenant-scoped hosted signup and protected-route refusal (APP-073/074; ADR-003), qualified on managed RDS and in the beta go-live trial, then left running as the first increment of the invite-first beta, on which the YC demo is recorded after PH04 (APP-075–078; ADR-005, ADR-008).

## Exit gate

- [ ] The integrated query → receipt → explicit command → atomic outcome/audit → reopen path passes; identical retries do not duplicate writes, stale edits conflict, and both revocation/adoption race orders pass (APP-012–014 locally; APP-076 proves last-slot redemption, identical retry and revocation at delivery through the public beta API; both revocation/adoption-versus-commit orders on RDS with lock observations are APP-080 by ADR-008).

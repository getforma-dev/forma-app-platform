# PH01: Foundations and first saved workflow

Team: GenUI. Progress: **active**. Exit gate: **pending**.

Predecessor phases: None — start here.

## Outcome

One authenticated user can query authorized data, inspect its receipt, save a decision and reopen it safely.

## Entry

The preserved design and published Forma 3.2 baseline are available. Begin APP-001; use independent isolated spikes while upstream integration gates are open.

## Deliverables

- Adopted typed contracts and measured native/parser/query qualification on Forma 3.2 (APP-001–006).
- Reproducible app scaffold, synthetic managed-store environment, tenant schema and session boundary (APP-007–009).
- Admitted definition, deterministic fixtures, query receipt, atomic command/outcome/audit and retry/conflict harness (APP-010–014).

## Exit gate

All phase tickets must be Done, predecessor phase gates must pass, and the following evidence must be accepted. Ticket completion alone does not complete the phase. Follow the [quality gates](../../docs/planning/QUALITY-GATES.md) for checks, release trials and evidence standards.

- [ ] APP-001–014 are Done with reproducible build, schema, parser/query confinement and native adoption evidence; compile refusals and numeric/resource bounds are tested.
- [ ] FORMA-246 conformance, FORMA-232 budget disposition and FORMA-247 hosted-auth receipts are accepted by GenUI in APP-003/006.
- [ ] The integrated query → receipt → explicit command → atomic outcome/audit → reopen path passes; identical retries do not duplicate writes, stale edits conflict, and both revocation/adoption race orders pass (APP-012–014).
- [ ] Tenant isolation and authoritative identity checks pass on the actual integrated path. Synthetic/local test substitutes are identified and cannot satisfy hosted integration acceptance.

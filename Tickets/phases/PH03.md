# PH03: App creation, governance and AI

Team: GenUI. Progress: **planned**. Exit gate: **pending**.

Predecessor phases: [PH02](PH02.md)

## Outcome

Users create, change, review, publish and generate supported apps without platform code changes.

## Entry

PH02 provides the trusted views, commands and persisted work used by the general authoring path.

## Deliverables

- Complete typed schema, general editor controls, semantic patches/undo and isolated previews (APP-032–036).
- Versioned publication policy, exact digest approval, reviewer UI, adoption/rollback and ownership lifecycle (APP-037–041).
- Private retrieval, provider/disclosure budgets, compose/adapt jobs, five tool boundaries, receipt-based explanation and the 15-intent evaluation (APP-042–047).

## Exit gate

All phase tickets must be Done, predecessor phase gates must pass, and the following evidence must be accepted. Ticket completion alone does not complete the phase. Follow the [quality gates](../../docs/planning/QUALITY-GATES.md) for checks, release trials and evidence standards.

- [ ] Both app shapes are built through normal authoring controls; source code/build identity stays unchanged and completion semantics are visible. Preview records never enter live work (APP-032–036).
- [ ] Publication rechecks digest/policy/approver epochs atomically; stale or replayed approval is refused. Existing work remains pinned and explicit rollback restores neither records nor revoked access (APP-037–041).
- [ ] Ten supported and five adversarial intents are frozen and evaluated. All admitted output validates, unsupported requests abstain and numbers match receipts. Provider requests respect disclosure policy, bounded attempts and budget (APP-042–047).
- [ ] Provider outage leaves published deterministic queries/forms operational; injected evidence cannot expand tools or authorize a mutation. User submission is required for record changes (APP-043–047).

## FormaStack dependencies

No new direct FormaStack gate in this phase. Earlier integration evidence and ticket prerequisites still apply.

## Parallel work

Direct authoring and policy work can progress before AI polish. Separate admission, disclosure and publication ownership; model success cannot waive deterministic checks.

## Sprints

- [S06: Direct authoring and safe transformation](../sprints/S06.md) — People compose both app shapes and make meaningful durable edits before AI polish.
- [S07: Publication and version lifecycle](../sprints/S07.md) — Organization policy controls exact publication and explicit compatible version adoption.
- [S08: Bounded AI creation and retrieval](../sprints/S08.md) — Real retrieval/adaptation/generation proposes valid apps without gaining authority or leaking evidence.

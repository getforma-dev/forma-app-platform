## Why

The APP-073 reviews ([schema-0003](../../evidence/APP-073/schema-0003/independent-review.md), [admission](../../evidence/APP-073/admission/independent-review.md), [provider](../../evidence/APP-073/provider/independent-review.md)) left minors, declined items, documentation routes to the coordinator and one owner decision open. [ADR-010](../../docs/architecture/ADR-010-NOV-2-MVP-CUT.md) deferred them past the 2026-11-02 MVP so the beta could go live on a handful of operator-provisioned, SES-verified invitations; they are owed before invitations go beyond the demo principals and before PH02's migration 0008.

Amend D7.8 with operator kinds for them (for example `source_revision.registered`, `work.seeded`, `provider_tenant.bound` with `outcome_digest` over the canonical `{issuer, provider_tenant_id, binding}`, and `app.seeded` or `work.seeded` for the seed, `outcome_digest` over the canonical command record), widen the operator RESTRICTIVE policy in the same migration as item 2, write one event per command, and have `verify` cover them. Until then the retained JSON output of each command, the RunTask override in CloudTrail and the APP-078 runbook steps that ran them (10.4, 11.3, 11.4, 11.6) are the record (`evidence/APP-012/README.md` D1; ADR-007 D7.8 recorded exception of 2026-10-30).
7. **Moved to [APP-174](../9-blocked/APP-174.md) on 2026-11-05** (its AWS steps); the `bound_elsewhere` candidate set below is fixed here by `genui_private.provider_tenant_index`. Original text: **Managed-invitation residuals (ADR-003 amendment 2026-10-30, managed invitations, revised after FormaStack's answers; APP-076 G2):** the `OperatorInvitationInput` secret joins the rotation and audit of item 1's store (three GenUI secrets per environment); the stack no longer creates a management secret. **Clear the A12 attachment, then rotate:** after the Nov 2 trial the stack parameters `ProviderManagementSecretArn`/`ProviderManagementUrl` are cleared by a stack update (a mutation, Victor-approved; APP-076 §9.5), which removes the operator task's injection and its execution role's `GetSecretValue` grant on FormaStack's `fauth-beta/management/northstar` secret; only after GenUI confirms that update completed does FormaStack rotate the Northstar management key with its rotation runbook (`/Users/victorvillacis/dev/Forma/work/FORMA-367/ROTATE-NORTHSTAR-MANAGEMENT-KEY.md`, FormaStack's action, Victor-approved). Until both are done the key stays readable to the operator task's execution role, and "GenUI never handles the raw key" was a process/agent boundary under one IAM user, not an IAM boundary (A12). A Canary key, if Canary invitations are ever wanted, is a second parameter. **Version history (operator-gaps review M3):** a `PutSecretValue {}` does not erase: the prior version moves to `AWSPREVIOUS`, and a second put (or `update-secret-version-stage`) only removes its labels; an unlabeled version is deprecated and deleted by Secrets Manager later and stays fetchable by version id until then, and versions are fully deleted only by deleting the secret. So the cleanup of the input secret's address-bearing versions (and of the capability secret's revoked entries) is this item's: secret deletion and recreation, or an audited bound on deprecated versions, with the rotation. The invitation input is emptied by the operator host, not by the task (a task-side `PutSecretValue {}` after use would add a write the task role does not hold today); the operator's `list` shows each redemption's principal and entitlement ids (APP-076 G5) with no audit of the listing itself. **`bound_elsewhere` candidate set (operator-gaps review M4):** `bind-provider-tenant`'s cross-organization check (B1 review m6) visits only the organizations that already hold a sign-in handle or a code under their own scope (`genui_private.handle_index` ∪ `code_index`), because FORCE RLS admits no scope-free read without a `genui_private` definer helper; an organization created by `provision` with no handle or code yet is skipped, so the same `(issuer, tenant)` can be bound to it and to another organization, and nothing re-checks when its first handle is issued (the registry, one binding per routed organization, stays the routing authority). This item adds the definer helper with its migration and re-checks at handle and code issue.

8. **ADR-002 scope sentence (APP-013 re-check N1):** ADR-002 line 33 still says the idempotency scope is organization + principal + work + command + key; add "+ app" or a note that the work is identified under its app (migration 0007 keys the claim and outcome on six columns including `app_id`; APP-013 review m6). Record only; ADR-007 D7.9 carries its own dated sentence.

## Migration and rollback

Migration 0021 widens the operator RESTRICTIVE policy with seven kinds, adds the nullable `genui.provider_invitations.detail`, and creates `genui_private.provider_tenant_index`, copying every active provider-tenant binding into it. It rewrites no stored value. Two organizations sharing one active issuer and tenant make the upgrade fail whole (the schema campaign proves it), so the release preflight checks for that first. `pool.rs` requires exactly version 21 (22 after APP-169), so the image and the database move together: beta auto-promotion refuses this change, and it ships only through the reviewed operator schema release in [APP-175](../4-done/APP-175.md). Rollback is forward-fix; a snapshot restore with the previous image is a separately reviewed recovery. The custody move retains the operator's ability to revoke; a failed move leaves the 0600-file default in force under its stated conditions.

## Why

The design requires one coherent versioned boundary so implementation does not confuse a released framework with an implemented platform. This ticket delivers: persist and admit a minimal typed definition and work binding.

## What changes

Immutable canonical digest, versioned registered kind/operator, correct input contracts (not author evidence IDs), separate published app/saved work; unknown/executable/excessive shapes rejected.

Keep this a reviewable slice: L means approximately 3–5 focused days. Re-estimate before selection and split the ticket if it exceeds five focused days. The estimate is a planning bound, not a delivery date.

Scope excludes production deployment and real customer data; this is a synthetic qualification. Upstream framework/auth changes remain with the FormaStack team.

## Acceptance tests

- [x] Persist a minimal immutable canonical definition digest naming supported schema/renderer/operator versions and create a separate work item with compatible source bindings.
- [x] Unknown or executable fields, over-complex definitions, undeclared operators and client-supplied grants fail whole-output admission with a coded reason.
- [x] Reload the admitted definition and saved work after restart; the reusable publication contains input contracts and does not embed the author’s private evidence binding.

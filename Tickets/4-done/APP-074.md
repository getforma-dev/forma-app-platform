## Why

The beta must be reachable from anywhere while protecting private data and paid work. This slice proves the public registration/admission journey on the local harness against the test-only synthetic issuer, including direct API bypass attempts; it is not a landing-page-only milestone. The hosted proof at `https://beta.getforma.dev` with real mail is APP-076's and the native Safari and Firefox runs are APP-079's (ADR-008).

## What changes

Serve a native public landing and invitation-entry surface, qualified here on the local harness and later deployed at `https://beta.getforma.dev` (APP-076). Only a valid invite permits signup. Integrate the FormaStack-owned tenant-scoped invite-only email/password registration contract and its approved recovery policy through the exact `https://beta.getforma.dev/auth/callback` code-flow handoff; here the synthetic issuer stands in for fAuth, and real email-verification delivery is exercised in APP-076. An authenticated pre-access session permits only bound admission/logout; APP-073's current membership/entitlement gate must pass before workspace access. Valid codes choose their server-bound isolated organization before signup through a bounded opaque handoff, never a client tenant/role selector.

The provider path is a backend `POST /t/{slug}/oauth/par` with the confidential provider `invite_token` plus PKCE fields; the browser receives only bounded `request_uri`, then final code/state. That contract is pinned merged source (gatewasm PR18/19 at `dfba787`, hash-bound in APP-006's receipt), not a deployed service; its hosted exercise is APP-076's. Phase 1 uses operator-provisioned email/explicit-role-bound provider invites with `delivery_mode: server_only`; no general tenant-management authority is added to the public app. Consume APP-073's remote ID/private handoff and operation state. The provider and GenUI databases are separate: completed identity signup still cannot admit a locally revoked, expired or exhausted code.

Add bounded signup/login/redemption requests, honest pending/invalid/expired/exhausted/rate-limited states and server-side IP, account/admission and global abuse limits. Keep codes, passwords and bearer credentials out of URLs/storage/telemetry. Operator code generation remains APP-073; general administration remains APP-066. LLM execution remains disabled until APP-043 passes. Full imports, generated applications and real-customer pilot readiness remain later work.

Keep this a reviewable L slice of approximately 3–5 focused days. The local harness drives the real GenUI routes against a test-only loopback issuer that implements the pinned fAuth contract (PAR, authorize, token, resend); it is not a mock of GenUI. The public-HTTPS, real-mail and browser-matrix proofs are APP-076's and APP-079's ([ADR-008](../../docs/architecture/ADR-008-YC-DEMO-AND-BETA-MVP.md)); do not relabel a local result as hosted acceptance.

## Acceptance tests

- [x] The native public landing and invitation-entry pages render through forma-server with usable keyboard/focus/error states; `GET /invite` and `POST /invite/validate` validate a code by digest without consuming a successful-redemption slot and answer honest pending/invalid/expired/exhausted/rate-limited states; the backend-only PAR handoff against the synthetic issuer leaves the browser nothing but the bounded `request_uri`, then the final code and state; no code, password or bearer credential appears in URLs, storage or telemetry.
- [x] Missing/invalid GenUI codes cannot obtain a new signup handoff; missing/invalid/email-or-tenant-mismatched provider invitations cannot create an account through UI or direct registration calls. Anonymous, authenticated-but-unadmitted, expired/revoked and foreign-tenant principals are refused by actual protected page/API routes before storage disclosure or work dispatch. Probe query/import/generation/export/record route families directly; not-yet-implemented capabilities remain denied/unavailable and cannot be counted as an implemented feature. A registered account alone and a pre-access session never mint workspace grants. Operator-preprovisioned trial organizations remain isolated; member invites join only their named existing organization.
- [x] Wrong/replayed state or code, expired pre-access state, changed destination, client-provided tenant/roles, cross-site redemption and leaked/replayed code outcomes refuse. Verify tenant scope remains server-bound and two unrelated trial organizations cannot read or consume one another's work.
- [x] Signup/login/redemption floods hit finite server-side IP and account/admission/global limits, including forged forwarded-IP headers and many account names. Request/body/deadline and pending-account/reservation bounds prevent unbounded work; denied requests invoke no model/provider. Inspect actual dispatch counters and safe logs, not just UI state.
- [x] Trusted proxy and bounds per ADR-007 D7.14: the client address is the rightmost `X-Forwarded-For` entry behind the trusted load balancer only and a forged header from an untrusted hop is ignored; form bodies over 4 KiB, JSON bodies over 64 KiB and requests past the 5-second deadline receive the uniform problem response; protected routes answer the uniform 404 to anonymous and foreign principals.

## Verification

Retain real API requests/statuses with secrets removed, backend dispatch/denial evidence, paired isolated organizations, database outcomes and synthetic-issuer PAR/token receipts in `evidence/APP-074/local/`. Use the independent observer to detect intentional token/grant/dispatch leakage in a negative control. A green local auth verifier alone is insufficient: the routes must be driven end to end on real PostgreSQL 16.13 with TLS. APP-012 proves the admitted query/receipt path on the same harness; APP-076 proves this entry hosted with real mail in installed Chrome and APP-079 in native Safari and Firefox.

Source obligations: [ADR-003](../../docs/architecture/ADR-003-PUBLIC-BETA-ACCESS.md), user beta direction, platform R15/C01/C11 and SR1/SR2/SR7/SR12. [Cross-team handoff](../../docs/planning/CROSS-TEAM-HANDOFF.md) defines FormaStack versus GenUI ownership.

## Migration and rollback

Disable new signup/redemption while retaining opaque-session invalidation and current membership/entitlement checks. Roll back only to a build that denies protected work under the same gate. Keep failed enrollments, scoped outcomes and audit; never substitute an organization picker, return bearer credentials to the browser or grant access because the provider is unavailable.

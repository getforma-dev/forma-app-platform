## Why

The design requires one coherent versioned boundary so implementation does not confuse a released framework with an implemented platform. This ticket delivers: freeze implementation contracts and unresolved decisions.

## What changes

Version typed AppDefinition, source/input contracts, receipt, command/outcome, publication and saved-work shapes; reconcile platform/demo contract lock; resolve revocation target and local-dev versus hosted-store configuration without silently reversing approved architecture.

Keep this a reviewable slice: M means approximately 1–3 focused days. Re-estimate before selection and split the ticket if it exceeds five focused days. The estimate is a planning bound, not a delivery date.

Scope excludes production deployment and real customer data; this is a synthetic qualification. Upstream framework/auth changes remain with the FormaStack team.

## Acceptance tests

- [x] AppDefinition, publication, saved work, source binding, receipt and command/outcome schemas distinguish immutable IDs, input contracts and concrete evidence revisions.
- [x] Platform and companion contract references reconcile to one edition; any implementation amendment lives outside the frozen snapshot and has an explicit rationale.
- [x] The total revocation bound, retry horizon, local developer adapters versus deployed stores, completion semantics and canonical encoding decisions have named dispositions or blocking owners.

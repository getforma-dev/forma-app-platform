## Why

Apps are whole products made of components. The Library and canvas should make that identity clear and prevent overlapping owners of the same DOM components.

## What changes

A single app object owns its App Card, Stack and Open presentations. Add places the App Card; Open replaces Unite. Switching views reuses the same components and preserves drafts, query receipts and location. Focus remains, Open page opens an authorized page in a new tab. Only Open is resizable. Library app components, Fan Out and Spread entry points are hidden/guarded in the frontend. No backend definition, grant, query or record mutation contract changes.

Cards also lists existing saved Shape cards and pinned Ask answers by their own durable card IDs through the existing authorized inventory.

Independent card works are whole works explicitly made through Make a card/Keep data, or personally categorized by the member. Existing ambiguous works remain Apps. Classification and optional component hiding are browser-local appearance preferences, never access control. Shared guests retain the admitted published presentation.

## Acceptance tests

- [x] Add → Open → Stack → Open produces exactly one app object; reload and migration retain one owner, geometry and mode.
- [x] App components cannot escape via Library, drag, commands or shortcuts; removing the app preserves Library/data.
- [x] Focus/Edit/Share/Open page behave across modes; open-page links use a new tab; inner remove and successful Ready chrome are absent while failures/loading/receipts remain.
- [x] Forms/drafts and genuine queries survive view changes; only Open is resizable.
- [x] Library has Apps, Widgets and Cards, including existing saved cards/answers by their own identity; explicit standalone creation and reversible personal classification work without inferring type from component count.
- [x] Browser-local visibility is labelled honestly, scoped to exact app/work, applied to member views and excluded from publication/guest payloads.
- [x] Relevant local browser/check campaigns and independent review pass; deployment stays held for this PR.

## Verification

Record focused tests, browser evidence and independent review before completion. Planning checks alone do not prove behavior.

## Migration and rollback

Preserve saved works, grants, records and receipts. Browser-local view metadata is bounded and contains identifiers only. Deploy through the existing protected pipeline after review; no cloud change is part of this ticket's current implementation turn.

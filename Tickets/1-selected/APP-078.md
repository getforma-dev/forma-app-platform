## Why

The PH01 exit gate requires tenant isolation and authoritative identity checks on the actual managed path; local substitutes are explicitly insufficient. This ticket carries [ADR-004](../../docs/architecture/ADR-004-TENANT-TRANSACTIONS.md) slice 3's managed obligations by reference to the [managed plan](../../evidence/APP-008/managed-plan.md) §Ordered managed run and §Required matrix, moved from APP-008 by [ADR-005](../../docs/architecture/ADR-005-PHASE-1-SEQUENCING.md); [ADR-008](../../docs/architecture/ADR-008-YC-DEMO-AND-BETA-MVP.md) defers the plan's recovery, pool-lifecycle, concurrency and drift rows to APP-080 so the synthetic beta can go live on the rows below.

## What changes

Inside one Victor-approved reserved window outside any fAuth deployment operation, with the service stopped and the consumer observed stopped: publish the new immutable production image from the final reviewed source, update the stack through a reviewed TemplateURL change set (new `ImageDigest`, new future stop schedule, optional task definitions, stack policy read back), observe and reserve, compare the live catalog and replication mode before any mutation, take the pre-migration snapshot, apply every landed migration once and once again, seed the two fixture organizations, run the rows below through the qualification task and the operator task, qualify the production HTTPS surface from the exact managed image, stop every task, clean up temporary resources and reconcile the ledger. After the STOPPED observation and ledger reconciliation, plan Task C3 restarts the service to count 1 on the recorded digest; that restart is APP-076's precondition, not this ticket's acceptance.

## Migration and rollback

The pre-migration snapshot is schema 1; the known compatible service candidate is the qualified `8f8c34b` image. Switching the image back while the source remains at a later version is not rollback. After a failed transactional migration, prove the source stayed at the exact version 1 baseline; after a committed upgrade, use a reviewed forward fix or the snapshot restore with an explicitly compatible image and a separately reviewed cutover. Until APP-080 exercises the restore, the snapshot is retained but unproven; during the beta the only rollback for a committed migration is a reviewed forward fix (ADR-008). Never widen IAM grants or bypass the RDS replacement/deletion guard.

## Why

A principal, tenant or service-scope mistake can expose another organization’s work; this boundary must be proven before dependent integration. This ticket delivers: establish tenant-bearing schema, database roles and deny-by-default authorization.

## What changes

FORCE RLS, NOLOGIN owner, tenant-leading PK/FKs, transaction-scoped tenant context with pool reset; two-org fixture and endpoint harness prove cross-scope denial in each role.

Keep this a reviewable slice: L means approximately 3–5 focused days. Re-estimate before selection and split the ticket if it exceeds five focused days. The estimate is a planning bound, not a delivery date.

Scope excludes production deployment and real customer data; this is a synthetic qualification. Upstream framework/auth changes remain with the FormaStack team.

## Acceptance tests

- [ ] Tenant-leading primary/foreign keys and FORCE RLS reject cross-organization relationships and reads under each application database role, including a missing tenant context.
- [ ] Reuse pooled connections across Northstar and canary requests; transaction-local scope resets and no prior tenant data or metadata appears.
- [ ] The workspace role cannot write publications or records, unknown permissions deny by default, and unauthenticated/guessed-ID route calls disclose no private existence information.

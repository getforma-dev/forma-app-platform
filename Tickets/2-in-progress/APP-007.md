## Why

The design requires one coherent versioned boundary so implementation does not confuse a released framework with an implemented platform. This ticket delivers: scaffold reproducible browser/rust workspace and one binary's role interfaces.

## What changes

Pin dependencies/lockfiles; local setup, migrations, sample config without secrets, health checks, focused verification scripts and CI; role-specific credentials even when hosted in one process. Own the first isolated synthetic integrated environment as well: final demo D2 requires managed PostgreSQL, S3 and organization key handling from row one. Record account, region, budget and operator before provisioning; an unavailable account or unresolved spending decision blocks that environment acceptance without changing the architecture. Local test doubles remain useful unit-test inputs, not integrated demo evidence.

Keep this a reviewable slice: L means approximately 3–5 focused days. Re-estimate before selection and split the ticket if it exceeds five focused days. The estimate is a planning bound, not a delivery date.

Scope excludes production deployment and real customer data; this is a synthetic qualification. Upstream framework/auth changes remain with the FormaStack team.

## Acceptance tests

- [ ] On the agreed account/region/budget, prepare reproducible isolated synthetic managed PostgreSQL/RDS, S3 and key configuration; verify two-tenant access, migration connectivity and cleanup/rollback. Record the operator and actual resource identities without committing credentials. Keep this acceptance blocked if required access or resource decisions are missing.
- [ ] A clean clone can install pinned dependencies, apply initial migrations and start the documented minimal role configuration using example settings with no secrets.
- [ ] The workspace, control, data and worker interfaces compile as one binary while each receives its own constrained credential/configuration; privileged behavior is not exposed by role selection alone.
- [ ] Focused formatting/build/type/security-contract checks run in CI from lockfiles and exact scripts; no generated application capability is claimed before its owning ticket passes.

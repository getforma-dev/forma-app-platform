## Why

Every beta promotion stopped on November 5. Debian's vulnerability data added two HIGH findings overnight for packages our images already ship: zlib CVE-2026-76844 and apt CVE-2026-109518. The scan guard refuses any newly introduced finding without a reviewed disposition, and the only disposition the code allowed was APP-167's three MEDIUM operator findings. Bookworm has no zlib fix. The apt fix exists, but it changes the Dockerfiles and so the deployment contract, which automatic promotion refuses.

## What changes

1. `ops/promotion/scan-disposition.json` becomes per-image (schema 2). Each entry binds the image's live predecessor manifest and the exact fingerprints of the two findings; the file binds the deployment contract and a November 12 expiry.
2. `ops/promotion/registry.py` pins the accepted CVE names, severities, packages, roles and expiry in source, refuses duplicate JSON keys and refuses every malformed shape. `github.py` validates the approval summary against the per-image entry.
3. Tests cover per-role review, every fingerprint mutation, scope and expiry, 29 tampered files and six malformed texts.
4. [Evidence](../../evidence/APP-173/SCAN-DISPOSITION.md): the refused run, the abandon, the pause, Debian's status, ARM64 APT candidates, an ELF import scan of all three images, and the applicability limits.
5. The promotion guide describes the current disposition; the APP-167 record gets a dated supersession note.

## Why

APP-195 measured the refresh herd. One page refresh takes 17 transactions at about 64 ms each (50 ms in release). About 45 ms (37 ms in release) of each is `Catalog::verify`, which `recycle` runs on every connection reuse. With two connections per role, 26 pages need about 10 s of data-role time. Neither more waiters nor 4 data connections fixed it. Without the per-reuse catalog check, a transaction costs about 19 ms (13 ms in release).

## What changes

- `Catalog::verify` runs at connection creation and at readiness, both unchanged.
- On reuse, it runs only when that connection's last verification is more than **30 s** old. This is a `const` with no environment override.
- `verify_identity`, `verify_baseline` and `verify_schema_version` stay on every reuse.
- A failed recheck discards the connection, as today.
- **ADR-004 amendment A5** (dated) records the cadence:
  - what moves to the 30 s cadence: the catalog document (grants and ACLs, relation kinds such as a table turned into a view, RLS policies, triggers, constraints, functions and role attributes) when it changes without a schema-version bump;
  - what stays checked on every reuse: identity and replication role (`verify_identity`, `verify_baseline`) and the schema version (`verify_schema_version`), so a migration that bumps the version and replica mode are still caught at once;
  - the ADR-004 sentence it amends: §Pool and driver lifecycle, "Only fully verified leases return to the pool";
  - its stated limit: no claim against a hostile database administrator (`evidence/APP-008/native/r5/independent-review.md:39`);
  - that the four application roles have no DDL privilege;
  - that detection latency for the catalog document moves from one transaction to at most 30 s, plus the transaction in flight.
- **Amendment A6** (4 workspace, 4 data, 2 control and 2 worker connections, 12 in all) is drafted. It applies only if, after A5, run A fails on CI or passes with p95 above 5 s.
- The `refresh-herd` campaign is un-quarantined in the same pull request that makes it pass.

## Acceptance tests

- [ ] Catalog drift is detected after the 30 s window and tolerated within it only for the catalog check. Identity, baseline and schema-version drift are refused on every reuse. A new backend is always verified at creation, and readiness still verifies. Each is proven by breaking it.
- [ ] ADR-004 amendment A5 is recorded, with ADR-007's header ("amended in exactly four named places A1–A4") updated to name A5. Refusal causes stay typed `trace::refuse` codes. A6 is drafted, and applied only on its trigger.
- [ ] `refresh-herd` passes run A at the revised criteria (APP-195) in the test profile on CI and in one recorded release-profile run, reporting the catalog-check count and per-transaction p50. The campaign is back in the tenant-foundation workflow.
- [ ] An independent Tier A review and recheck find no blocker.

## Why

Victor asked whether the box stays. APP-108 built folders: a box holds files, shows them, and can form an app that traces back to the folder. APP-120 then called that folder a widget, not an app. The later app-page tickets left the question open and said not to remove folders. This spike is the place that answers how a box fits. It does not delete the folder code.

## What changes

Write `docs/planning/app-model/box.md`. Read APP-108, APP-120, and the folder routes under `app/src/boxes/` before deciding a sentence.

1. **What it is today.** A box is a folder widget. It holds files the member uploaded. It is not an admitted app. It has no cards. Ask against a folder is the folder ask route, separate from `POST /v1/ask`.
2. **How an app comes out of it.** Formation reads the folder and produces an app through the existing composer and admission path. The new app links back to the folder. The folder remains. Model output from formation is data, not markup.
3. **Where it sits next to the new model.** An app is created in APP-141 without a folder. A folder is an optional way to start an app from files. A component is not a file. A widget that is not a folder does not hold files.
4. **The open question, answered or kept open.** The note recommends keep or drop, with the reason. If Victor has not chosen, the note says "keep, because APP-120 and APP-108 already shipped it" and lists what would break if it were removed. It does not remove it.

No product code in this spike.

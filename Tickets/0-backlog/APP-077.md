## Why

The production image omits `tenant_seed.py`, the contract validator, fixtures and their dependencies, so the managed seed in the [managed plan](../../evidence/APP-008/managed-plan.md) has no runnable artifact, and the two-order race matrix on RDS needs a coordinator that proves real lock waits rather than sleeps. Both must exist and be reviewed locally before APP-078 reserves a window.

## What changes

Build a separate operator image and package for the migration identity (`PGPASSWORD` from the execution secret, no application role-assumption grants) with subcommands `migrate` (canonical `apply_migrations` for every landed migration), `verify-catalog`, `seed` (`tenant_seed.seed` with validated envelopes), `admission {issue,list,revoke,extend}` (APP-073's operator command, raw code printed exactly once) and `upload-sources` (fixture source bytes normalized through the reviewed APP-004/005 adapter and written under `o/<org>/sources/<source_id>/<revision_id>` with KMS, recording the real digests). Every ECS override fits 8,192 bytes with a matching `entryPoint`. Add the optional count-zero `OperatorTask` definition to the CDK stack with tests. Build the race coordinator as the preparation record proposes: run-scoped session advisory-lock phase beacons plus `pg_blocking_pids`/`pg_locks` observations, the application actor reserving one workspace lease, the operator actor using two migration connections (writer and observer), never extending the three-second application transaction, and aborting on beacon loss, unexpected owner or timeout.

## Acceptance tests

- [ ] The operator image is built from the frozen source with exact context, source and image bindings; it contains the migration runner, catalog verifier, seed, admission operator, source upload and their hash-locked dependencies, holds no application role-assumption grant, and each documented override fits 8,192 bytes with a matching `entryPoint`.
- [ ] On disposable local PostgreSQL 16.13 with TLS, the coordinator proves real blocking relationships for both orders of membership revocation, organization suspension and saved-work version change (application first completes only under its held fence; writer first causes a current-state or stale-pin refusal after waiting), monotonic epoch restoration (operator mutations advance epochs, never reset them) and peer-loss cleanup; a sleep or process start is never the barrier.
- [ ] The optional `OperatorTask` definition (migration execution role, `PGPASSWORD` secret, count zero) passes the CDK template tests; the service and qualification task definitions are unchanged.
- [ ] An independent review binds the package, the coordinator evidence and the exact binaries with no blocking finding; unresolved items from the preparation record (cross-process timing under the transaction deadlines, lock visibility under the approved RDS roles, seed package paths, partial-mutation recovery, the drift-trial target) are each answered or recorded as a limitation for APP-078.

## Why

A page refresh takes 17 transactions: the document's 8+3, the batch's 2+1 and the view's 2+1. Even with APP-197 that is the next limit at 25 or more open pages.

## What changes

- One transaction per read path (`storage/actions.rs::work_reads`, `shared_reads.rs`, `query/page.rs`).
- A server-advised spread in the live hint, proportional to the number of subscribers. This needs a contract edition.

Nothing here ships before the class.

## Acceptance tests

- [ ] The document refresh, the record-components batch and a typed view each use one data-role transaction, with no change in what each role can read (the existing campaigns stay green).
- [ ] The live hint carries a server-advised spread under a reviewed contract edition, and the client honours it.
- [ ] `refresh-herd` reports the reduced transaction count and a higher sustainable page count. An independent review finds no blocker.

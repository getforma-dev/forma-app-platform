## Why

The deploy helpers still defaulted to each checkout's `.cache/ops/beta`, despite ADR-013 requiring a single budget ledger, approval record and window chain. A linked worktree could therefore use a second ledger. Development environments and build caches must remain local to the invoking checkout.

## What changes

1. `ops/beta/lib.sh` resolves the main checkout through `git-common-dir` and Git's worktree inventory. Its default `$PRIV` is the main checkout's `.cache/ops/beta`; an explicit `GENUI_OPS_PRIV` remains supported. An unavailable main checkout fails with an explicit-override instruction instead of inventing a ledger location.
2. `load_env` restores that resolved path after reading the private config, while keeping `REPO` and both Python environments local to the invoking checkout.
3. `just deploy` prints the resolved operator-state directory before every step, including `help`. Discovery and help create no files and call no AWS APIs.
4. Legacy import restricts permissions on the actual private destination and its descendants, without changing arbitrary parent directories when an override is used.

## Verification

`python3 -m unittest discover -s ops/beta -p 'test_*.py'` exercises temporary Git repositories, dummy private config and existing fake-AWS/Docker transports. `bash -n ops/beta/lib.sh ops/beta/deploy.sh ops/beta/import-legacy-priv.sh` checks shell syntax. No deployment, real ledger edit, runtime restart or live AWS call is part of verification.

## Migration and rollback

No state moves automatically. Existing main-checkout state is reused. A worktree with intentionally separate state must set `GENUI_OPS_PRIV` explicitly. Revert these source changes to restore the old resolution; preserve the authoritative main ledger and window chain.

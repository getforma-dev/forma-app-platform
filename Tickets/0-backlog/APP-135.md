## Why

Victor, 2026-10-31: "in the gap we built too much for MVP and hard coded lots of stuff." APP-132 showed a path that silently assumed the 20-app library: with none, a sentence could not build an app, and nothing flagged it. The clean profile (`just dev clean`) makes these assumptions testable for the first time.

## What changes

1. Walk every user path on the clean profile (no library, no data, demo off): compose, Ask, Shape, Do, Forma, folders, made cards, naming, sharing, MCP, Slack. Record each place that fails or only works with seeded data, the demo org, fixed ids, hand-written hints (the six workflow apps' `command.hint`), rehearsed sentences or catalog-only facts.
2. For each: fix it now (small), move it behind `GENUI_DEMO_MODE` and into APP-098's register (demo-only by design), or ticket it (larger), with the cut against the MVP.
3. List what was built beyond the MVP (ADR-010/011 scope) that adds hard-coding without demo value, and propose what to remove or defer.

### MVP scope proposals (awaiting Victor's disposition)

- **Keep:** generation, governed records and receipts, explicit confirmations, sharing and live updates. These support ADR-011's pitch directly; the first three fixes above make the same paths honest outside the demo.
- **Keep for the current demo; review after Nov 2:** made cards, pins, namespaced commands, folder imports and the clean customer profile. Removing integrated paths now adds regression risk; APP-097 should decide their release contract and onboarding scope.
- **Defer expansion:** extra widget styles, additional approval templates and hard-coded workflow hints, additional consumer connector support, and broader folder/PDF-derived builds. Existing limits remain in APP-098/APP-097; do not add new canned tenant behavior to solve clean-profile failures.
- **Remove the misleading copy now:** absent-app starter examples and unconditional seeded provenance (register 2–3). No implemented product feature or evidence file was removed by this audit.

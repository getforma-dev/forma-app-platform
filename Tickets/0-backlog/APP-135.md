| 1 | Do vs Forma: a plain sentence that reads ("Review expenses over $200", the empty canvas's own chip) | 2026-10-31, pitch instance, demo org, model key present: the chip drafted **"Submit claim?"** ($200.00, Unknown merchant, other, submitted); nothing written (the confirm stopped it). Root cause: the demo-org rehearsed parser counted the noun "expense(s)" as a spending verb, so any amount plus "expenses" was a filing (`app/src/actions/rehearsed.rs:347` at 5bd3c35: `lower.contains("expense")`), and nothing on the server stopped a create or decide for a sentence that only reads (the model path had the same exposure: the prompt said `create` for "money spent" and gave no read rule). The client's `/app words` lane also took any `$` amount as an entry (`app/admin/src/canvas/slash.ts:97`, `\$\s?\d`) | **Fixed** (`pivot/review-routing`): a deterministic server guard (`app/src/actions/guard.rs`) in `Parser::parse`, every organization, rehearsed and model alike (web and Slack): a read verb (show, list, find, review, filter …) or a question never yields create/decide (answers `place`); a threshold amount ("over $200") with no filing verb is no filing; a read sentence with a threshold answers `place` before any model call; an `open` carrying a threshold goes to the composer, which filters. The rehearsed parser no longer reads "expense(s)" as a verb (only "expense …" as the first word, or "expensed"). The parse prompt states the rule too (model output stays data; the guard has the last word). The client's `isEntry` mirrors the guard. "Review expenses over $200" now lands Expense review queue, adapted Amount > $200 (APP-101's intended path) | `actions::guard`, `actions::rehearsed`, `actions::prompt`, `canvas/slash.ts` |

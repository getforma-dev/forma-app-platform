## Why

The per-member allowance is the compiled default 80 (`app/src/composer/model.rs:94`), overridable only by `GENUI_MODEL_DAILY_CALLS_PER_MEMBER` (`:96`), which the managed deployment does not set (`:88`) and which is read once per process (`:468-478`). The service's environment is the stack's task definition (`infra/src/stack.ts`), so an env change is a template change and a release, and a parameter edited outside the promotion makes the next promotion refuse (`infra/scripts/preflight.py:570`). There is no release-free switch today. APP-222 part B adds `genui.organization_allowances` and the audited `set-allowance` command, after which the switch is one operator task. MCP tools other than `forma_compose_app` and the folder tools already run on the member's own AI (`app/src/mcp/`; APP-222 "Why"), so "own AI via MCP" needs no change.

## What changes

1. **The free bundle, as data:** with part B live, the organization's allowance rows for the free plan: `ai_calls_per_member_per_day = 10`; the organization cap, the MCP windows and agent tokens per member keep their deployment defaults. The values are rows set by `set-allowance`, never constants named for the class.
2. **The switch on Dec 12 (class end):** `admission set-allowance --organization $TRIAL_ORG --key ai_calls_per_member_per_day --value 10`, idle state, a receipt, the audit event part B defines; the readback on `/admin` (today's use against the new allowance). Announce it to the members the day before (the class guide's announced-window rule).
3. **The member's words:** the canvas's daily-limit copy (`app/admin/src/canvas/daily-limit.ts`) and the 429 `daily_limit` answer read the allowance from the response, not a number in the text, so 10 shows as 10; a check that no copy hard-codes 80.
4. **If part B is not live by Dec 12:** nothing changes; 80 a day stands under the 1,000-a-day process cap (`model.rs:86`) and the $1,000 Anthropic organization limit, and this ticket runs after the release that carries part B.

## Why

The PH01 gate requires the integrated path on the actual deployment with accepted upstream evidence and direct API denials; ticket completion alone does not complete the phase. [ADR-005](../../docs/architecture/ADR-005-PHASE-1-SEQUENCING.md) moved the hosted acceptance items of APP-012 and APP-073 here. [ADR-008](../../docs/architecture/ADR-008-YC-DEMO-AND-BETA-MVP.md) makes this trial the go-live of the first increment of the invite-first beta that invited viewers can try (the YC demo is recorded after PH04 on the same deployment): it runs once in installed Chrome with real verification mail on the exact candidate build, and the service is then left running rather than stopped. The native Safari and Firefox runs, the deployed negative campaign and the canary resource check of the joint rehearsal are APP-079's; the RDS lock-observation repeat of the race orders is APP-080's.

## What changes

On one exact candidate source/image, after APP-078 has applied the migrations and the FormaStack-operated fAuth with mail transport is live under FORMA-366: apply any reviewed migration not yet applied on RDS through the operator task and repeat it unchanged; run the operator admission command on RDS to issue the viewers' codes; then prove the journey invite → verified sign-in → current tenant entitlement → authorized query → visible receipt → explicit command → atomic outcome/audit → restart/reopen at `https://beta.getforma.dev` against the hosted fAuth contract accepted in APP-006, including the denial, replay, concurrency and failure cases below, in installed Chrome. Exercise rollback as a redeploy of the previous task definition, restore the service, reconcile the ledger against the beta figure Victor approves (until then ADR-003's $100/month cap) and obtain independent review. Leave the service running as the beta. No LLM call is made.

## Acceptance tests

- [ ] Every reviewed migration not yet applied by APP-078 applies on RDS from the exact candidate image, adding exactly one history row per migration, with an unchanged idempotent repeat; the real managed database migration and operator command issue, list and revoke bounded codes; an ordinary application/member role and a forged operator identity are denied. (Moved from APP-073 by ADR-005.)
- [ ] Through the actual public beta API, anonymous, pre-access-only, expired/revoked-entitlement and foreign-tenant requests invoke no query engine and disclose no private metadata. A currently admitted member runs the same query successfully; entitlement revocation while queued/executing denies result delivery. Retain dispatch counters and both race orders, not just UI hiding. (Moved from APP-012 by ADR-005.)
- [ ] With public HTTPS ingress, visitors in a second network can reach landing/invitation entry; only an invited recipient can reach and complete email/password registration. Exercise the exact callback, code admission and logout against the actual hosted fAuth contract in installed Chrome (native Safari and Firefox: APP-079 by ADR-008; WebKit does not substitute for Safari). Prove actual verification delivery and mailbox activation, using controlled synthetic inboxes if appropriate; do not invent delivery or a verification JWT claim. Record identity/tenant/client/TLS/build receipts and usable keyboard/focus/error states without exposing credentials. (Edited from APP-074 item 1 by ADR-008: browser split.)
- [ ] The ADR-006 routes hold hosted against the deployed fAuth contract: `GET`/`POST /signin/{handle}`, `/auth/pending` and `POST /auth/pending/resend` in installed Chrome (native Safari and Firefox: APP-079) with real controlled-mailbox delivery, the provider resend outcomes mapped to `requested`/`unavailable`/already-verified, the 60-second cooldown and 5-per-24-hour limit, forged forwarded-IP refusal, and activation only through a fresh sign-in whose exchange reports `email_verified` true; these items need the qualified mail image recorded under FORMA-366, the lean fAuth deployment under FORMA-367 and its separately approved hosted-auth allowance, not the $5 identity rehearsal. (Edited from APP-074 item 8 by ADR-008: browser split; gates FORMA-366/367.)
- [ ] Against the accepted provider implementation, inspect actual backend PAR, browser navigation, email delivery, storage and logs: provider invitation capability is server-only/confidential, the explicit email/least-privilege role/destination stay bound, and the browser sees only bounded request URI and final code/state. Detect a deliberately exposed raw invite token or management credential. The old raw-token email URL and implicit administrator role are not accepted defaults. (Moved from APP-074 by ADR-008.)
- [ ] An invited, mailbox-verified member completes the integrated path on the live deployment: exact query with receipt → explicit command → one atomic record revision/outcome/audit → service restart → reopen of the same record/version/outcome; identical retries do not duplicate writes and stale edits conflict, with database-backed evidence.
The former item 7 (concurrent last-slot redemption through the public API, identical retry without a second slot, code or entitlement revocation refused at the next request and at result delivery, no revival by a late response or existing session) moved verbatim to [APP-083](APP-083.md) by [ADR-010](../../docs/architecture/ADR-010-NOV-2-MVP-CUT.md); identical retry and revocation at delivery for one admitted member stay in item 2 above, the storage race proof is APP-073's and the RDS lock-observation repeat is APP-080's.

- [ ] If a temporary `/32` infrastructure trial ran, it is over and HTTPS is restored to `0.0.0.0/0`; application denial works from the external test network. Disable signup/admission and exercise safe rollback without exposing a protected route or restoring a revoked entitlement. LLM calls remain disabled before APP-043. (Moved from APP-074 by ADR-008.) Rollback is exercised as a redeploy of the previous task definition (demo §11.1) that also disables protected work: during rollback protected routes answer the uniform 404 and no protected work is dispatched. The service is then restored and observed RUNNING with the exact candidate image digest recorded as the beta's, temporary resources are removed, the protected database identity is unchanged and the ledger is reconciled against the monthly figure Victor approves for the always-on beta (ADR-008; until approved, ADR-003's $100/month cap stands); the fAuth deployment's cost is a separately approved allowance recorded in the ledger before any reservation, with FormaStack's cost receipt attached. (Rewritten by ADR-008 for an always-on service; not a move.)
- [ ] Through the actual public beta API, anonymous, pre-access-only, expired/revoked-entitlement and foreign-tenant requests to real private routes, malformed or forged bearer and organization headers, known private IDs, guessed foreign IDs and nonexistent IDs receive the same designated response status, body and security headers, without existence disclosure or provider/queue effects; a forged token, a replayed authorization code and a cross-site POST are refused with the uniform response and no session is minted. (Private-route matrix moved from the APP-008 managed plan by ADR-005.)
- [ ] Audit rows written during the trial are insert-only for every application role and the per-organization, per-writer-role hash chains verify on RDS.
- [ ] An independent reviewer binds all receipts to the exact candidate commit, image digests, task-definition revisions, provider identities and fixture hashes and records them in `evidence/APP-076/` for the PH01 gate record; failures are retained with their disposition, and the gate record names the ADR-008 deferrals (APP-079, APP-080).

## Migration and rollback

Additive migrations only; retain committed history, outcomes and audit. Rollback is a redeploy of the previous task definition that disables new admission and command capabilities; it never erases a committed decision, reopens ingress to an unguarded app or introduces an organization picker. Any correction is a separately authorized compensating command.

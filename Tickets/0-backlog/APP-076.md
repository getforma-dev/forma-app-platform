## Why

The PH01 gate requires the integrated path on the managed synthetic environment with accepted upstream evidence and direct API denials; ticket completion alone does not complete the phase. [ADR-005](../../docs/architecture/ADR-005-PHASE-1-SEQUENCING.md) moves the hosted acceptance items of APP-012 and APP-073 here so those tickets finish on the local harness, and makes this trial the single owner of the end-to-end managed demonstration that feeds `evidence/phases/PH01/GATE.md`.

## What changes

On one exact candidate source/image, inside a reserved window with the auth consumer coordinated with FormaStack: apply every reviewed migration not yet applied by APP-078 on RDS through the operator task and repeat it unchanged; run the operator admission command on RDS; then prove the journey invite → verified sign-in → current tenant entitlement → authorized query → visible receipt → explicit command → atomic outcome/audit → restart/reopen at `https://beta.getforma.dev` against the hosted fAuth contract accepted in APP-006/074, including the denial, replay, concurrency and failure cases below. Stop the service, clean up, reconcile the ledger and obtain independent review. No LLM call is made.

## Acceptance tests

- [ ] Every reviewed migration not yet applied by APP-078 applies on RDS from the exact candidate image, adding exactly one history row per migration, with an unchanged idempotent repeat; the real managed database migration and operator command issue, list and revoke bounded codes; an ordinary application/member role and a forged operator identity are denied. (Moved from APP-073 by ADR-005.)
- [ ] Through the actual public beta API, anonymous, pre-access-only, expired/revoked-entitlement and foreign-tenant requests invoke no query engine and disclose no private metadata. A currently admitted member runs the same query successfully; entitlement revocation while queued/executing denies result delivery. Retain dispatch counters and both race orders, not just UI hiding. (Moved from APP-012 by ADR-005.)
- [ ] An invited, mailbox-verified member completes the integrated path on the managed environment: exact query with receipt → explicit command → one atomic record revision/outcome/audit → service restart → reopen of the same record/version/outcome; identical retries do not duplicate writes and stale edits conflict, with database-backed evidence.
- [ ] Both revocation/adoption-versus-commit orders, concurrent last-slot redemption, identical retry and code/entitlement revocation preserve their declared transaction boundaries on RDS with real lock observations; a late response or existing session cannot revive expired/revoked entitlement.
- [ ] Rollback disables new signup/admission and protected work without exposing a protected route or restoring a revoked entitlement; HTTPS remains `0.0.0.0/0`; every task is observed STOPPED, temporary resources are removed, the protected database identity is unchanged and the ledger is reconciled within $100/month. The original $5 covers only the identity-only rehearsal; this window's hosted-auth cost is a separately approved allowance recorded before reservation.
- [ ] Through the actual public beta API, anonymous, pre-access-only, expired/revoked-entitlement and foreign-tenant requests to real private routes, malformed or forged bearer and organization headers, known private IDs, guessed foreign IDs and nonexistent IDs receive the same designated response status, body and security headers, without existence disclosure or provider/queue effects; a forged token, a replayed authorization code and a cross-site POST are refused with the uniform response and no session is minted. (Private-route matrix moved from the APP-008 managed plan by ADR-005.)
- [ ] Audit rows written during the trial are insert-only for every application role and the per-organization, per-writer-role hash chains verify on RDS.
- [ ] An independent reviewer binds all receipts to the exact candidate commit, image digests, task-definition revisions, provider identities and fixture hashes and records them in `evidence/APP-076/` for the PH01 gate record; failures are retained with their disposition.

## Migration and rollback

Additive migrations only; retain committed history, outcomes and audit. Rollback disables new admission and command capabilities; it never erases a committed decision, reopens ingress to an unguarded app or introduces an organization picker. Any correction is a separately authorized compensating command.

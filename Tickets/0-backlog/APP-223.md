## Why

Forma Canvas on beta.getforma.dev has no footer and no public legal page. A visitor cannot find About, the Forma blog, a contact address or the terms they agree to without an invitation code in hand. The class of Nov 28–30 and anyone a member shares a link with should see the small set of links a SaaS product normally carries, without a marketing site.

## What changes

1. **One footer** (`app/admin/src/site/footer.tsx`). A `<footer>` after the page's `<main>`, so it is the page's contentinfo landmark. It holds one `<nav aria-label="Footer">` with three groups: **Forma Canvas** (Home `/`, About `/about`, Sign in `/signin`, "Have an invitation?" `/invite`), **Forma** (Forma Stack `https://getforma.dev`, Blog `https://getforma.dev/blog`, Server lab `https://getforma.dev/labs/`, each `rel="noopener"` and without `target`, like the About page's external link) and **Help & legal** (Contact `mailto:support@getforma.dev`, "Beta terms & privacy" `/notice`, Security `/.well-known/security.txt`). A bottom line shows the Forma mark (the pages' own tile and wordmark, not a link, hidden from assistive technology) and "© 2026 Forma · Forma Canvas is in private beta." It takes no props, reads nothing from the request and runs no script.
2. **Which pages.** `/`, `/about`, `/notice`, `/signin` (with and without a handle), `/invite`, `/auth/pending`, `/auth/callback` (denied), every error page (it replaces the one-line "Forma beta · Questions?" footer), `/admin`, `/record`, `/w/{app}/{work}` and `/s/{share}`. Not `/canvas`, `/shared` or `/workspace`. There is no member-name page: `POST /me/name` answers a `303` to `/canvas`, and the name form lives in the canvas, so it gets no footer.
3. **The notice page** (`app/admin/src/notice/app.tsx`, `pages::NoticeProps`). `GET /notice`, "Beta terms & privacy", shows one sentence ("This is the notice every member accepts when joining. Questions or data requests: privacy@getforma.dev.", a mail link), the version (`NOTICE_VERSION`) and the notice title and paragraphs. `NoticeProps::current` builds them from `auth::notice` through `InviteProps::notice`, the rows the invitation page shows, so no text is copied. It is served like `/about`: declared in `build.ts`, required SSR at startup, bound before `finalize`, a complete `PageResponse` (nonce CSP with `frame-ancestors 'none'`, `no-store`, `nosniff`), no session read and no cookie. Any method other than `GET` and `HEAD` is the uniform 404. The binary's own routes move into `site()` so the test drives the production composition. The dev stand drops `/notice` with `/` and `/about`, as before.
4. **The canvas** (`app/admin/src/canvas/app.tsx`, `canvas.css`). The top bar's Feedback link becomes a "Help" `<details>` menu, styled like the name menu, holding Feedback (still `feedback@getforma.dev`), "Beta terms" `/notice` and "About" `/about`; the two pages open with `target="_blank" rel="noopener"` so the canvas keeps its state. Two more links would have pushed the name menu and Sign out out of the row (see the log). At phone width the list is `position: fixed`, so the scrolling header row cannot clip it, and the first-run name prompt drops below the top bar while the menu is open.
5. **`GET /.well-known/security.txt`** (RFC 9116, `product::SECURITY_TXT`). A static constant, merged into the product router so the uniform layers apply: `200 text/plain; charset=utf-8` with `http::secure`'s non-page headers (`no-store`, `nosniff`, `no-referrer`) and HSTS from `finish`. The body is exactly `Contact: mailto:security@getforma.dev`, `Expires: 2027-11-15T00:00:00.000Z`, `Preferred-Languages: en` and `Canonical: https://beta.getforma.dev/.well-known/security.txt`, one line each. Any method other than `GET` and `HEAD` is the uniform 404. It is not a refusal, so a browser navigation gets the text. Renew `Expires` before November 2027.
6. **The look** (`app/admin/src/styles/app.css`, `error.css`). Existing tokens only: muted 13 px type under a hairline (`--forma-line`), mono group labels, three columns, the groups stacked at phone width with their links in a row. The footer keeps the width of the page column above it (32, 48, 64 or 72 rem), so its edges line up with the page's; on the error page it takes the card's width. Light and dark follow the existing roles. No font, image or external resource is added.
7. **The image allowlists.** The root `.dockerignore` admits `app/admin/src/site/footer.tsx` and `app/admin/src/notice/app.tsx`. No Rust file is new and the qualification image builds no browser bundle, so `app/qualification/Dockerfile.dockerignore` and the managed qualification's source bundle are unchanged. **This changes the deployment contract digest**, so the change ships inside a reviewed contract-only release, as APP-217 did. No migration.

## Migration and rollback

No migration, no contract edition, no infrastructure and no operator change.

## Why

A canvas of mock numbers would not survive an investor's question. The views must run on the organization's data and show where each number comes from.

## What changes

Bind canvas views to the governed query path (APP-012's engine) so each number carries a visible receipt, and add the record form submitting through APP-013's explicit commands (idempotent, transactional, audited, stale-edit conflict).

## Acceptance tests

- [ ] Each canvas view displays its query result with a visible receipt, and a view with no receipt shows no number.
- [ ] A foreign tenant or anonymous caller cannot run the view's query; denial is the uniform 404 and invokes no query engine.
- [ ] The record form submits one explicit command; an identical retry does not duplicate the write and a stale edit conflicts.
- [ ] The audit row for the command is written and verifies.

## Verification

Run on the synthetic fixtures through the clone; retain receipts, statuses and the audit check, sanitized.

## Migration and rollback

No schema change beyond what APP-012/013 already apply; the form is removable.

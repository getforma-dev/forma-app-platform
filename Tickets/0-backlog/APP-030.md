## Why

Internal decisions must survive retries and restarts without duplicate mutations, silent overwrite or stale authority. This ticket delivers: generalize forms and commands without weakening transaction invariants.

## What changes

Stable typed fields, source-reference/row/field authorization, transitions, per-work uniqueness; server-rendered pre-activation submit and post-adoption submit share idempotency semantics; clear pending/committed/unknown/conflict recovery.

Keep this a reviewable slice: L means approximately 3–5 focused days. Re-estimate before selection and split the ticket if it exceeds five focused days. The estimate is a planning bound, not a delivery date.

Scope excludes production deployment and real customer data; this is a synthetic qualification. Upstream framework/auth changes remain with the FormaStack team.

## Acceptance tests

- [ ] Create/update forms enforce stable field types, constraints, per-work record identity, authorized source references and permitted transitions on the server.
- [ ] Submit a server-rendered form before island activation and retry after activation; one intended outcome is observed with the same idempotency semantics.
- [ ] The UI distinguishes absent/pending/committed/failed/unknown/conflict states and offers authorized recovery without silently overwriting concurrent changes or implying an external payment.

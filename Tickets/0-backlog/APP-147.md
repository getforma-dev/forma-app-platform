## Why

"Card" is used for a view, a form, a records list, and a thing on the board. Victor's direction is that those are components of one app. APP-141 and APP-142 need a list of component kinds and a rule for what happens when a component is focused, fanned out, or taken off the app. The last of those is not decided. This spike writes the list and records the open rule. It does not implement detach.

## What changes

Write `docs/planning/app-model/components.md`. Read APP-120's object list, APP-106's focus and unite, and the work outline that `GET /w/{app}/{work}` already renders.

1. **Kinds.** Name the component kinds the admitted definition already has: a view that returns numbers or rows, a records collection, and a form that posts a command. A component is one of those, addressed `app.card` or by the pane number. It is not a separate app.
2. **On the board and in the page.** On the board a component is a card. In the APP-142 page the same component is a part of the page. Focus opens one component. Fan-out puts the components back on the board. The data is the saved work either way.
3. **What is not a component.** A widget. A stack. The page frame. The window size.
4. **Open, and not built here.** Whether a component can leave the app and become a widget while its records stay. Whether a component can be removed from the app and keep its data. The note lists both as open. It does not pick an answer unless Victor has written one.

No product code in this spike.

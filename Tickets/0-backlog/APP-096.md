## Why

The pitch is only real if it runs on the live beta in front of the audience.

## What changes

Deploy the clone's build to the beta through a reviewed change set, keeping the Phase 1 task-definition revision available for rollback. Write a rehearsal script (describe, canvas, governed data with receipt, share, outsider denial) and run it on the live beta with sanitized evidence.

## Acceptance tests

- [ ] A reviewed change set deploys the pitch build; the Phase 1 rollback revision remains available and a rollback is rehearsed.
- [ ] The rehearsal script runs end to end on the live beta in installed Chrome, with timings and the model call cost recorded.
- [ ] Sanitized evidence holds no credential, address, token or code and binds to the deployed commit and image digest.
- [ ] The scope of the beta's ledger and monthly figure is checked before the deploy.

## Verification

Tier A review for any auth, isolation or admission change in the change set (ADR-011 §3–4). Retain the script, outputs and digests under the clone's evidence directory.

## Migration and rollback

Rollback is a redeploy of the Phase 1 task definition; committed data and audit are never erased.

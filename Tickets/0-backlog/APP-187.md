## Why

The stack has no CloudWatch alarm, SNS topic or AWS Budget, so nobody would know the beta was down or overspending. Changing `infra/src` would block promotion, so the alarms are kept outside it.

## What changes

A standalone CloudFormation template, `ops/monitoring/alarms.json`: an SNS email topic to Victor; alarms on load-balancer 5xx, unhealthy targets, ECS running tasks below 1 and RDS free storage; and an AWS Budget alert. A Python test pins its resources and parameters. Victor deploys it once with his operator identity.

## Acceptance tests

- [ ] The template's resources, thresholds and parameters are pinned by a test, and no `infra/src` file changes.
- [ ] After Victor deploys it, the topic subscription is confirmed, a test notification reaches him, and every alarm reads OK.
- [ ] The trial runbook names what each alarm means and the first response.

## Verification

The template test; Victor's deploy and test-notification evidence.

## Migration and rollback

Deleting the standalone stack removes the alarms without touching the service.

## Why

The [designer brief](../../docs/design-brief/README.md) lists engineering gaps the design will expose. The live beta works, but the landing ships a framework demo counter, error pages are raw JSON in a browser, one form field is free text, and several controls fail contrast or have no focus ring. The designer's mocks are applied after these fixes so the design lands on a sound base.

## What changes

1. **Remove the framework demo counter island on `/`** (it ships 28,168 B gzip of JavaScript, the only JS in the build), so the landing ships no JS; the size report then has no interactive route.
2. **Neutral HTML 404 and 503 pages for browsers** (today `application/problem+json`): content negotiation on `Accept` serves one neutral HTML page; the uniform-response guarantees hold (identical status, headers and body for every 404 cause: anonymous, expired, revoked, foreign, nonexistent; no hint about existence or sign-in state; a link home), and API clients still receive the JSON body. Tests compare the byte-identical bodies across causes.
3. **Spend Review status field as a `<select>`** with the same `name` and option values as the free-text input.
4. **Receipt starts expanded** (it starts collapsed today), keeping the digest rows and their order.
5. **Contrast and focus:** borders about 1.35:1 (need 3:1 for input borders and UI edges), the dark-theme failed/denied red `#b3261e` at 2.72:1 (need 4.5:1), and unstyled buttons (sign-in, pending, denied, workspace sign-out, record submit) with a visible `:focus-visible` ring on every link, input and button.
6. **CSS size budget:** add a CSS budget to the build's size report (the Forma code and JS budgets exist; CSS has none) and fail the build when exceeded.
7. **Apply the designer's mocks when they arrive:** tokens, typography, components and the listed states from the brief's deliverables, within the brief's constraints (server-rendered, no client JS, `font-src 'self'`, same form `action`s and field `name`s, the **keep** copy unchanged in meaning).

## Acceptance tests

- [ ] `/` ships no JavaScript and the size report shows no interactive region and a CSS budget that the build enforces.
- [ ] A browser request for any unknown path and for each protected-route refusal cause gets the same HTML 404, byte-identical across causes; a JSON client still gets the uniform JSON; a 503 page exists in the same style; no existing uniform-refusal test is weakened.
- [ ] The Spend Review status control is a `<select>` posting the same values, and the receipt is expanded on first render of a ready or empty result.
- [ ] Measured contrast meets 4.5:1 for text and 3:1 for input borders and UI edges in light and dark, and every link, input and button shows a visible focus ring (keyboard walk of each page recorded).
- [ ] The designer's mocks are applied page by page with before/after screenshots at 1280 and 390 widths, and an independent review binds the changes with no blocking finding.

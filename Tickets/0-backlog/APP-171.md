## Why

Apps are whole products made of components. The Library and canvas should make that identity clear and prevent overlapping owners of the same DOM components.

## What changes

Explore an optional desktop icon view of the same whole app, with accessible label, double-click/Enter Open, Focus/Edit/Share/Open page and visible placement state. Keep App Card as the current shipped entry point; this ticket is a measured design/interaction decision before implementation.

## Acceptance tests

- [ ] Compare icon and App Card at mobile/desktop scale with keyboard and touch navigation.
- [ ] Prove the proposed icon reuses whole-app placement and keeps authorized new-tab page access.
- [ ] Record the decision and any implementation ticket without duplicating app identity or changing data ownership.

## Verification

Record focused tests, browser evidence and independent review before completion. Planning checks alone do not prove behavior.

## Migration and rollback

Preserve saved works, grants, records and receipts. Browser-local view metadata is bounded and contains identifiers only. Deploy through the existing protected pipeline after review; no cloud change is part of this ticket's current implementation turn.

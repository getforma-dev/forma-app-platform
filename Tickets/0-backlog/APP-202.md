## Why

Release C adds six grammar members and one renderer kind ([ADR-020](../../docs/architecture/ADR-020-PARTICIPATION-PRIMITIVES.md) §§4–11). Every builder after this one consumes the admitted shapes, so the grammar lands first, once, in one new contract edition (ADR-002: a compatibility change is a new edition; the published edition's fixtures and digests are never changed in place).

## What changes

Edition `impl-2026-11-14.2`, exactly as ADR-020 §11:
- `record_schema.one_per_creator` (1..4 ids; requires `visibility: "own"`; the key rules of §5);
- `guard.via` and the literal `{"type": "now", "offset_seconds"?}` admitted only inside `command_declaration.requires[].value`; `command_declaration.requires` (1..4) and `set_now` (1..4 timestamp fields, not writable) per §6;
- renderer kind `countdown` with `records: {version, input_id, schema_id, timestamp_field, offset_seconds?, closed_when?}` per §4;
- `record_component.group_by: "creator"` (exactly one of `group_field`/`group_by` on `record_ranking`), `record_measure` `matches` on `record_summary` and `record_ranking`, ranking `limit` 1..50 per §7;
- value type and value `multi_enum` with the refusals of §9;
- problem codes `requirement_not_met` and `unchanged` (422, no `recovery_view`, no `current_revision`);
- `record_components_receipt.components[].kind` gains `countdown`.

Both validators enforce every rule (stored and new content alike). Edition `impl-2026-11-14.1` is retained whole under `contracts/fixtures/impl-2026-11-14.1/` and recorded in the lock; `schema.json` `$id` moves; the README gains the edition section; ADR-002 gains the edition note. Owned files: `contracts/schema.py`, `schema.json`, `validate.py`, `make_fixtures.py`, `record_components_contract.py`, `test_contracts.py`, `fixtures/negative-vectors.json`, `fixtures/impl-2026-11-14.1/**`, `implementation-lock.json`, `README.md`; `app/src/admission/validate.rs`, `tests.rs`, `record_receipt.rs`, `mod.rs`; `docs/architecture/ADR-002-CONTRACT-EDITION.md`. Nothing else.

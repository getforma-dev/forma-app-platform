## Why

Victor, 2026-10-31:
- "for the command /apps is there an argument that comes after it? We should show options and arguments …"
- "/apps brings up the commands, should this be /commands instead? … why is it a card on the canvas? And there is no way to remove it."
- "do the best practice pattern."

The best practice (Slack, Discord, Raycast, Linear) is one command registry with typed arguments. That single registry drives:
- autocomplete, with inline argument hints and live value suggestions;
- a help sheet;
- the shortcut sheet.

There are no duplicate surfaces: the Library pane is the app directory.

## What changes

1. **Registry.** One table, in `app/admin/src/canvas/slash.ts` or a new `command-registry.ts`. Each command declares:
   - name and aliases;
   - category: Apps, Records, Folders, Canvas, Widgets, Agents or Help;
   - a one-line description;
   - arguments, as `[{name, kind: text|app|card|folder|city|zone|optional…, required}]`;
   - one or two examples.

   Registered app slugs (library, named apps) and widget commands (`registerCommands`) join it with the same shape.
2. **Autocomplete with arguments.**
   - Typing `/` lists commands by category, each with its argument signature (for example `/expense <what you spent>`).
   - After `/name ` the bar shows the next argument's hint and an example as ghost text or a hint row. Live suggestions appear for argument kinds that have values: apps for `/apps` and `/unite`, cards with numbers for `/card`, folders plus `new` and `formation` for `/folder`, and recent cities for `/weather`.
   - Tab or Enter accepts a suggestion. The list is keyboard-navigable and readable by screen readers.
3. **`/commands`** (aliases `/help`, and `?` when the bar is empty) opens a command sheet: a modal or side sheet, not a canvas card.
   - Categories, each command with arguments and examples, and a search box.
   - Clicking a command inserts it into the bar.
   - Esc or × closes. Focus is trapped and returned (APP-113 pattern).
   - The `?` shortcuts sheet links to it.
4. **`/apps [query]`** opens the Library pane, filtered by the query when there is one. The bar's suggestions after `/apps ` list matching apps; Enter places one, exactly as the pane's Add does. The canvas card that `/apps` used to create is removed. Any already in a member's saved layout loads with × and a one-time note ("The app list moved to the Library (L)").
5. **Utilities.** The Library's Utilities group keeps the widgets and notes. Every utility card has × (APP-112 parity).
6. **Docs.** GUIDE.md commands table and SCENARIOS.md lines updated.

## Acceptance tests

- [ ] Typing `/` shows every command with its argument signature, grouped by category. `/expense ` shows its argument hint and example. `/card ` suggests numbered cards. `/folder ` suggests folders plus `new` and `formation`. `/apps ` suggests apps and Enter places one.
- [ ] `/commands` and `/help` open the command sheet, which is not a canvas card. Clicking a command fills the bar. Esc and × close it, and focus returns.
- [ ] `/apps` opens the Library pane (filtered by any query) and never places a canvas card. A previously saved `/apps` card loads with × and can be removed.
- [ ] One registry is the only source: the autocomplete, the command sheet and the `?` sheet list the same commands (unit test).

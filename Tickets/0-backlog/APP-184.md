## Why

There is no dollar, daily or per-organization model cap (APP-043 is in Backlog). Only per-member hourly windows exist, and they reset on every deploy. A real trial needs a hard daily ceiling that members understand when they reach it.

## What changes

One process-wide daily counter, reset at UTC midnight, checked where every Anthropic request is sent (`composer/model.rs` `send` and `complete_with_documents`). Five model clients exist, so the counter is shared. Past the cap the call fails with `model_daily_cap`, which the compose, Ask, Shape, folder Ask and explain routes answer as 429 `daily_limit`. The canvas says: "Today's AI limit for the trial is reached. It resets at midnight UTC." The default is 300 calls a day, in code. `GENUI_MODEL_DAILY_CALLS` overrides it for tests, with no stack change.

## Acceptance tests

- [ ] Past the cap, no request reaches the provider, and each listed surface answers 429 `daily_limit` with the plain message. Unit and campaign tests show it, and removing the check fails them.
- [ ] The counter is shared by every model client in the process and resets at UTC midnight. A unit test with an injected clock shows both.
- [ ] An independent review finds no blocker.

## Verification

Unit tests for the counter; the composer and actions campaigns with the cap set low by env; `just check admin test`.

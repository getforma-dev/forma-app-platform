## Why

Victor, 2026-10-30: "the weather widget/app was built, that can be a one off to show a user can customize their working dashboard", and "/calculator make it a TI-84 in the Matrix style".

This is a short breadth beat. It shows that the canvas is the member's own workspace, and that the same intent bar restyles things in words. The governed apps remain the story.

## What changes

1. **Widgets, ported from our own `forma-generative-ui` registry.**
   - **Weather.** `registry/artifacts/weather-card/1.1.0` provides the look. `src/connectors/catalog/environment.rs` (`geocode`, `weather`, `weather_condition`) is ported as `GET /v1/widgets/weather?location=&units=`:
     - Open-Meteo, no key, an 8 s timeout, a bounded response, and no redirects, following the `media.rs` fetch pattern.
     - A fixture mode serves canned data when the network is off, and always serves it inside the demo organization (DS-65).
   - **Calculator.** New, with a working keypad and expression evaluation by a small safe parser (no `eval`).
   - **Clock.** `retro-digital-clock/1.2.0`, with time zone and 12/24 h.
   - Widgets are client-side canvas cards with no governed data. They are labeled "widget" and need no receipts.
2. **Commands.** `/weather [place]`, `/calculator`, `/clock [zone]`. They register through APP-101's pluggable canvas command list and appear in `/apps`.
3. **Customize in words.**
   - Text after the command, or a message to a placed widget ("make it a TI-84 in Matrix style", "show Celsius", "Tokyo"), becomes a **closed, typed widget state** produced by the fast model. This is the pattern of `forma-vector-studio/src/server/customizer.rs`: the model returns state JSON of the same shape. The state includes:
     - `skin` (one of a fixed set: `default`, `ti84`, `matrix`, `retro`, `glass`, `paper`);
     - `accent` (one of a fixed palette);
     - `font` (one of a fixed set);
     - the widget's own arguments (location, units, zone, 12/24 h).
   - The server validates the state against the closed set. The model never writes CSS or markup (I5).
   - Inside the demo organization, the rehearsed sentences map to fixed states without a model call (DS-66).
   - The full generative restyle is the proper fix (DS-66).
4. **Layout.** Widget placement uses the canvas's existing per-browser layout (DS-06).

## Acceptance tests

- [ ] `/weather Austin` places a weather card with current conditions (live or fixture, labeled); `/calculator` computes `12*(3+4)` = 84; `/clock Tokyo` shows Tokyo time.
- [ ] "make it a TI-84 in Matrix style" turns the calculator into the TI-84 skin with the Matrix palette; the request round trip is ≤ 1.5 s with the real model, instant for the rehearsed sentence.
- [ ] A model reply outside the closed set (unknown skin, CSS, markup, script) is refused and the widget keeps its state.
- [ ] The calculator's parser refuses anything but numbers, operators and parentheses.

## Verification

Unit tests for the state validation and calculator parser; one real-Haiku customize smoke (decisions and latency only); a canvas screenshot of each skin.

## Migration and rollback

No migration. Widgets are client-side; removing the commands removes them.

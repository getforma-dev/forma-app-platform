## Why

Two workflows were red on every `pivot/pitch-mvp` push since 2026-10-30 (inventory §B.6): **Foundation preparation** (last green `b704274`, run 41077522217) and **Tenant foundation qualification** (last green `9234dbe`). Each red run stopped at its first failure, so later steps had not run for a day and hid further failures. ADR-012 D12.6 requires each to be fixed within a day or quarantined, and the APP-013 campaign regression to be ticketed either way.

## What changes

Each red step was reproduced locally, its root cause found, and fixed (none needed a quarantine):


1. **Foundation: the runtime venv lacked the contracts lock** (CI-vs-local difference). `scripts/check-foundation.py` installed only `app/runtime/requirements.lock`; `app/runtime/test_library.py` (APP-107/108, 2026-10-30) imports `contracts/validate.py`, which needs `jsonschema` from `contracts/requirements.lock`. CI run 41214071302's artifact `local-preparation.json`: `ModuleNotFoundError: No module named 'jsonschema'` (1 error, 1 failure of 179). Locally green because `just setup` installs both locks into the runtime venv (`scripts/dev/setup.sh:61`, ADR-012 D12.4), and `tenant-foundation.yml` does the same. Reproduced with a fresh uv venv holding only the runtime lock (same error), green with both. **Fix**: `check-foundation.py` installs both locks.
2. **Tenant foundation: `native_command_campaign` "expected a committed command: Err(Denied)"** at `command_qualification.rs:204` (the `committed` helper), called for ik-2. Cause: `becf103` (APP-113 storage 1, merged 2026-10-30) added `require(!(fired && by_filer))` to `commands::compose`: a declared transition on an existing record is refused when the decider filed it ("an approver decides other people's claims, in every path"). The campaign (written for APP-013 before that rule) has the author file EXP-002 and then decide it. The new behavior is by design (reviewed, merged, deployed as TaskDefinition:9 per APP-113's log), so the **test's expectation is wrong, not the code**; nothing in authorization is weakened. **Fix (test only)**: the reviewer, granted `record_read`/`record_write` on the work before the first command, decides; the campaign now also asserts the filer's ik-2 is Denied with nothing written. The HTTP section's session is the reviewer's (its form decides LOST_RECORD, which the author filed); the row-visibility check expects exactly the reviewer's own outcome.
3. **Tenant foundation: `native_race_campaign`** (APP-014; never reached in CI because step 2 failed first): the same `Err(Denied)` at k2, for the same reason. **Fix (test only)**: the reviewer (granted at the start, its session minted after the restart) takes each needs_context → reviewed transition (k2, B and B-changed, C/D and their recovery, the route recovery on r8, k35's recovery); refusals that never fire a transition stay the author's (they are refused before the filer rule is reached).
4. **Tenant foundation: `native_query_campaign`** (APP-012; also never reached): `seed-library` returned 20 apps against a hard-coded 13 (`query_qualification.rs:573`); the library grew with APP-107. **Fix**: the counts come from `contracts/fixtures/library/catalog.json` (apps; distinct source ids for `library_sources.build`, 19, since apps share sources).
5. **Tenant foundation: `app/qualification` unittests** (new at `f99deec`, from the APP-128 merge): `Dockerfile.dockerignore` re-included `app/src/dev/` and `app/src/bin/` as directories, which `check_image.allowlist` refuses unless closed by `dir/**` (ValueError); and `test_tools.compiled_rust_sources` counted the feature-gated `dev-stand` sources as compiled by the release build, while the root `.dockerignore` correctly leaves them out (APP-128 verified `cargo check` without them). **Fix**: the five dev files are listed one by one; `compiled_rust_sources` drops `#[cfg(feature = "…")]` modules and `[[bin]]` targets with `required-features` (the Dockerfile enables no feature: ADR-007 D7.13, ADR-012 D12.1).

6. **New `pitch.yml`**: the eight cheap pitch-era campaigns (next section); `scripts/dev/campaigns.tsv` marks them `pitch`, and `just ci` / `check.sh` name both workflows.

No workflow is quarantined: every red step had a fix of under a day. The only workflow edit is ADR-013 D13.9 row E: a `concurrency` group (`workflow`-`ref`, cancel in progress) in ten workflows. **`parser-release.yml` is left without one**: a release refuses parser bytes without a passing record composed by a push run of that commit (its header comment), so cancelling a superseded run would leave that commit without a record.

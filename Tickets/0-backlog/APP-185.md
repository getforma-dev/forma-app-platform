## Why

The documented invitation path (`ops/beta/run-step.sh`) is fenced since deploy state moved to the promotion bucket. `ops/promotion` has no admission command, so nobody can be invited through a reviewed path.

## What changes

A new `ops/promotion/admission.py`, following the operator module pattern (`AWS()`, `identity()`, `Store`, `--expected-state-sha256`, receipts):
- `issue --count N` mints codes locally, writes the one-shot invitation-input secret, runs the operator task with the issue override for the trial organization, waits, clears the secret, and writes the codes to a private file.
- `list`.
- `revoke --code`.
- `grant-admin --principal`.
- `delete-uploads --principal`, which deletes every S3 version of that member's uploaded files.
- `restart`, an announced forced deployment.

Trial-organization overrides are added to `app/operator/overrides.json`. One restart serves every invite issued before it.

## Acceptance tests

- [ ] Each command's request is built and refused exactly as specified in fake-AWS unit tests: wrong account, wrong organization, stale state hash, a secret left non-empty after a failure, and more than 128 capabilities.
- [ ] `issue` never leaves the invitation-input secret populated, even when the task fails, and the codes exist only in the private output file and in Victor's own sending.
- [ ] The trial runbook (APP-188) names each command with its expected output. An independent Tier A review finds no blocker.

## Verification

`just check py-promotion` (or the module's unittest); a dry run against the fake AWS client; Tier A review file in `evidence/APP-185/`.

## Migration and rollback

Operator tooling only. A run that fails part-way leaves receipts and is safe to retry with the same codes.

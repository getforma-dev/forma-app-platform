## Why

The product claim requires meaningful new apps and edits through supported primitives, with no developer rewriting a second example. This ticket delivers: complete appdefinition schema and registry admission.

## What changes

All required views/queries/record schemas/commands/links/layout, stable field IDs, canonical digest and complexity budgets; immutable revisions, unknown versions/capabilities/authority rejected; compatibility fixtures.

Keep this a reviewable slice: L means approximately 3–5 focused days. Re-estimate before selection and split the ticket if it exceeds five focused days. The estimate is a planning bound, not a delivery date.

Scope excludes production deployment and real customer data; this is a synthetic qualification. Upstream framework/auth changes remain with the FormaStack team.

## Acceptance tests

- [ ] All launch views, query inputs, stable record field IDs, bounded commands, links, defaults and explicit app completion semantics fit one versioned canonical AppDefinition.
- [ ] Unknown capabilities/versions, executable markup/code/SQL/FMIR, permission grants, arbitrary paths/URLs and excessive complexity are rejected as a whole.
- [ ] Persist/reload and schema compatibility fixtures preserve field identity and meaning; publication contracts never smuggle private evidence revisions into reusable definitions.

## Why

Victor's 25 adult students use his class apps on Nov 29–30. Two general defects in Release C's record components would mislead them or their grader:

- **A.** A `record_summary` or `record_ranking` with a `matches` measure is computed under the viewer's `own_rows` (ADR-020 §7). A contributor cannot read an owner-filed `own` key list, so their page shows themselves with a score of 0. A student who answered correctly sees 0. That is wrong, not "honest and harmless".
- **B.** An update or transition form's record chooser labelled each record `<first text value> · revision n` (`app/src/query/routes.rs`). A reviewer grading 25 submissions could not tell whose entry was whose, although the Records card beside it already names the filer.

## What changes

**A. The key must be readable, or the component is withheld (ADR-020 §17.34).** Decided server-side, once, where the snapshot is captured (`app/src/storage/record_components.rs`, `capture`), so every path agrees: the canvas, the work page, the record page, the FMIR SSR, the live refresh and any other reader of the run.
- The key is unreadable when both hold: the `key_input`'s bound collection is declared `visibility: "own"`, and the viewer is neither the app's owner nor a reviewer of the work. The test is exactly the one `own_rows` applies to a row the viewer did not create (`authorization::hidden`, which embeds `reviewer_clause`): one SQL statement per key input, `SELECT $collection = ANY(hidden(app, work, SCOPED))`. No second definition of a reviewer is written. Under `authorization::BYPASS` nothing is withheld.
- A withheld component leaves the engine payload: it is never computed, so there is no misleading value; the key input is not captured when no remaining component names it (the contributor's snapshot lists no `expected` revision); the result document and the receipt carry no value and no coverage for it. The run lists the withheld declarations (`RecordComponentsRun::withheld`).
- Every path shows the same thing: the props (`query::record_components::withheld_props`) carry the state `withheld`, the message exactly `Scores are shown to this app's reviewers.` (`WITHHELD_NOTE`) and no number, rows, groups, filters or receipt. `props`, `unavailable_with_parameters` and `record_routes::compute` (the one function both pages and the JSON batch call; a run with nothing left to compute still answers the note) append them. The wire shape of the record-components response is unchanged (a `state` value and the existing `message` member), so the client needs no change; no contract, edition, migration or SQL schema change.
- Unchanged: `count` and `sum` measures, every `matches` whose key list is shared or readable to the viewer (the owner's and the reviewer's pages compute as before), the engine (`record_engine.py`), the receipt kind and every digest domain.

**B. Grading by name (ADR-020 §17.35).** In `query::routes::document_forms`, when the chooser lists records of a collection declared `visibility: "own"`, each label is `<creator label> · <first text value or "Record"> · revision n`, with `<creator label>` = `directory::label(organization, creator)`, the same name the Records card's "Filed by" and the ranking use. It applies to every viewer of an `own` collection (a contributor sees only their own entries, so their own name: one rule, no viewer branch). Shared collections keep today's label byte for byte; the ADR-020 §6 reference picker is unchanged; the text part is cut at 100 characters and the name never is (`record_choice_label`). `RecordDetail` gains `own` from the published schema's `visibility` (presentation only; the row rule stays `own_rows`). The work page, the work client (`admin/src/work/render.ts`) and the record page (`admin/src/record/app.tsx`) render the labels the server sends, so one rule serves all three. The canvas has no record chooser: an update form there is reached from the Records card, which names the filer. No new data is released.

Files: `app/src/storage/record_components.rs`, `app/src/query/record_components.rs`, `app/src/query/record_routes.rs`, `app/src/query/routes.rs`, `app/src/query/route_tests.rs`, `app/src/storage/commands.rs` (`Published.own`, `RecordDetail.own`), `app/src/commands/tests.rs` (literals), `app/src/storage/record_components_campaign.rs` (the APP-211 checks), `app/src/storage/composer_qualification.rs` (acceptance 3's contributor assertion), ADR-020 §17, `evidence/APP-211/`.

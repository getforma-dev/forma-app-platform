## Why

Victor wants creating an API to feel as direct as FastAPI feels to a programmer, and he wants it on the drop: pick one, or describe one, and it lands. He also wants an API bank, a store of APIs to choose from, and a place those definitions live. This is not the trial and not the app-page start. It is recorded so it is not forgotten.

## What this is

An API here is an admitted definition, not a program. It names a method, a path shape, the input fields, the output fields, and which saved work or source it may read or write. The platform runs it through the existing session, tenant fence, command or query route, and receipt. The model may propose that definition as data. It may not return Python, SQL, HTML, FMIR, or a grant. There is no embedded FastAPI process and no second database server.

The API bank is a catalog of those definitions, the way the library is a catalog of apps. "API db" means those rows live in the tenant's existing store, under the member's grants. It is not a new engine.

Drop means the same gesture as a library card: the member drags an API from the bank onto an app, or describes one and confirms, and it becomes a way to call that app. It does not become its own app and it does not skip admission.

## What changes

1. The bank lists admitted API definitions the member may use. A foreign tenant's API is absent, not described.
2. Adding one is explicit. A template or a short description comes first. Confirm admits the definition. Cancel writes nothing.
3. The drop attaches that API to an app the member may already edit. A member who owns no authoring app is still stopped by APP-145. This ticket does not create the shell.
4. Calling the API is a governed route. A write is the existing command path. A read is the existing query path. A number carries its receipt. A stranger gets the uniform 404.
5. MCP agent tokens in APP-115 are not this bank. An API a person calls and a token an agent uses stay separate.

## Acceptance tests

- [ ] The bank shows only APIs the signed-in member may use. Another organization's API is not listed.
- [ ] Describing an API and confirming stores an admitted definition. The stored row contains no executable source. Cancel stores nothing.
- [ ] Dropping an API onto an app attaches it to that app. It does not create a second app.
- [ ] A call that writes uses the command route. A call that reads uses the query route. A governed number carries a receipt.
- [ ] A request with no session, or for a work the member cannot read, is the uniform 404.

## Verification

Read `admit_definition` and the library drop before designing the bank row. One fresh-browser check on a worktree port when it is built. Ports 4001–4003 and 4010 stay untouched. This ticket is not scheduled ahead of APP-141.

## Migration and rollback

A later migration may add the API definition rows. This ticket does not add one. Removing the bank hides the catalog. Definitions already admitted stay until an operator removes them. No route is added by recording the ticket.

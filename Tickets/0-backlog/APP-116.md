## Why

Victor, 2026-10-30: "we want to show the real AI and MCP work in real time, and I'll show the time it took as real numbers." The app should measure and display its own step times, so a recording can show real numbers without manual timing.

## What changes

The timing chip is off by default and turned on with "Show timings" in the toolbar menu, or with `#timing=1` (the canvas URL takes no query string). When on, every action shows a compact chip with its real steps, measured by the client and, where available, by the server's per-step durations returned in responses. For example:
- `pick 4 ms · reshape 0.8 s`;
- `draft 0.9 s · saved 0.1 s · live on Sarah's screen 0.04 s`;
- `formation: context 0.2 s · model 5.8 s · admitted 0.05 s · views 0.6 s`.

Agent calls (MCP) appear in a small "agent activity" chip on the affected card: the tool name, its duration, and "via <label>".

## Acceptance tests

- [x] With timings on, compose, the act path, a decision, a folder formation and a widget restyle each show a chip whose numbers match the server's reported durations within network time.
- [x] Off by default; the setting persists per browser; it never appears in exported or shared views unless on.
- [ ] Agent tool calls show their tool, duration and agent label on the affected card. (Partly: label and time only; the live event carries no tool or duration. See Log.)

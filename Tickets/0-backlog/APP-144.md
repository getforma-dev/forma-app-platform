## Why

APP-142 makes the united app a page on the canvas. Victor also wants that app to be a page in the ordinary sense: open it, read it, fill it in, and follow it, the way a person uses an HTML page. The canvas stays the board. The page is the other view of the same app.

## What changes

1. The member can open an app as a page at its own address. The address is a link that can be shared. APP-139 still owns the case where the recipient has no account yet.
2. The page is rendered by the trusted app renderer from the admitted definition, the same views and the same form. It is server-rendered. The model does not supply HTML, script, SQL, FMIR, or a grant.
3. Interaction is the page's own: scroll, fill the form, submit through the existing audited command route, and read a receipt on a governed number. Focus from APP-142 can open one part larger. Fan-out still returns the parts to the board.
4. A widget is not given this page. A widget stays a one-off on the board.

## Acceptance tests

- [ ] Opening an app's page address shows that app as one page, with its parts in the admitted order, and no other app's cards.
- [ ] The page HTML is produced by the trusted renderer. A generated definition cannot add a tag, a script, or a link that the renderer did not already allow.
- [ ] Submitting the form on the page uses the existing command route. A governed number on the page carries its receipt.
- [ ] The same app can still be fanned out to cards on the board. The page and the board show the same data.
- [ ] A widget has no app page.

## Verification

## Why

APP-142 is the app as a page on the canvas. Victor also wants that same app to be a page in the ordinary sense: a document you open, scroll, fill in, and submit. The canvas stays the board. This is the other view of the same saved work.

## What exists today

`GET /w/{app}/{work}` is the native app document for an authorized workspace member. A query string remains the uniform 404; filters and record selections travel in bounded, closed request bodies. Existing canvas and united-app headers offer **Open page**; the document links back to `/canvas#g-{work}`.

The November 1 follow-up reads every admitted part and its `default_layout`, including literal notes and each exact declared command form. Native HTML and live JSON retain the same row/column reading order. The renderer owns a finite layout and element vocabulary: definitions cannot add arbitrary HTML, scripts, styles or URLs. Unsupported query operations remain an explicit unavailable part; the renderer does not fabricate a result. Qualified source views run their admitted defaults on entry or restore valid saved parameters. Exact values and receipts remain attached to their released results.

Current-record forms use a native, CSRF-protected selector posting to the same document path. Form premises come from fresh authorized record detail and match the listing pin. Unsent fields, current record identity and same-key retries survive live updates; a removed selector no longer poisons subsequent refreshes. New enum fields reflect unambiguous unconditional initial-state rules while guarded rules and all backend command checks stay intact. A selected later enum value is retained by both native and refreshed forms.

The existing shared document at `/s/{share}` and connected-app placements use the same trusted ordered parts through a narrower read-only projection. They include notes, view-only form labels and released chart/table views, with no command fields, Ask context, selector or member links. Guest release checks remain in the sharing routes. APP-139/APP-154 still own recipient identity and sharing; this rendering work grants no new access.

The model does not render the page. The trusted renderer does. That rule stays.

## What changes

1. From the app on the board, or from the APP-142 page, the member opens the page. The address is `/w/{app}/{work}` for that saved work. No new path is invented. No query string is added.
2. The HTML is the admitted app, in declared order: its views and its form, as one document. The renderer is the existing work-page renderer, extended to show those parts as the page rather than only the legacy run form. A generated definition cannot insert a tag, a script, an inline style, or a URL the renderer did not already allow.
3. The member scrolls, fills the form, and submits. The submit is the existing audited command route, the same one the canvas card uses. A governed number carries its receipt. A refused command leaves the page in place and shows the refusal. It does not navigate away.
4. The page offers a way back to the canvas for this work (`/canvas#g-{work}`), and the canvas offers a way to this page. Focus may open one part larger. Fan-out still belongs to APP-142 and still returns the parts to the board. The page and the board read the same saved work. A record added on one is visible on the other after refresh. For the requested connected experience, the open document must also consume the existing reauthorized live updates for this exact work, preserve unsent form values and receipts, and recover after reconnect.
5. A member opens `/w/{app}/{work}`; a private share hands its recipient the existing `/s/{share}` address. Both render the admitted app through the trusted document vocabulary. APP-139/APP-154 own the account-only recipient flow and view-only grants. A member who cannot read the work still gets the uniform 404.
6. A widget has no `/w/...` page. Opening a widget stays on the board.

## What this ticket does not do

- It does not let the model, or the member, supply the HTML.
- It does not add a public unauthenticated page.
- It does not move filters into the URL.

- [ ] An owner commit reaches the open recipient document without manual reload through the existing reauthorized event path; measure latency and verify reconnect/revocation behavior. It must not overwrite an unsent form.

For an enum initialized to one permitted value by the admitted create command, the form must not offer other initial values that the command will refuse. Guarded initial rules need deliberate handling; backend authorization must remain unchanged.

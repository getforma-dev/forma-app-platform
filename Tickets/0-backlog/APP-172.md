## Why

The beta database `genuisyntheticfoundation-database…` is PostgreSQL 16.13, available, with automatic minor upgrades off and no pending maintenance. Local dev and the current pins use the same 16.13 image, `postgres@sha256:5d143123fdf80462d1778cd4f24b9f7ca13c87174bca19141fb194c5a1ebca59`. A historical local migration run used a different image and reported 16.15. That run did not change RDS.

On 2026-11-03 RDS in `us-east-1` offers PostgreSQL 16.3, 16.4, and 16.9 through 16.15. **16.15** is the newest 16 minor. The image promotion cannot apply it: that path may change only task images, services, and the stop schedule. The stack policy also denies replacing or deleting the database. Upgrading inside the current release would be the change that can break beta.

## What changes

Start only after [promotion run 41711515143](https://github.com/getforma-dev/forma-app-platform/actions/runs/41711515143) on `c192a90` has sealed, or after the release that supersedes it has sealed, and after `ops.promotion.maintenance inspect` shows no active lease.

1. Re-read the RDS PostgreSQL 16 versions in `us-east-1`. Upgrade the GenUI instance to 16.15 if it is still the newest offered minor. If RDS then offers a newer 16 minor, stop and record that version before changing the engine. Do not move to PostgreSQL 17 in this ticket.
2. Take a database snapshot and keep the existing identifier, endpoint, storage, encryption, deletion protection, backup retention, and parameter group. The change set must be an in-place engine modification. Refuse it if CloudFormation would replace or delete the database.
3. Leave automatic minor upgrades off. Apply the explicit version. Do not let an unattended minor upgrade move the instance again.
4. After the instance is available on the new version, move every current 16.13 pin to one inspected image digest whose `postgres --version` is that same minor. The copies today are `compose.dev.yaml`, `app/src/storage/qualification.rs`, `app/operator/check_image.py`, `app/operator/test_operator.py`, `app/qualification/local_harness.py`, `app/runtime/qualify_tenant_schema.py`, `app/runtime/qualify_migration.py`, `app/runtime/test_admission_operator.py`, and `evidence/APP-007/restore-local-sql/qualify.py`. Update the CDK engine in `infra/src/stack.ts` to the same version. Do not reuse the historical 16.15 digest `ca0bd484…` unless inspection shows it is the intended image.
5. Re-run the migration qualification and the tenant-schema qualification on that digest. A local dev volume created on 16.13 can start on a later 16 minor. Do not reset it as part of the pin change.
6. Leave the GateWasm staging database alone. It is still 16.13 with automatic minor upgrades on, and it is not the beta app database.

## Acceptance tests

- [ ] The GenUI database is available on the chosen 16 minor, with the same identifier and endpoint, automatic minor upgrades off, and the pre-upgrade snapshot retained.
- [ ] The reviewed change set modified the engine in place and did not replace or delete the database. Application data, roles, and schema version survived.
- [ ] Local dev, the qualification harnesses, and the CDK engine all name that same minor, and the migration and tenant-schema qualifications passed on the new image digest.

The application schema is unchanged. Rollback of the engine is a restore from the snapshot taken in this ticket, not a task-image rollback. Do not start the upgrade while a promotion lease is held.

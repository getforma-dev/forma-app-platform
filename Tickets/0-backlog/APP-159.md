## Why

A chart renderer cannot make a meal tracker calculate spending. The qualified query path currently runs one source input and explicitly refuses records inputs (`storage/queries.rs::view_query`). The existing expense ledger aggregates a listing labeled “live records, last 200”; it is not a general full-collection records query. Reusing that display without its scope warning would make plausible but incorrect monthly totals.

## What changes

Implement a small registered records-query subset over one authorized collection of the exact saved work: typed filters, count, exact money sum, grouping by an admitted enum/text/date field, monthly date buckets, stable sort and bounded top-N. Derived budget progress/remaining amount uses the same aggregate and a declared typed scalar denominator. Record the denominator and origin in the receipt; a preset or explicit parameter must be labeled as such. If the app exposes a budget **Set** control, it must submit an actual admitted command to a budget record of this same work. Resolve that scalar through an authorized server read and include the budget record/version and snapshot identity in the result receipt; do not present a browser-only setting as saved data. This bounded scalar input does not authorize multi-collection joins, arbitrary formulas or a general reporting engine.

Reuse the APP-020/021 typed grammar and exact arithmetic contracts, APP-023's committed record snapshot/provenance and APP-024's admission/deadline/release controls. APP-158 supplies the canonical filters and APP-025 their epochs. These remain owning dependencies, not completed work inferred from a polished reference app. Implement and qualify only the declared subset; leave unsupported operations visibly unavailable. Split before selection if the registered subset cannot fit a reviewable five-day change.

Select the record snapshot under current member or guest authority, bind the query to the admitted publication/work/policy, then fence again at release. A receipt identifies the actual record snapshot, actor/delegation, operator/definition versions, canonical parameters, covered population and exact result. Reuse the confined execution boundary; no model SQL or new general database access is permitted. Record aggregate reads are not commands and cannot mutate data.

List pagination and top-N display must not change a claimed complete filtered total. Qualify an explicit collection/input bound. If the exact requested population exceeds it, refuse the complete result; partial results require an admitted partial-scope contract and prominent coverage metadata. Never turn a timeout, unavailable input, denied read or missing budget into a zero. ADR-014's five-second authority lease remains independent of these potentially slower data queries.

## Acceptance tests

- [ ] Admission accepts only the registered same-collection operators and compatible fields, currency/exponent, grouping and date/filter parameters. Unknown, mixed-currency, cross-work, unbounded and hostile expressions are refused before execution. The implementation has no app, restaurant, tenant or fixture-name branch.
- [ ] Save synthetic November meals of 1,250 and 750 USD minor units at Cafe A and 2,500 at Cafe B through actual commands, plus excluded October 31 and December 1 rows. For `[2026-11-01, 2026-12-01)`, obtain 4,500 minor units, count 3, Cafe B then Cafe A with 2,500/2,000, and the correct monthly bucket. A declared 10,000-minor-unit budget yields 45 percent used and 5,500 remaining, with denominator provenance. Re-derive every result from its captured snapshot and parameters.
- [ ] A preset or parameter budget is visibly identified as such. If **Set** is offered, an actual budget-record command persists the change across reload, stale/refused/uncertain submissions retain normal command semantics, and its authorized record/version appears in the refreshed receipt. A concurrent budget edit cannot combine one denominator with another version's receipt; read-only guests receive no Set action.
- [ ] Qualify typed dates separately from timestamps: half-open boundary rows, explicit timezone treatment where supported, stable tied rankings, negative/large values where admitted, null policy, exact minor-unit arithmetic and safe transport. Zero/missing denominators produce a defined unavailable ratio, not infinity or fabricated zero; genuine empty aggregates follow their declared semantics.
- [ ] Use more matching records than one displayed list page and more groups than top-N. A complete sum/count still covers the full authorized filtered population; limits and omitted groups are disclosed. Exceeding the admitted input/resource budget returns the declared refusal or explicitly permitted partial state, never an unlabeled “monthly total.”
- [ ] A concurrent command and delayed query cannot combine one snapshot's summary with another's rows under the same receipt. Canonical filters and snapshot identity are inspectable; late prior-filter/work/account results are discarded. Subsequent live refresh produces a new coherent result and receipt without replacing an unsent form.
- [ ] Actual member/guest authorization negatives, foreign receipt lookup, sponsor/source loss where applicable, publication drift and revocation during execution or cache release disclose no values. A guest receipt names the actual account/delegation, never an impersonated owner. Source queries, cached results and record aggregates cannot extend ADR-014's visible authority lease.
- [ ] Deadline, cancellation, queue/resource exhaustion and unreadable record input produce visible non-success states. Numeric charts retain exact table/receipt alternatives, and empty, partial, unavailable and denied states cannot masquerade as successful zero-valued dashboards.

## Verification

Retain the admitted definition, synthetic command outcomes, exact expected values, snapshot/receipt payloads, query bounds and negative/race evidence in `evidence/APP-159/` when implemented. Extend actual PostgreSQL/confinement/query campaigns, not only arithmetic unit tests. Use current registered check/campaign commands and record exact source/build/runtime identities. Independent Tier A review covers authority, record snapshot capture, confinement, cancellation and final result release. Browser assertions then compare the rendered values to those authoritative results; screenshots alone do not qualify computation.

## Migration and rollback

Version record input/operator and receipt encodings; retain old source-query and definition behavior. Any snapshot storage or database privilege change needs an additive migration and role qualification in this ticket. Disable the new query capability on rollback without replacing historical receipts, erasing commands or converting unavailable results to defaults. Existing record forms and source queries remain usable under their current contracts.

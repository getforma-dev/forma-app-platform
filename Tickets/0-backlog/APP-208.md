## Why

"Choose all that apply" is a plain poll shape. The grammar (`multi_enum`) is in edition `impl-2026-11-14.2` from APP-202 so that the edition is published once; this ticket makes it usable.

## What changes

Exactly ADR-020 §9: checkboxes in the canvas, record-page and SSR forms composing an ordered `multi_enum` value (none selected posts `null`); `records_list` cells joined by ", "; `record_ranking` over a `multi_enum` `group_field` counts a row once per selected value; `record_query::scalar_row` projects the field as joined text for the typed engine; the composer learns `multi_enum` for "choose all that apply". Files: `app/src/storage/record_query.rs`, then, after their owners' merges, the form files of APP-205, the engine files of APP-204 and the composer prompt of APP-207.

## Acceptance tests

- [x] A form with a `multi_enum` field shows one checkbox per declared value; a selection posts the values in declaration order and storage accepts it; no selection posts `null` and a non-nullable field refuses it; an out-of-order or duplicate value is refused by storage. (SSR tests for the record page, the canvas form and the document form; `commands::tests::form_checkbox_groups_compose_one_multi_enum_value_in_posted_order`; `storage::commands::tests::multi_select_values_are_an_ordered_subset_of_the_declared_values`; the record-components campaign's "APP-208 storage" and "APP-208 forms" checks.)
- [x] A `record_ranking` over the field counts each option once per row that selected it (a row selecting a and c adds one to each); a `records_list` shows "a, c"; a typed query view over the input runs with the field as text. (`test_record_engine.MultiSelect`, `test_record_query`, `record_query::tests::a_multi_select_projects_as_joined_text_and_is_rejudged`, `record_components::tests::a_multi_select_cell_joins_its_values`; the campaign's "APP-208 ranking", "APP-208 typed query" and "APP-208 x D7" checks.)
- [x] Guards, record filters, typed filters, keys, `matches` fields and list ordering over a `multi_enum` field are refused by both validators (tests), and the existing campaigns stay green. (Both validators' refusals are B0's, APP-202, unchanged here; the engines refuse the same shapes defensively, `test_record_engine.MultiSelect.test_a_set_is_never_an_order_a_filter_or_a_key`; the `participation`, `record-components` and `private-entries` campaigns ran green on this branch, `evidence/APP-208/`.)

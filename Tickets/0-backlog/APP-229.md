## Why

`admit_redemption` inserts every entitlement as `now()+interval '30 days'` (`app/migrations/0025_organization_roles.sql:243-244`). Sign-in requires `status='active' AND expires_at>clock_timestamp()` (`app/src/storage/sessions.rs:781`, `:816`), and so does every guest share the member sponsors (`app/src/storage/shared_access.rs:272-273`). The operator's `extend` reaches only unredeemed codes (`app/runtime/admission_operator.py:1303-1320`). The operator chain's kinds are a closed policy list (`0025:118-122`) and `append()` refuses an unlisted kind (`admission_operator.py:717-719`), so an audited extension is a migration.

## What changes

1. **Migration 0026:** `ALTER POLICY operator_chain` adds `entitlement.extended` and `member.erased` (APP-230 shares the migration); the schema-version checks move to 26; the catalog JSON and manifest follow. Nothing existing changes shape.
2. **`admission_operator.py`:** `OPERATOR_KINDS` gains both kinds; a new subcommand `extend-entitlement --organization <org> --until <RFC 3339 UTC> (--principal <id> | --all-active)`. In one transaction as `genui_owner` (`begin()`, `:692-702`): organization active and `FOR SHARE`, each target membership `FOR UPDATE` and `status='active'`, then `UPDATE genui.entitlements SET expires_at=greatest(expires_at,%s) WHERE organization_id=%s AND principal_id=%s AND status='active' AND expires_at<%s`, one `entitlement.extended` event per changed member (actor the member, outcome the new `expires_at`'s digest). Refusals before any write: `until_in_past`, `until_too_far` (more than 400 days ahead), `member_unknown`, `member_inactive`, `organization_inactive`, `kind_refused` below schema 26. A member already past `until` is reported `changed: false`, never lowered. No epoch advance. Revoked entitlements are untouched.
3. **`app/operator/overrides.json`:** the `admission-extend-entitlement` override; **`ops/promotion/admission.py`:** an `extend-entitlement` command with `--until` and `--principal` or `--all-active`, idle-state and identity checks, a receipt, and the task's log line in the output file.
4. **Runbook:** a short section after §5 with the command, the expected `{"organization_id": ..., "until": ..., "members": N, "changed": M, "unchanged": N-M, "membership_epochs": ...}` shape and the post-release-H run `--all-active --until 2027-02-15T00:00:00Z`.
5. **Not here:** entitlement length as plan data and the lapse warning on `/admin` and to the member (A19, with A13).

## Acceptance tests

- [ ] On a fixture at schema 26, `extend-entitlement --principal` moves one active member's `expires_at` later and appends exactly one `entitlement.extended` on the operator chain whose hash chain still verifies; a second run with an earlier `until` changes nothing and appends nothing.
- [ ] `--all-active` extends every active member in one transaction, including a lapsed-but-not-revoked member, who can sign in again and whose sponsored guest share answers again; revoked members and revoked entitlements are untouched.
- [ ] Refusals are proven before any write: `until` in the past, `until` more than 400 days ahead, an unknown or revoked member, a suspended organization, and schema 25 (`kind_refused`); each leaves the entitlements and the chain unchanged.
- [ ] The managed path works end to end on the dev stand: `admission.py extend-entitlement` composes the override, runs the task, writes the receipt and prints the result; the operator image's `check_image.py` admits the new override.
- [ ] Shipped in a reviewed schema release record (release H), with the bulk run's receipt for the trial organization recorded in the private trial folder.

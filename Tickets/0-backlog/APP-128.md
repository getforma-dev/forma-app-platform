## Why

The local stand was an `#[ignore]` test run as an 8-hour server: 281 lines of bash with pid files, four Python cookie proxies, a tmpfs Postgres removed by a destructor, a 600 s credentials file rewritten every minute, the asset manifest read once with no reload, fixed ports and one machine-wide state directory (inventory §A; every row of the root-cause table). A code change reseeded the database, a second checkout could not run, and proxies kept old code.

## What changes

1. **`genui-dev`** (`app/src/bin/genui-dev.rs`, `app/src/dev/`) behind cargo feature **`dev-stand`** (`required-features`), the `qualification-harness` pattern: the Dockerfile never enables it, so release builds contain none of it (ADR-007 D7.13). It calls `genui::product::routes` with the binary's pages, the real query engine, a local object store and the sealed parser when `just parser` built it. Lib changes under the feature only: `Settings::fixture` (loopback role pools, still verified TLS), `mint_session_for_tests` (persona sessions) and a 30-day credential lifetime for a `localhost` database (`config::DEV_LIFETIME`; production keeps 600 s), so nothing rewrites the credentials file.
2. **`compose.dev.yaml`**: PostgreSQL 16.13 (digest-pinned, the fixtures' image), one Compose project and named volume per checkout and profile, `genui.scope=dev` / `genui.profile` / `genui.checkout` labels, loopback port from the port base, healthcheck. The binary's idempotent bootstrap at every start: TLS material (per-checkout CA), roles, migrations and validated seed (no-ops when current), synthetic role passwords, password-only TCP; one-time operator setup per volume (marker table in the `postgres` database).
3. **Profiles.** `pitch`: Northstar, demo mode on, the 20-app library granted to Diego, Sarah and Priya (each with an authoring app), their example records and Diego's "Q3 board pack" folder, seeded once per volume. `clean`: Alex Rivera in the second fixture organization, **no library**, no records, demo off, only an authoring app (the app the composer drafts on; generation with no sources is refused today, see the log); `just dev clean seed-library` runs the audited operator `seed-library` + `grant-library-access` and builds the sources.
4. **Personas in process**: one loopback listener per persona; an axum layer sets that persona's session cookie; each browser its own session (8 per persona, a `genui_dev_client` cookie; cookie-less requests share the last one); sessions kept alive and re-minted when ended; on `clean`, `Clear-Site-Data: "storage"` once per database epoch. No Python proxies.
5. **Front end without a command**: process-compose runs `npm run dev` (one watcher per checkout, `.cache/dev/admin.lock`); the binary exits 75 when `admin/dist/manifest.json` changes and is restarted (rust-embed reads `admin/dist` from disk in debug builds, so no Rust rebuild).
6. **`process-compose.yaml`** (process-compose v1.124.0): `db` (Compose up; shutdown is `compose down`, which keeps the volume), `admin`, `server` (`scripts/dev/server.sh`: cargo build, then the binary; depends on db and admin healthy; readiness `/health/live`; restart on failure; a failed build waits for `just restart`).
7. **`scripts/dev/`**: `dev.sh` (`just dev [clean] [start|stop|reset|restart|status|logs|seed-library] [-d]`, replacing step 2's wrapper; refuses to start on ports another process holds, naming it), `env.sh` (instance identity: port base from `.env.dev`, 4000 in the main checkout, a free derived base from 4100 in a worktree, recorded in `.env.dev`), `admin.sh`, `server.sh` (`ANTHROPIC_API_KEY` from the clone's `.env` into the server process only).
8. Deleted: `app/scripts/dev_stand.sh`, `fresh_stand.sh`, `dev_stand_proxy.py`, `app/src/storage/dev_stand.rs` and the fixture's `refresh_credentials`; the catalog's `dev-stand` entry. `GUIDE.md` "Local dev stand" is a pointer; `just clean docker` keeps stopped dev instances' data volumes; workspace gets `rust-analyzer.cargo.features: ["dev-stand"]`.

## Acceptance tests

- [ ] A front-end edit is served on the next page load with no command.
- [ ] A Rust edit plus `just restart` keeps the data (no reseed).
- [ ] `just dev clean` shows no apps; `just dev clean seed-library` installs 20 (idempotent, audited).
- [ ] Two checkouts' instances run at once on different port bases.
- [ ] `just dev [clean] stop` leaves no container, only the named volume.
- [ ] fmt, clippy `-D warnings` with and without `dev-stand`, `cargo test --locked`, admin typecheck/build/test, board check.

## Migration and rollback

Stop stands started by the old scripts before merging (`app/scripts/dev_stand.sh stop`, `fresh_stand.sh stop` from the checkout that started them); after the merge the scripts are gone. Rollback: revert the commit (the old scripts and the stand test return).

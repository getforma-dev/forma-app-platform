## Why

Ten pitch commits, from APP-094 (efff3ed) to APP-120 (3c15417), changed `contracts/schema.json`, `schema.py`, `validate.py`, `test_contracts.py` and the README, and added `make_library.py` and the library fixtures, without a new contract edition. The lock was stale, so Contract qualification was red. ADR-002 makes a new edition a contract decision.

While classifying the changes, the edition found that one APP-113 definition rule ("create writing a governed enum field requires initial") refuses beta's stored Expense claims definition `sha256:d70710d3…d0de`. That definition was seeded at 0c3261b and never re-seeded. It is valid under edition impl-2026-10-29.3 and under Rust admission. Victor chose option A: the two APP-113 rules judge new content only.

## What changes

1. **Edition `impl-2026-10-31.4`.** Edition impl-2026-10-29.3 is retained byte for byte in `contracts/fixtures/impl-2026-10-29.3/` (5 files) and added to `RETAINED`, with lock sha `0e3024b1…9a50`. Editions impl-2026-10-29.2 and impl-2026-10-28.1 stay retained. The schema `$id` names the new edition.
2. **Authoring verdict.** `validate(entity, new_content=True)` and `validate_bundle(bundle, new_content=True)` add the two APP-113 rules: no duplicate `(field, from, to)` transition, and governed-field `initial`. The default stays the stored-document verdict, unchanged from impl-2026-10-29.3. `make_library.py` validates every library bundle as new content.
3. **Stored-data vector.** `contracts/fixtures/stored/expense-claims-d70710d3.json` is beta's Expense claims bundle as seeded, byte for byte (sha `446e5485…d059`, equal to the 0c3261b catalog's `fixture_sha256`). It validates under the stored verdict, is refused as new content, and Rust admission admits it.
4. **The lock now covers what the pitch ships:** the APP-107 shape amendment, `make_library.py` and the 21 library JSON files.
5. **Tests.**
   - Python: `EditionFourTests` covers retention of edition three, every library bundle against the catalog as new content, and the stored vector.
   - Rust: `admission::tests` (edition id, embedded retained and stored fixtures, a stored-definition admission test), the `managed_qualification` source bundle and validator pin, and the qualification image allowlist.
6. **README.** An edition section with the change table, the approvals, the trade-off and the gaps. The stale "13 bundles" claim is fixed: the library has 20 bundles, 6 of which use the amendment.

## Gaps to revisit

1. Rust admission does not enforce either authoring rule for new content, including composer-generated definitions. Decide whether to add an authoring mode there.
2. Beta's stored Expense claims revision could be superseded at a later window (option B), with Victor's word: a new revision and publication, then adoption. `seed-library` currently refuses on beta ("existing seed differs").
3. Composer-generated definitions on beta are unverified against the authoring rules. A read-only check on beta needs Victor's word.
4. The catalog's `edition` label (and `make_library.py` `EDITION`, `tenant_seed.py` `LIBRARY_EDITION`) still says `impl-2026-10-28.1`, although six library bundles use members that edition refuses.
5. The Contract qualification workflow does not run the library: `make_library.py --check` needs DuckDB, which `contracts/requirements.lock` lacks. It is a candidate for `just check` or CI.
6. The lock binds the library CSVs only through the digests inside their bundles.
7. The amendment and authoring rules have no `negative-vectors.json` entries. Rust parity rests on unit tests, not shared vectors, and the JavaScript verifier does not judge guards.

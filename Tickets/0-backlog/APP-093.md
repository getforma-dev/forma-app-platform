## Why

The core of the pitch: a member describes an app and sees it appear. The planner reuses what exists and the model fills only the gap.

## What changes

In the clone, a composer panel takes a description; the planner retrieves admitted modules from the vector index of published modules, adapts them where needed and asks the model (Vector Studio's path, key from a secret, never argv or logs) to generate only what is missing. Every component is labeled retrieved, adapted or generated. Model output is a typed definition and enters only through `app/src/admission/`; nothing generated is executed, rendered as markup or treated as a grant.

## Acceptance tests

- [ ] Describing an app produces a canvas of components, each visibly labeled retrieved, adapted or generated.
- [ ] A generated component reaches the canvas only after passing admission as a typed definition; a hostile or malformed model output is refused and shown as a refusal, never rendered.
- [ ] The model key is read from a secret; a log, argv and evidence scan finds no key.
- [ ] Retrieval returns only modules the session's tenant may use; a foreign tenant's module is never offered.

## Verification

Run the composer against a recorded set of descriptions and a hostile-output fixture; retain labels, admission outcomes and the key scan, sanitized.

## Migration and rollback

Additive in the clone; with the composer disabled the canvas shows only saved apps.

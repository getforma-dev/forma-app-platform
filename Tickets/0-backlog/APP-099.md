## Why

Victor, 2026-10-30: "we want to show integrations on MCP … which MCP would give us the most ROI." Forma is the integration with the most ROI. Exposed as an MCP server, Forma becomes the governed system of record that any agent can act through: Claude, OpenAI, Cursor, or a company's own agent. Every agent gets the same identity, permissions, receipts and audit as the canvas, and its actions show up live in front of the team. The pitch line is: "Your agents already talk. Forma is where their work becomes governed, shared, and visible." Slack follows as APP-100.

Any MCP client works. MCP is an open protocol, and a Streamable HTTP server is reachable from:
- Claude Code: `claude mcp add --transport http` with an `Authorization` header.
- Claude Desktop, through a remote-MCP bridge that adds the header.
- OpenAI's Responses API and Agents SDK: the hosted `mcp` tool with `server_url` and `headers`.
- Cursor, VS Code and Gemini CLI.

The one client difference is auth. The consumer connector UIs (claude.ai custom connectors, ChatGPT developer-mode connectors) expect OAuth 2.1 or no auth, while the developer clients accept a bearer header. The pitch uses bearer tokens (DS-48). OAuth is the proper fix.

## What changes

1. **Endpoint.** `POST /v1/mcp` is MCP Streamable HTTP: JSON-RPC 2.0 with `application/json` responses and no server-initiated stream.
   - It is stateless, keeps no `Mcp-Session-Id`, and answers `GET /v1/mcp` with 405.
   - It handles `initialize`, `notifications/initialized`, `ping`, `tools/list` and `tools/call`, at the current protocol version, accepting the previous one.
   - Limits: 64 KiB body, 120/token/hour. The long deadline applies (`http::uniform_with_many`, as for `/v1/act`), because `forma_compose_app` calls the composer.
   - Origin checking: a request carrying an `Origin` header that is not the deployment's own origin is refused (MCP's DNS-rebinding rule).
   - Cookies are ignored. Only the bearer authenticates, so a browser cannot ride a session into the endpoint (no CSRF).
   - Recommendation: hand-roll the JSON-RPC surface (about 300 lines, no new dependency under the locked, reviewed dependency set). The official `rmcp` crate is acceptable if it passes the dependency review.
2. **Agent tokens.**
   - A signed-in member mints a token from the canvas with "Connect an agent": `POST /v1/agent-tokens` (same-origin, session, label such as "Claude" or "OpenAI"). The raw token is shown once.
   - Tokens are stored as SHA-256 digests in `genui.agent_tokens`: organization, principal, label, created_at, last_used_at, revoked_at.
     - The table is created in migration 0009, under RLS and FORCE RLS like the other tenant tables.
   - A token becomes a `TrustedRequest` only through `storage::sessions`: a new constructor checks the digest, that the token is not revoked, the member's current epoch and the registry identity, exactly as for a session row. A revoked member, a bumped epoch or a revoked token makes every call a uniform `not found`.
   - The canvas lists connected agents and can revoke them: `DELETE /v1/agent-tokens/{id}`.
   - Tokens carry no wider rights than the member. The tools call the same storage operations as the canvas routes.
3. **Tools.** The set is closed and typed. Each tool declares MCP `annotations`: `readOnlyHint` on reads, `destructiveHint: false` with a confirm step on writes. Each result has `content` (short text for the model) and `structuredContent`, plus a canvas deep link `https://…/w/{app}/{work}`.
   - `forma_list_apps`: the library and the member's saved and shared work, with ids, titles, origin labels and whether the data is synthetic.
   - `forma_run_view(app_id, work_id, view?, parameters?)`: rows (at most 50) with types, the **receipt id** and the synthetic label. These are the same query engine and receipts as the canvas (I3).
   - `forma_compose_app(description)`: the composer (`POST /v1/compose` internals). It returns the retrieved, adapted or generated label and the canvas link. The `app.placed` event puts the app on the member's open canvas live.
   - `forma_draft_record(app_hint, values, approver_name?)` and `forma_draft_decision(target_hint, decision: approve|reject, note?)`:
     - These are the action path's resolver (`actions::resolve`) and dry run (`Data::dry_run_command`), fed by the agent's structured arguments instead of the router model's parse. The values are typed under the published schema (I5).
     - The result is a draft (`draft_id`, display values, approver, target), not a write.
   - `forma_commit(draft_id)`: commits the held draft through the audited command route with its server-minted idempotency key (I4), then shares it to the resolved approver. It returns the record and the canvas link. The `record.committed` event updates the teammates' canvases live.
     - Drafts live in memory per member: 10-minute TTL, single use (DS-49).
     - The agent cannot commit values it did not draft, and the commit re-judges everything.
   - `forma_list_pending`: records awaiting the member's decision.
   - `forma_share(app_id, work_id, member_name)`: the existing share route's operation.
4. **Canvas.**
   - A "Connect an agent" panel offers mint, copy-once, list and revoke, with copyable setup snippets for Claude Code and OpenAI (URL plus header placeholder, never a live token in a snippet).
   - Records and apps changed through MCP show an "via Claude" / "via OpenAI" chip, taken from the token's label recorded in the audit event's actor detail.
5. **Rehearsal client.** `app/scripts/mcp_openai_smoke.py` uses the OpenAI Responses API `mcp` tool against a local or beta server. The key is read from the gitignored `.env` (`OPENAI_API_KEY`) and never printed. A Claude Code `claude mcp add` line goes in `docs/pitch/SCENARIOS.md`.
6. **Pitch scenario** (added to `docs/pitch/SCENARIOS.md`):
   - Diego, in Claude: "Log my $86 Nobu dinner and send it to Sarah." Claude drafts, Diego says yes, and Claude commits.
   - Sarah's canvas shows the claim arrive live, with a "via Claude" chip.
   - Sarah, in an OpenAI agent: "What's waiting for me? Approve the Nobu dinner."
   - Diego's canvas flips to approved live, "via OpenAI".
   - Two vendors act on one governed record, with receipts and audit.

## Acceptance tests

- [x] `tools/list` returns exactly the seven tools with JSON Schemas and annotations; `initialize` negotiates the protocol version; unknown methods return JSON-RPC errors; `GET` returns 405.
- [ ] Without a token, with a malformed, revoked or foreign-organization token, or for a member whose epoch was bumped, every call answers the same uniform refusal with no timing or content difference observable in the response (I1, I2).
- [x] A member's token cannot list, run, draft, commit or share anything the same member could not do on the canvas; a foreign tenant's app id is a uniform not found.
- [x] `forma_run_view` returns the same rows and receipt id as the canvas for the same view and parameters.
- [x] `forma_draft_record` → `forma_commit` files one audited record, idempotent under a repeated `forma_commit`; an expired, reused or other member's `draft_id` is refused; a hostile `values` payload (extra fields, wrong types, a status other than the starting state, SQL or markup in text) is typed, refused or stored as inert text, never executed.
- [x] A commit through MCP emits `record.committed` and the teammate's canvas updates live (the existing events campaign, driven by MCP).
- [x] Origin check: a request with a foreign `Origin` is refused; a request with a valid bearer and a session cookie but no bearer is refused.
- [x] A log, argv and evidence scan finds no raw agent token, no Anthropic or OpenAI key (I6).
- [ ] Real cross-vendor smoke: Claude Code and the OpenAI Responses API each list tools and complete the pitch scenario against the local stand; decisions and latencies recorded, no tokens.

## Verification

Unit tests for the JSON-RPC surface and each tool's refusal order; `storage::mcp_campaign` (Docker) for the two-member story end to end over real rows with timings and the isolation and hostile cases; the OpenAI and Claude Code smokes against the local stand. Infra test asserts the route behind the ALB and no new public path beyond `/v1/mcp` and `/v1/agent-tokens`.

## Migration and rollback

Migration 0009 adds `genui.agent_tokens` (additive; pins and SOURCES updated). With the route disabled or every token revoked, the canvas is unchanged.

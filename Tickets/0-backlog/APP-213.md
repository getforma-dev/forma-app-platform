## Why

The Release C authorization review (branch `release/c-participation` at `3bd4319b`) found one MAJOR and one residual risk:

- **MAJOR-1.** A `one_per_creator` create that replaces the creator's existing entry (ADR-020 §5.4) composes fresh, in `storage/commands.rs` (`commit`) and `storage/actions.rs` (`dry_run_command`) alike. Every field the create does not write resets to its `initial` value or null. In the composer's homework app (`composer/prompt.rs`, `plain_words::homework`) `submissions` is `own` with `one_per_creator: ["task"]`, `submit` is a contributor create writing `task, answer`, and `review` is a `reviewer_only` update writing `score`. A student submits, Victor scores it 9, the student submits the same task again: the score is gone from every current-revision read, through every commit path (form, canvas, Slack, MCP). The same holds for an `initial` status enum a reviewer moved by transition. The campaign covered resubmit-then-score, not score-then-resubmit.
- **Residual.** Nothing refused a `matches` key list the model left shared (`visibility: "own"` omitted on the expected entries). The key would then be readable to every contributor through any view or typed query over that input. The prompt said `own` and the example was `own`; only the real-model smoke and the campaign asserted it.

## What changes

**1. A replace may not undo another command's work (ADR-020 §17.43).** In both `commit` and `dry_run_command`, after the key match and the `Unchanged` check, every field of the published schema that is neither in the create's `writable_fields` nor in its `set_now` is compared between the matched entry's stored values and the composed values (`storage::commands::untouched_fields_differ`; "differ" is the typed equality `Unchanged` uses, field by field). If any differs, the command is refused with the existing `Error::Denied` path and nothing is written; the fresh form's record id is never created. What the member sees is what any value a declared rule refuses shows: the record page's `Notice::Refused` and the canvas's "The command was refused: a value is not one this command accepts. Nothing was changed."; JSON callers the uniform 404; the action path `could_not_draft`; MCP not-found; Slack its refusal. No new wire code, no contract or edition change (a member-worded 422 code would be a new problem code and a new edition, not opened here; `requirement_not_met` is not borrowed, its one meaning is a failing `requires` guard).
- Before a reviewer acts, the non-writable fields still equal their initial or null on both sides, so a resubmission replaces as today.
- The quiz's `responses`, whose create writes every field, are never locked. Attendance's `checked_at` is `set_now` and never locks.
- The reviewer's own update on the entry is unchanged (it targets the record id).

**2. Generated answer keys are private (ADR-020 §17.44).** `composer::plan::require_private_keys`, judged in `plan_generated` after `require_bindable`: generated content whose `record_summary`/`record_ranking` `matches` `key_input` binds (by `storage::composer_bindings`' rule, through the shared `bound_schema`) a record schema without `visibility: "own"` is refused with the composer's own code `shared_matches_key`. Its static hint: "A matches key_input must be an `own` list that only reviewers file (visibility: own with a reviewer_only create), so contributors never read the expected values." The prompt's NEVER line names the shape. Admission of stored content and the library and adapted paths are unchanged.

Files: `app/src/storage/commands.rs` (`untouched_fields_differ`, the commit's guard, the unit test), `app/src/storage/actions.rs` (the dry run's guard), `app/src/composer/plan.rs` (`bound_schema`, `require_private_keys`), `app/src/composer/prompt.rs` (the hint, the NEVER line, their tests), `app/src/composer/tests.rs` (the planner test), `app/src/storage/composer_qualification.rs` (the homework phase's APP-213 check), ADR-020 §17, `evidence/APP-213/`.

## Acceptance tests

- [x] In the composed homework app a resubmission **before** the reviewer's score replaces the entry (revision 2 of the first record id) and the dry run names it (`DryRun::Valid { replaces: Some(first) }`); a resubmission **after** the score is refused by the dry run and the commit alike (`Err(Error::Denied)`) with nothing written: the entry keeps revision 3, its answer `final` and its score 9, the fresh form's id is never created, and the reviewer can still rescore it (revision 4). (`just campaign composer`, the APP-213 check.)
- [x] The rule, in isolation: before a reviewer acts no field outside the create's reach differs; once the reviewer's update wrote `score` the same resubmission differs; a create that writes every field never differs; a `set_now` stamp re-stamped later never differs; stored bytes that do not decode are `Unavailable`, never a judgment (`storage::commands::tests::a_replace_differs_exactly_when_a_field_outside_the_creates_reach_moved`).
- [x] The worked participation example (its `expected` list `own`) plans; the same content with `visibility` dropped from `expected` still admits as stored content and is refused as generated content with `shared_matches_key` and a hint that differs from the unknown one; content with no `matches` measure has no key to judge (`composer::tests::a_generated_matches_key_must_be_an_own_list`; the prompt's NEVER line and hint table tests).
- [x] Each guard (the rule, the commit's call, the dry run's call, the planner's rule), broken alone, is caught by a named test or the composer campaign and restored byte-identically ([evidence](../../evidence/APP-213/break-and-restore-2026-11-14.md)).
- [ ] The integration into `release/c-participation` keeps the `composer`, `participation` and `private-entries` campaigns green on the merged branch, and Victor sees a scored submission stay scored after a student resubmits on his Nov 25–26 build day.

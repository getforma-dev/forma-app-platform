## Why

APP-196 gave a schema release's migration a reserved exit code, 4, for "commit outcome unknown". The restore command refuses that code, as it refuses a signal, an expired observation and an unresolved start. For all of them the runbook's fix-forward path ([Promote to beta](../../docs/pitch/BETA-PROMOTION.md#schema-releases), "Failure and recovery") follows the same steps:
- prove the migration task stopped;
- read the schema version with the candidate operator image's documented `verify-catalog` and `verify-catalog-baseline` overrides;
- act on the outcome.

No command can run that read in this state:
- `ops/promotion/admission.py` runs operator-task overrides, but `reviewed_state` refuses while a deployment holds the lock. It also refuses when the stack differs from the live parameters, and both are true here.
- Its `admission-stats` override proves only the image's latest catalog, so it cannot tell `from` from neither.
- `infra/scripts/window_requests.py operator-task` composes the request, but its runner, `ops/beta/run-step.sh`, is fenced after the cutover.

So today the read is a separately reviewed manual operator action, at the moment beta is down.

**This ticket does not gate APP-194.** The [APP-196 recheck](../../evidence/APP-196/review-2026-11-14.md) accepted the gap for release B, for these reasons:
- the cases that need the read are rare;
- waiting is safe, because the lock is held, the services are stopped and the snapshot is kept;
- a new AWS-calling command would need its own Tier A review inside release B's window.

## What changes

The change is one operator command: a reviewed wrapper over the existing composition of the `verify-catalog` and `verify-catalog-baseline` tasks.

**When it is allowed.** Only while a schema release holds the lock with its services stopped. It refuses in every other state, and it refuses the workflow roles and a GitHub Actions environment.

**What it does:**
1. It binds the exact reviewed state hash.
2. It proves the migration task STOPPED, then runs the two reads:
   - `verify-catalog`, for the `to` version;
   - `verify-catalog-baseline` with `--version` set to the release's `from` version.
3. It records its proof in immutable receipts and prints the outcome: `to`, `from` or neither.

**What it never changes:** the lock, the phase, the journal or the stack. It starts no other task.

## Acceptance tests

- [ ] It runs only as a non-workflow operator identity, bound to the exact reviewed state hash. It runs only while an `executing` schema release holds the lock with both services stopped. Every other state, role or environment refuses before any AWS call. Tests cover each refusal.
- [ ] It proves the migration task STOPPED before any read:
  - DescribeTasks of the start receipt's task ARN, where `MISSING` counts as stopped;
  - or, for an intent, ListTasks by `startedBy` `forma-schema-release` with both desired statuses, then DescribeTasks of each.

  A task that is not stopped refuses before any RunTask, and the command never stops a task. Tests cover each case.
- [ ] Its only mutations are two RunTask calls of the stack's `OperatorTaskDefinition`, with the documented overrides (`verify-catalog`, and `verify-catalog-baseline` with `--version` set to the packet's `from`). The requests are composed by `window_requests.run_task_request`, with deterministic client tokens, and each is journaled in its own receipts. Other than those receipts, the canonical state, the lock, the phase and the journal are byte-identical before and after. An unknown RunTask outcome is recorded and never retried. A test asserts the exact requests and the unchanged state.
- [ ] It waits a bounded time for each task to stop, records the stopped observations, exit codes and printed JSON as immutable receipts, and reports `to`, `from` or `neither`, with a refusal for anything it cannot classify. Tests cover each outcome. Mutations of each guard are seen failing a test.
- [ ] An independent Tier A review finds no blocker, and the runbook's fix-forward read step names the command in place of the manual action.

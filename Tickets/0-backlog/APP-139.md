## Why

Reviewers will not accept a canvas that already holds apps and records. The link has to admit a new member into an empty organization, show an empty canvas, and carry one real workflow: describe an app, add one record, share it. A second person signs in with their own invite during the same three minutes and sees that work. A stranger gets the uniform 404. The entry is an invite, not a public signup.

## What changes

Confirm, then remove, the empty-organization publish limit. `Workspace::composer_context` chooses an authoring app the member already owns, with `edit_definition` and `run` (`app/src/storage/composer.rs`, `choose_authoring`). The clean dev stand creates that shell with `create-app` (`app/src/dev/db.rs`). An invitation does not. A new member therefore gets `no_authoring_app` (`app/src/boxes/routes.rs`). The first slice gives that member one authoring shell through the existing publish path. No new permission model, no server-side layout store, and no second demo mode.

Then a short guide on the empty canvas names the next moves. It does not read `GENUI_DEMO_MODE` and it does not use a rehearsed sentence. The app appears through compose and admission. The record is the existing command path. The share is the existing share path.

The seeded two-window rehearsal stays in APP-096, APP-098, APP-105, and APP-110. It is not this trial.

## Acceptance tests

- [ ] One invite admits a new member into an organization with no library apps, no placed cards, and no records. The canvas opens empty.
- [ ] That member can describe one app and see it appear through the existing composer and admission path, including when they owned no app at sign-in.
- [ ] That member adds one record through the existing command path. A shown number carries its receipt. Nothing uses `GENUI_DEMO_MODE` or a rehearsed sentence.
- [ ] A second person, with their own invite into the same organization, signs in during the same three minutes and sees the shared work under their own grants. A stranger gets the uniform 404.
- [ ] A three-minute script and a sanitized click log or recording exist. They contain no credential, invite token, or model key.

## Verification

Read `choose_authoring` and the invite path before changing publish. The first slice is one branch and one fresh-browser check on a worktree port. Ports 4001–4003 and 4010 stay untouched. Review depth for the authoring shell is Tier A (ADR-010 §4): it grants `edit_definition` and `run` to the new member on an app they own.

## Migration and rollback

No migration. The authoring shell is one app row and its grants for that member. Removing the slice stops creating the shell; apps already created stay. The guide is canvas copy and can be removed without a data change.

## Why

Victor, 2026-10-30: "That's why we have the side pane. So anything we can get with the / we need to map to it being done without it?" The rule is that slash commands are accelerators, never the only path: every command has a click path, but not every click needs a command. People who have never used a command line must be able to do everything by pointing.

## What changes

1. **Audit.** List every slash command and keyboard shortcut in `app/admin/src/canvas/` (slash.ts registrations, the widget, note and folder commands, focus and unite keys, toolbar actions) next to its click path: library pane, card header or ⋯ menu, toolbar menu, folder card buttons, or the intent bar in plain words.
2. **Fill every gap** with a visible control in the most natural place.
3. **The `?` sheet** shows both paths per action ("Unite: card menu → Unite · U").
4. **Plain words.** Any command whose action can be said as a sentence also works as a sentence in the intent bar.

## Acceptance tests

- [ ] An audit table in this ticket's Log, covering every command and shortcut with its click path. No gaps remain.
- [ ] A first-time user can do the demo script without typing a slash command or a shortcut (browser walk).
- [ ] The `?` sheet lists both paths.

## Why

Victor builds his class apps from sentences. Without prompt text, an example and the lifted reference refusal, the composer cannot emit any Release C member ([APP-193 finding](../../evidence/APP-193/finding-2026-11-14.md), G7).

## What changes

In builder B5's files (`app/src/composer/prompt.rs`, `plan.rs`, `tests.rs`, `app/src/storage/composer_qualification.rs`):
- The generation prompt states the new grammar members and when to write them (ADR-020 §10), names the edition `impl-2026-11-14.2`, and carries one general worked example, `participation_example()` (items, responses, expected; no classroom words).
- `require_usable_fields` allows a `reference` field whose `target_input` is a `records` input of the same content and still refuses any other reference; `multi_enum` stays refused in generated content until APP-208 lands.
- A hint for the new admission refusals (`participation_rule`): static text, never a value of the refused document.

## Acceptance tests

- [x] `participation_example()` admits through `plan_generated`, publishes, and the prompt tests assert the grammar lines, the "never" rules (no `now` outside `requires`, no `one_per_creator` on a shared list, no `set_now` on a writable field, no declared transition for the owner's close) and that nothing about permissions appears in the examples.
- [x] The composer campaign (stub model) turns the acceptance sentence "a quiz where each student answers once per question and can change it until the question closes after 30 seconds, with a leaderboard on my screen" into an admitted definition with an `own` responses list keyed by the item reference, `requires` with `via` and `now`, `set_now` on the reviewer-only post and reopen, a `countdown`, and a ranking by creator with `matches`; the ids are general.
- [x] The generated definition runs end to end on the merged Release C branch: post, answer, replace, refuse after close, the ranking on the owner's page (the `participation` campaign of APP-203 accepts the composer's output as its second app).
- [x] One real-model smoke (`smoke-composer`) with the acceptance sentence is run once and recorded with its output in `evidence/APP-207/`; a miss is fixed in the prompt and re-run once.

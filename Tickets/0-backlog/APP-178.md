## Why

APP-154's shared-app reads enforce these conditions in SQL, but no test shows them:
- organization shutdown through `o.status='active'` (`storage/shared_access.rs:260`);
- an expired invitation through `s.expires_at>clock_timestamp()` (`:264`).
Nothing tests that two independent grants to the same account survive the loss of one. A broken predicate would pass every current check.

## What changes

1. Add checks to the `live-sharing` campaign (`storage::shared_campaign`):
   - a sharer's organization set to a non-active status, after which the guest's query, document release and links all refuse;
   - an invitation past its expiry, which cannot be accepted;
   - two independent grants to the same account, where revoking one leaves the other working.
2. Each check must fail when its predicate is removed (a recorded mutation).

## Acceptance tests

- [ ] Organization shutdown denies the guest's query, final document release and connected links, including when it races a slow query, and restoring the organization restores access.
- [ ] An expired invitation cannot be accepted, and the refusal does not reveal whether the recipient has an account.
- [ ] Two overlapping independent grants: revoking one leaves the other's access exactly intact.
- [ ] Removing each predicate makes its check fail; an independent review finds no blocker.

## Verification

`just campaign live-sharing` with the new checks; a mutation per predicate; independent review.

## Migration and rollback

Test-only unless a check finds a defect; any fix carries its own migration and rollback.

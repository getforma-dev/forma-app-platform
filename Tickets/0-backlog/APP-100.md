## Why

Victor, 2026-10-30: "Then lets do slack." The manager in the expense story lives in Slack, not on the canvas. The approval should reach Sarah where she already works: she clicks Approve in a DM, and Diego's canvas flips live. This turns Forma from a place you visit into the governed layer under the tools a team already uses.

Prior work studied: `side-projects/forma-agents` (fork of Inkeep's agents, `packages/agents-work-apps/src/slack/`) and `side-projects/slack-api-project` (a NestJS reader of users and channels). The fork is Elastic License 2.0 with Supplemental Terms that forbid using it for an "Agent Builder". **No code is copied.** Only the protocol patterns are reimplemented here in axum:
- signature check on the raw body;
- ack within 3 s and finish the work in the background;
- one interactivity endpoint dispatching on `action_id`;
- a short-lived link token plus a mapping table from the Slack user to the member;
- `response_url` with `replace_original` so a button cannot be pressed twice.

## What changes

1. **Endpoints.** `POST /v1/slack/commands` and `POST /v1/slack/interactivity`, plus `POST /v1/slack/events` (only `url_verification` and `app_mention`).
   - Every request is verified before parsing. The check:
     - reads the raw body (16 KiB cap);
     - requires `X-Slack-Request-Timestamp` within 300 s;
     - compares `v0=hex(HMAC-SHA256(signing_secret, "v0:{ts}:{body}"))` in constant time;
     - answers a failure with a uniform 401 and nothing logged but a counter.
   - Handlers ack within 3 s (an empty 200 or an ephemeral "Working…") and finish in `tokio::spawn`. Results go to the request's `response_url` or to `chat.postMessage`.
   - The Slack Web API client is `reqwest` against `https://slack.com/api/*` with the bot token from the secret. The token never appears in argv, a log or evidence.
2. **Linking a Slack user to a member** (migration 0010, `genui.slack_links`: organization, principal, team_id, slack_user_id, linked_at, revoked_at; RLS and FORCE RLS; unique on (team_id, slack_user_id)).
   - `/forma link` replies ephemerally with a URL to `/slack/link?t=…`. The `t` is a 10-minute HMAC-signed token over team, Slack user and nonce.
   - A signed-in member opens it and confirms. The row is written for that member's organization.
   - A Slack request becomes a `TrustedRequest` only through `storage::sessions`: a new constructor checks the link row, the member's current epoch and the registry identity, as APP-099 does for agent tokens.
   - An unlinked Slack user gets only a link prompt. The Slack user id alone never confers anything (I1, I2).
3. **Flows.**
   - **`/forma <utterance>`.** The action path (`POST /v1/act` internals, rehearsed parser inside the demo organization) runs as the linked member.
     - A `create` or `decide` answers with an ephemeral confirmation: values, approver, and **Confirm** / **Cancel** buttons. The draft is held in memory as in APP-099 (DS-49).
     - Confirm commits through the audited command route with the server key and shares to the approver (I4). It then replaces the ephemeral message with "Filed, sent to Sarah", plus a canvas link.
     - `open` ("what's waiting for me") answers with the pending list, each item carrying Approve / Reject.
     - `place` answers with a canvas link.
   - **Approver DM.**
     - When a record is committed whose approver is linked, the bot DMs the approver (`conversations.open` + `chat.postMessage`). The message is a section with the claim (amount, merchant, date, note, who filed it) and **Approve** / **Reject** buttons. The button `value` is the record id; the record is re-judged on click.
     - The trigger is the event hub's `record.committed` from any origin: canvas, MCP or Slack.
   - **Button click.**
     - The click is judged as the clicking member: link → TrustedRequest → `decide` through the command route.
     - The message is replaced through `response_url` with "Approved by Sarah · 2:14 PM" (no buttons).
     - The filer gets a DM "Your Nobu dinner ($86.00) was approved by Sarah".
     - Canvases update live through the existing events.
     - A click by anyone but a member allowed to decide is refused with an ephemeral notice.
   - **Origin chip.** A record decided or filed in Slack carries a "via Slack" chip on the canvas (the audit actor detail, as APP-099's "via Claude").
4. **Install.**
   - The pitch uses a single workspace (DS-50). Victor creates the app from the manifest and installs it to his workspace. The bot token (`xoxb-…`) and signing secret go into `SlackApp` (Secrets Manager, KMS, injected only as `SLACK_BOT_TOKEN` / `SLACK_SIGNING_SECRET`) and the local `.env`.
   - Victor puts the values there himself. The agent never sees them.
   - The proper fix is OAuth v2 install per workspace with an encrypted per-team token.
5. **Docs.** `docs/pitch/slack-app-manifest.json` (scopes `commands, chat:write, im:write, users:read, users:read.email`; slash command `/forma`; interactivity URL) and `docs/pitch/SLACK-SETUP.md` (the create, install, secrets and link steps). A Slack act goes into `docs/pitch/SCENARIOS.md`.

## Acceptance tests

- [x] A request with a bad, missing or stale signature (or a replayed body with a new timestamp) is refused before parsing; `url_verification` echoes the challenge only on a valid signature.
- [x] Every handler acks under 3 s with the model stubbed slow (10 s); results arrive by `response_url`.
- [x] Linking: an expired, tampered or reused link token is refused; a link binds the signed-in member's organization only; an unlinked or revoked Slack user, or a member with a bumped epoch, can do nothing but get a link prompt.
- [x] `/forma` file → Confirm files exactly one audited record (a double Confirm is idempotent) and DMs the linked approver with Approve / Reject.
- [x] Approve in Slack decides the record as the clicker through the command route; the message loses its buttons; the filer is notified; both canvases update live. A click by a non-approver, or on an already-decided record, is refused without changing it.
- [x] A hostile utterance or button `value` (foreign record id, another tenant's id, markup) is refused or rendered inert; Slack text is escaped (`&`, `<`, `>`) in every message the bot posts.
- [x] A log, argv and evidence scan finds no bot token, signing secret or link token (I6).
- [ ] Live rehearsal in Victor's workspace: the Slack act of `docs/pitch/SCENARIOS.md` end to end with latencies recorded.

## Why

A reviewer must control exactly what ships, while saved work retains its meaning and current access. This ticket delivers: implement explicit work-version adoption and rollback.

## What changes

New work current publication, existing work pinned; visible meaning/schema compatibility, compare-and-set and audit, incompatible migration blocked until separately approved deterministic plan; rollback never undoes records or revives access.

Keep this a reviewable slice: L means approximately 3–5 focused days. Re-estimate before selection and split the ticket if it exceeds five focused days. The estimate is a planning bound, not a delivery date.

Scope excludes production deployment and real customer data; this is a synthetic qualification. Upstream framework/auth changes remain with the FormaStack team.

## Acceptance tests

- [ ] New work binds the current permitted publication while existing work remains pinned until an authorized explicit adoption action.
- [ ] Adoption shows calculation/schema meaning changes and atomically compares source pin/version; racing adoption or incompatible schema returns a visible conflict/refusal.
- [ ] Rollback selects only a compatible still-permitted app revision and never reverses committed record changes or restores revoked access.

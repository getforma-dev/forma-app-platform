## Why

The APP-073 reviews ([schema-0003](../../evidence/APP-073/schema-0003/independent-review.md), [admission](../../evidence/APP-073/admission/independent-review.md), [provider](../../evidence/APP-073/provider/independent-review.md)) left minors, declined items, documentation routes to the coordinator and one owner decision open. [ADR-010](../../docs/architecture/ADR-010-NOV-2-MVP-CUT.md) deferred them past the 2026-11-02 MVP so the beta could go live on a handful of operator-provisioned, SES-verified invitations; they are owed before invitations go beyond the demo principals and before PH02's migration 0008.

## What changes

1. **At-rest custody (provider review M2; ADR-003 amendment 2026-10-29, for Victor's veto):** Victor confirms the Phase 1 default (0600 file in a 0700 directory on the FileVault-encrypted operator Mac, outside synced folders, synthetic beta invitations only) or vetoes it; then move the capability into AWS Secrets Manager under the tenant key with bounded readers and lifetime, and correct the README accordingly.
2. **Provider-operation audit (provider review m8 and audit recommendation; APP-073 Log "owed before APP-076's first live invitation", deferred by ADR-010):** amend ADR-007 D7.8 with the operator kinds `provider.invitation.created`, `provider.invitation.reconciled` and `provider.invitation.revoked` (`outcome_digest` over the canonical `{{operation, state_before, state, remote_invitation_id, detail}}`), widen the operator RESTRICTIVE policy in the next migration, and write one event per transition in `admission_operator.py`; `verify` covers them.
3. **Provider nits (provider review n1, n2, n5, n6, n7, n8):** stand-in coverage of gatewasm's non-atomic create and 0/3/6/9-digit timestamps; a pinned provider host allowlist so a misconfigured `GENUI_PROVIDER_URL` never receives the management key; persist the 404 `not_pending` detail; enforce one tenant per organization in the operator path; document the `create_remote` lock order; a positive control in check 24. Documented limits: provider/code expiry divergence (m4), `reconcile` runs only when the operator runs it, the 300 s clock-skew assumption.
4. **Admission review documentation routes (m4, m5, m6, nits, implementation-choice notes):** renumber the pre-0004 references in ADR-007 D7.7/D7.12 and the plan, and the "migration 0006" strings in `admission_operator.py`; record in D7.19 that Phase 1 trial extension is code extension plus reissue (no entitlement extension) or add `entitlement.extended`; record the plan Task 5 seed disposition; note in D7.3 that 0004's `entitlements.entitlement_id` grant is read by APP-009; `gssencmode="disable"` and the Unix-socket refusal in `runtime.migrate`; read `--provider-email` from a non-argv channel defined with APP-074; one sentence in D7.8 or D7.19 that `backfill` writes no audit event; the APP-074 reconciler note (a never-sent `create` still `pending` plus its `revoke` means "do not create").
5. **Schema-0003 review observations:** record m7's disposition (runner review m3 runtime half, record-only) and the four observations (pending-admission bound now m3(a); context digest rests on the flow record; `replayed` returns the epoch only; compromised workspace connection inherent to ADR-004) in the APP-073 README as accepted limits.
6. **Operator source and work seeding audit (APP-012 storage open question 1; APP-012 review m9):** `admission_operator.py register-source-revision` and `create-bound-work` write no audit event because ADR-007 D7.8's operator kinds name none. Amend D7.8 with operator kinds for them (for example `source_revision.registered` and `work.seeded`, `outcome_digest` over the canonical command record), widen the operator RESTRICTIVE policy in the same migration as item 2, write one event per command, and have `verify` cover them. Until then the retained JSON output of each command is the record (`evidence/APP-012/README.md` D1).

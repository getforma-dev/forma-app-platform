## Why

The canonical expiry is one pinned value, `RENEWED_EXPIRY = '2026-12-16T08:00:00Z'` (`ops/promotion/expiry_renewal.py:35`), consumed by the next release minus 18 hours (`ops/promotion/runner.py:226-227`). The December ledger month is pinned in `ops/promotion/month_renewal.py:29` (`MONTH = '2026-12'`), which refuses any other month (`:69`) and refuses once the month has begun (`:80`). A window may reach at most 32 days past its reservation (`infra/scripts/preflight.py:87`, `:363`, `:579`), so a release executed before the current stop (by Dec 10 02:00Z after release G) reaches Jan 11 at most. January needs its own reconciled ledger month before any release whose window reaches into it (`preflight.py:428-432`). The ADR-019 amendment's ceilings table ends at "December 1–16", and the AWS Budget template says "118 for December" (`ops/monitoring/alarms.json:44-49`).

## What changes

1. **Pins:** `RENEWED_EXPIRY = '2027-01-16T08:00:00Z'` (the next release's stop reads 2027-01-15T14:00Z); `MONTH = '2027-01'`; `TRIAL_CEILING_CENTS` to January's figures (about 12000 / 15800); `december_projection` renamed to a month projection; both docstrings rewritten (no "release B", no purge). A re-pin, not a `--month` argument: the one-reviewed-value pattern stays.
2. **The bound (if Victor takes Q2's recommendation):** `max_expiry` 32 → 45 days for the always-on plan (`preflight.py:87`), the message at `:363`, and ADR-019 amendment 2 recording why (one renewal release instead of two). Otherwise this ticket plans two renewal releases (the first to about Jan 10).
3. **Tests:** `ops/promotion/test_expiry_renewal.py` (`:18`, `:22`, `:62`, `:71`, `:112-113`, `:124`, `:129`, `:141`, `:161-164`), `ops/promotion/test_month_renewal.py` (`:34`, `:55`, `:72`, `:83`, `:90`, `:103`, `:111`, `:155`, `:158`), `infra/test/preflight_test.py:448`.
4. **ADR-019 amendment 2:** two ceiling rows, December (whole month, about $175 GenUI / $213 project by the model) and January 1–15 (about $120 / $158); the caps stay 21000 / 24800 cents; the sentence "the December ceiling ... needs no code change" superseded. The AWS Budget parameter stays 248 through December and becomes about 160 on Jan 1 (amount only; A7).
5. **Runbook §2 gains the January procedure**, in the order the code enforces, all within 24 hours of the merge: `reconcile observe/apply` (December, owned by reconcile once begun) → `month_renewal` for `2027-01` with an assessment bound to the post-apply `ledger_sha256` (rationale; 0 / 1500 / 3800 / 0 cents) → `expiry_renewal` plan and apply (expect `after_expiry 2027-01-16T08:00:00Z`, `next_release_expiry 2027-01-15T14:00:00Z`, caps 21000/24800, `cost_by_month` for `2026-12` and `2027-01` under them) → enable promotion, merge release H, approve only if the packet's stop reads 2027-01-15T14:00:00Z; `--revert` if the merge slips. With the 45-day bound the release window is **Dec 2 to Dec 9** (from Dec 1 14:00Z; 24 hours before the Dec 11 02:00Z stop).
6. **The merges cost no release:** the pins and tests change no runtime path (`beta-promote.yml` `runtime_changed`) and promotion stays paused until release H.

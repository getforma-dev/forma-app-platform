## Why

Notice v1 (`app/src/auth/notice.rs:19-26`) promises that "this workspace's data is deleted after the test, by December 14, 2026" and names feedback@getforma.dev for data requests. Victor decided the opposite on 2026-11-15: everyone stays on a free plan unless they ask to be deleted. A member consents to exactly one version (`genui.member_consents`, written only by `admit_redemption`, migration 0023; 0025:281-282), and nothing re-asks an existing member (sign-in never reads the table, `storage/sessions.rs:781`), so the new terms must be live before anyone but Victor redeems a code. The text is general platform text; the test refuses cohort words (`notice.rs:53-55`).

## What changes

1. **`app/src/auth/notice.rs`:** `NOTICE_VERSION = 2`; `NOTICE_PARAGRAPHS` becomes the approved v2 text (the plan's §3 block, after Victor's approval); the module test pins version 2, the new "Your data" and "After a trial period" paragraphs word for word, privacy@getforma.dev, the MCP and allowance sentences, and keeps the cohort-word refusal. The title and checkbox label are unchanged. The invitation page and `/notice` (APP-223) render from this one source, so no other code changes.
2. **ADR-008 amendment (the charter):** a dated "Continuation" amendment records decision 1, that the "End of the test" purge is replaced by deletion on request (APP-230), what deletion covers and how fast it is honoured, and notice v2 verbatim beside v1. Design history is not rewritten.
3. **Documents that quote v1 or the purge:** the class guide's code email paragraph (§4, rewritten from v2 as the guide instructs), `docs/operations/TRIAL-RUNBOOK.md` §10 and §11.4 (retitled from the end-of-trial purge to deletion on request, pointing at APP-230; the purge commands stay documented as the tool they are), `docs/planning/TRIAL-25-READINESS.md`'s "by Dec 14" row, and `docs/README.md`'s descriptions. `ops/promotion/expiry_renewal.py`'s docstring mention of the purge is APP-228's.
4. **Pre-v2 members:** Victor's written acceptance of v2 for his own accounts (the Nov 1 account and, if redeemed before this release, the build account) is recorded as an operator note in the private approvals file with the release record. No code re-asks a member; the sign-in consent prompt is a later primitive (plan §4.3 item 15).
5. **No migration, no contract edition.** `NOTICE_VERSION` is a constant stored on each new reservation and consent; existing rows keep version 1.

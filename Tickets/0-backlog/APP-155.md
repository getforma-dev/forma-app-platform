## Why

Unite already gathers the same card nodes into an app frame, and the member document and guest page render its admitted parts. The result still exposes the repeated headings, borders and tools of separate canvas cards. Victor's expense-app references clarify the intended use: one app header, purposeful sections, an obvious next action and consistent content whether embedded on the canvas or opened at its URL. This is a presentation improvement over the current saved-work identity, not a new app store, app copy or runtime.

## What changes

Define and implement a small shared app presentation contract: app header and description, ordered sections and component placement, consistent typography/spacing, and a primary-action area. Keep builder/canvas editing controls distinct from normal app-use controls. Existing titles, literal notes and qualified components supply the content. Do not add invented totals, behavior or a generic executable page language to make a reference screen look finished.

Preserve exact trusted organization, `(app_id, work_id)`, publication/digest, component IDs, records and bindings across the united canvas, member `/w` page and authorized `/s` projection. Standalone navigation does not instantiate or copy a work. Guest rendering remains view only: command controls are absent or clearly unavailable under current guest policy; the same visual design does not imply identical authority.

Use the admitted `default_layout` as the baseline. Specify bounded presentation roles and their compatibility rules before extending the definition contract. Definitions without new optional presentation metadata retain a deterministic usable rendering; all existing views remain reachable. Unknown versions/keys, duplicate or missing component references, excessive nesting and executable markup/style/URLs refuse admission. Existing data/view `links` are not repurposed as UI navigation. An action area is absent unless a valid action from APP-156 is available; it is never an inert pretend button. APP-157 owns persistent appearance tokens, APP-158/159 record views and aggregates, and APP-160 the complete reference-app qualification.

Retain Focus and explicit Fan out. App-use mode must not show editing handles on every part, but a member can still deliberately inspect/focus a component or enter editing mode. Moving between presentations must preserve authorized receipt details, form drafts, selection and scroll where applicable. Mobile reading order follows the admitted section/layout order; the app remains usable without dragging the canvas.

This is a narrow app-presentation slice over the existing renderers. It does not replace APP-032's full schema roadmap, APP-033's general editor or APP-034's general semantic diff/undo work. It does not detach components into widgets, add arbitrary HTML/CSS/JavaScript, introduce another router or iframe runtime, redesign the four-pane library, or implement sleep/wake. Split before selection if the final contract/rendering scope exceeds five focused days.

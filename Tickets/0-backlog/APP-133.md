## Why

There is no deploy history: eight beta activations on 2026-10-30/31 left their digests in the other clone's private directory and their facts scattered over ticket logs, with zero tags (inventory §C; ADR-013 Context). `release.json` existed (APP-127) without a fixed schema, so a rollback window could not be composed from it. The module boundaries of the monolith were described only in ADR-013.

## What changes

1. **`release.json` schema** (`ops/beta/release.py`, stdlib): `schema_version`, `window_id`, `supersedes_window_id`, `candidate_sha`, `branch`, `tag`, `built_at_utc`, `images.{service,qualification,operator}.{repository, local, local_id, local_size_bytes, tag, digest, size_bytes}`, `parser_manifest_sha256`, `stack.{name, template_sha256, task_definition, task_definition_revision, rollback_task_definition}`, `database_version`, `migrations.{snapshot, migrated}`, `operator_tasks[]`, `approvals[]` (`{step, at_utc, approvals_md_line}`: a reference to the line in `$PRIV/approvals.md`), `created/pushed/executed/activation_requested/activated/updated_at_utc`, `verified.{at_utc, origin, live, canvas, mcp, slack}`, `git_tag`, `releases_row`. `release.py check` validates; `row`, `append`, `tag` derive the public facts.
2. **Written by the steps**: `new` (init, with the database version from the candidate's migrations manifest and the local image record), `push` (digests and ECR sizes; **refuses local images whose ids are not the ones `just images` qualified**), `synth` (template sha256), `execute` (stack and task definitions), `snapshot`, every operator task (`run-step.sh`: label, run, exit code; a clean `migrate` marks the migration), every approval (`lib.sh record_approval`), `activate`, `verify`.
3. **`just images`** ends with `ops/beta/image_record.py`: `.cache/images/<sha7>/build.json` (ids, sizes, times) and the parser manifests of the service and operator images compared (guest, host, source binding equal; install paths may differ); a difference fails the build.
4. **`just deploy activate`**: after the approved activation, waits for `/health/live` 200 (public origin, no AWS API), records the activation, appends the non-secret row to **`docs/pitch/RELEASES.md`**, creates the annotated tag **`beta/<yyyymmdd>-<sha7>`** on the candidate and pushes it to `origin`, and prints the commit command for the row. Not healthy in time: no row, no tag; `--record-only --approved "…"` redoes just that part.
5. **`just deploy verify [<window>]`** reads the window's `release.json` (default: the newest activated), prints the release, runs the four checks (`verify.sh --json`) and records the results.
6. **`docs/pitch/RELEASES.md`**: the table, backfilled with TD:4 (APP-078 go-live, digests from its window record) and TD:5–TD:12 (the pitch windows, from the APP-096/100/105/113/117 logs; their digests were never tracked in Git).
7. **`docs/architecture/MODULE-MAP.md`** (D13.4): the four layers and each module's place, the rules, the measured release-code dependency table, the layer-2 cycles, the two named leaks with their state and owner (APP-097), and the edges the measurement found that D13.4's table does not name. `scripts/dev/deps.py` is the report-only walker (enforcement stays deferred to APP-097 as the ADR says; no `just check` step).
8. `just check` gains `py-ops`: `ops/beta/test_release.py` (the schema, and `deploy.sh` end to end in a synthetic repository with `aws`/`docker`/`curl` shims and its own bare `origin`).

## Acceptance tests

- [ ] `release.py check` accepts a record from `new` and refuses a malformed one; `--activated` requires the digests, the task definition revision, the activation time and an `activate` approval.
- [ ] `push` without `--approved` exits 3 with no AWS call; with it (shim), the three digests land in `release.json` and the approval is referenced by its line.
- [ ] `push` refuses a local image whose id differs from `build.json`.
- [ ] `activate` (shim) writes the row once (a `--record-only` rerun adds nothing), tags the candidate and pushes the tag to the synthetic origin; the row holds no full window id and no ARN.
- [ ] `verify` picks the newest activated window and records the four results.
- [ ] `just images <sha>` writes `build.json` with the parser manifests equal.
- [ ] The first real window through `just deploy` leaves `release.json`, the row and the tag (done when; needs Victor's word per step, ADR-013 step H).

Windows made before this commit have no `release.json` in the new schema: none exist under `$PRIV/windows/` except `_pre-adr-012/` (history, untouched). Rollback: revert the commit; `RELEASES.md` stays as history.

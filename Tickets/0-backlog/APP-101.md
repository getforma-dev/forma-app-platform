## Why

Victor, 2026-10-30: "do we want to have prebuilt apps, that can be modified and transForm-a based on user intent? So for all it would be default, but can change on the fly."

Today every compose waits on a model call. The Haiku router takes about 1 s and the app lands about 1.3 s after typing; generation takes about 5.7 s. The campaign's 273 ms and 694 ms figures were measured with a loopback model stub. "Adapted" only renames the title and description.

The canvas the pitch borrows from switched instantly. The fix is to pick the prebuilt app without a model call, show it at once with its defaults, and let the model reshape it in the background with a typed, admitted transform.

## What changes

1. **Instant pick (target ≤ 50 ms server time, no model call).**
   - A local matcher scores the request against each library app's routing metadata already in `catalog.json`:
     - `routing.description`, `intent_examples`, `negative_examples` and `capabilities`;
     - the title;
     - the input field ids.
   - Scoring: normalized tokens with simple stemming and a small synonym table. A negative example match vetoes the app.
   - A confident pick opens the app at once with defaults, labeled `retrieved`. A near-tie or no hit falls back to the router model, today's path.
   - The matcher replaces `plan::demo_route` and runs in every organization. It is a real router, not a demo shortcut.
   - A vector index is recorded as the scale path in APP-098: hundreds of team-published apps.
2. **Live transform (target ≤ 1.5 s after the pick, in the background).**
   - After the instant pick, if the request says more than the app's defaults, the fast model turns the rest into a closed, typed **transform**:
     - a filter (`field op value`, ops from the engine's qualified set);
     - a time window;
     - group-by or aggregate;
     - visible columns (project);
     - sort and limit;
     - presentation (table, bar, line, or number card, where the canvas supports it);
     - a title.
   - The server validates every field id against the app's input contract. The transform becomes a new revision of the member's own copy through `admit_definition` (I5), labeled `adapted`, and the views run with receipts (I3).
   - Unknown fields, unqualified operators or a refused admission keep the defaults. The canvas gets a neutral "kept the standard view" note, never an error.
3. **Canvas.**
   - The card lands at once.
   - A subtle "tailoring to your request…" state follows, then the card reshapes in place: the filter chip "Amount > $200", new columns, a chart.
   - The card is labeled "adapted to your request", with a one-click "back to standard" that reopens the default revision.
   - The transform arrives on the existing live channel (an `app.adapted` event, or the compose response's second phase), so a teammate viewing the shared work sees the reshape too.
4. **Rehearsed sentences.** Inside the demo organization the rehearsed sentences of `docs/pitch/SCENARIOS.md` map to fixed transforms without a model call (DS-53), the same pattern as `actions/rehearsed.rs`. Unrehearsed text uses the model.

## Acceptance tests

- [ ] For each library app, its `intent_examples` pick it instantly (no model call) and its `negative_examples` never do; measured p95 server time ≤ 50 ms.
- [ ] "Review expenses over $200" lands the expense app at once with defaults, then reshapes with a filter `amount > 200` whose rows and receipt match a direct run with that filter.
- [ ] A transform naming an unknown field, a foreign input, an unqualified operator, SQL or markup is refused and the defaults stay; nothing unadmitted reaches the canvas.
- [ ] "Back to standard" reopens the default revision; the adapted revision stays in the member's history.
- [ ] A teammate viewing the shared work sees the reshape live.
- [ ] With the model unavailable, the instant pick still works and the transform is skipped with the neutral note.

## Verification

Unit tests for the matcher against every catalog entry's examples and negatives, and for transform validation (hostile cases); a campaign extension (Docker, loopback model stub) timing pick → land → reshape; the real-Haiku transform smoke on the rehearsed and five unrehearsed sentences, decisions and latencies only.

## Migration and rollback

No migration. With the matcher's threshold set to never fire, the composer behaves as before.

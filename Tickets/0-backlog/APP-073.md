## Why

Invite-gated email/password signup proves identity, not permission to use GenUI. Victor needs codes he can issue while uninvited visitors cannot consume protected data or compute. This ticket supplies the persisted authority and owner workflow consumed by APP-009/074.

## What changes

Add tenant-bearing code, reservation/redemption and active-entitlement state under the established database roles. Provide an authenticated operator-only issuance/revoke/list command, with exact operator identity and least-privilege database authority recorded; it may use the approved operator channel rather than waiting for APP-066's general admin UI. Ordinary users cannot issue codes or modify destination, role, expiry, limits or usage counts. Internal admission operations accept trusted identity/context types; public request/session binding belongs to APP-009/074.

Codes have at least 128 bits of cryptographic entropy, a digest at rest, explicit finite expiry/redemption count and server-bound organization/least-privilege permissions. Show the secret only once. Owner-preprovisioned isolated trial organizations preserve the fAuth tenant boundary; unrelated trial users never share a default beta organization. Automatic tenant creation is outside this slice. Pre-signup validation does not consume a successful-redemption slot. Any reservation is finite, expiring and bound to the admission context; it does not authorize work. Recheck expiry, revocation and count at authenticated grant. The operator controls initial isolated-tenant invitations and explicit later member invitations; no generic public account registration is enabled.

Record the separate provider invitation's remote ID, intended email, explicit least-privilege identity role, destination and pending/confirmed operation state. FormaStack's proposed server-only invitation/PAR contract is still in progress and must be accepted through APP-006 before live use. Its current invite creation defaults to administrator and is not idempotent: operator provisioning must never omit the role or blindly repeat an unknown creation outcome. General tenant-management credentials stay in the approved operator channel, outside ordinary app signup. Any provider invitation capability needed by the backend is a separate encrypted/secret-store handoff with bounded readers/lifetime; GenUI codes themselves remain digest-only. APP-074 owns the actual accepted provider/browser exchange.

Keep this a reviewable L slice of approximately 3–5 focused days; split if implementation exceeds that scope. This ticket does not establish hosted signup, app sessions, provider calls or public beta readiness.

## Acceptance tests

- [ ] The admission migration and operator command issue, list and revoke bounded codes on the real role/tenant harness (local PostgreSQL 16.13 with verified TLS, the four fixed roles and the `genui_lock` fences); an ordinary application/member role and a forged operator identity are denied. Raw codes appear only at creation and are absent from storage, logs, URLs and retained evidence. The managed application of this migration and operator command on RDS moved verbatim to [APP-076](APP-076.md) by [ADR-005](../../docs/architecture/ADR-005-PHASE-1-SEQUENCING.md).
- [ ] A code's organization, permissions, expiry and entitlement are server-fixed. Foreign tenant, guessed identifiers, malformed/expired/revoked/exhausted codes and client-provided authority fields refuse without private-existence disclosure. A reserved code grants no workspace/data/job capability.
- [ ] Redemption, slot consumption, membership/entitlement creation and audit commit atomically. Two principals racing for the last slot yield exactly one admission; identical retry does not consume twice, and different-principal/changed-payload outcome retrieval refuses. Exercise rollback and restart on the actual database.
- [ ] Both redemption-versus-code-revocation orders and entitlement-use-versus-revocation orders preserve their declared transaction boundary; expiry or a late response cannot resurrect access. Code revocation and entitlement revocation have distinct tested effects.
- [ ] Safe code reissuance/explicit trial extension, reservation expiry/release and bounded list/audit output work without resetting another tenant's state. Record exact configured trial lifetime, pending reservation lifetime and finite limits before issuing usable codes.
- [ ] Operator provisioning requires the intended email and explicit least-privilege provider role, records the remote invitation ID and protects any separate provider capability through the approved secret channel. Ordinary app/signup roles cannot obtain tenant-management credentials; omitted roles, capability disclosure and legacy raw-token email delivery refuse pending a safe provider contract.
- [ ] Unknown remote create/revoke outcomes remain pending and are reconciled through the accepted provider inspection/operator procedure without duplicate blind creation. Expiry/revocation blocks new GenUI handoff immediately and propagates remote revocation with pending/confirmed evidence. A failed remote operation never restores local access. Prove that completed provider identity creation followed by locally expired/revoked/exhausted admission produces no membership/entitlement grant; only the GenUI transaction is atomic.

## Verification

Use APP-008's real role/tenant harness with Northstar/canary plus separate synthetic trial organizations. Exercise the actual operator/admission code and database constraints, concurrent transactions, restart and disclosure inspection. APP-009/074 must later prove these same primitives behind real sessions and public routes; local fixtures do not pass those integration checks. Retain exact commands, source/migration/operator identity, expected/actual outcomes, sanitized evidence and independent authorization/concurrency review in `evidence/APP-073/`.

Provider timeout/partial-outcome injection here qualifies GenUI's durable local operation state and refusals only; label simulated transport explicitly. Actual invite creation, mail suppression, provider revocation and PAR/browser behavior require the accepted APP-006 contract and APP-074's live campaign. This division keeps the local ledger independent without describing a mock as hosted identity evidence.

Source obligations: [ADR-003](../../docs/architecture/ADR-003-PUBLIC-BETA-ACCESS.md), Victor's October 28 beta direction, platform C01/C11/C15 and R15/R16. The frozen manual-provisioning design remains historical evidence.

## Migration and rollback

Version the admission schema. Disable issuance/redemption to recover safely while retaining membership, outcomes and audit. Never restore revoked entitlement, reuse a secret code or reset usage counts by rollback; reconcile unknown outcomes through the same scoped redemption identity.

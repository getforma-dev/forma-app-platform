## Why

Victor, 2026-10-31: "the user can run an alias … users need to be able to name apps, name aliases, name cards, put descriptions on them." Today names, addresses and aliases come only from the catalog (APP-120). Teams need to own them.

## What changes

1. **Two naming layers.**
   - **Organization labels**, changed by the app owner or an admin and visible to everyone who can open the app: the app's display name, its address (`/name`), description, kept aliases, and each card's display name and description.
     - Stored in a label table beside the definition (migration, RLS and FORCE RLS), written by an audited command (`app.labeled`).
     - Labels never change the governed definition, its revision or its receipts.
   - **Personal aliases**, changed by and visible to the member only: `/exp` → an app, `/q3` → a card. Stored per member, also audited.
2. **Rules.**
   - Addresses are unique per organization (case-insensitive). No address or alias may take a verb (`/card`, `/app` …) or another app's address.
   - A personal alias may shadow nothing; on a clash, the organization's address wins.
   - Renaming an address keeps the old one as an alias automatically.
   - Card names are labels; receipts and data are unchanged.
3. **Where.**
   - In the Library, a ✎ on app and card rows opens a small editor: name, address, aliases, description, and "my aliases".
   - On the canvas, double-clicking a card title renames it (org label if permitted, otherwise a personal label).
   - Commands `/rename <app|app.card> <new name>` and `/alias <shortcut> <app|app.card>`; both are verbs in the registry (Make group).
4. **Surfaces read labels.** The Library, the command and address registry (`GET /v1/commands`), card headers, the address chips (APP-120), MCP `forma_list_apps`, Slack, and the confirm card all show labels.

## Acceptance tests

- [ ] The owner renames Expenses → "Team spend" with address `/spend`. Every member sees it, `/expenses` and `/expense` still work as aliases, and an audit event is recorded. A non-owner cannot rename.
- [ ] A member creates the personal alias `/exp` → Expenses; it works for them and no one else. An alias that clashes with a verb or an organization address is refused.
- [ ] A card renamed "Q3 spend" shows that name everywhere, and its receipts are unchanged.
- [ ] The labels table is under RLS and FORCE RLS. A foreign organization's member gets the uniform 404 on every route that reads or writes labels.

## Verification

Unit and campaign tests (Docker); the schema qualifier; a browser walk on the dev stand.

## Migration and rollback

An additive migration (labels and aliases tables). Without labels, everything falls back to catalog names.

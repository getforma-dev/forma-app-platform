## Why

[ADR-010](../../docs/architecture/ADR-010-NOV-2-MVP-CUT.md) removed the one live PH01 proof that needs two verified identities racing one invitation slot on `https://beta.getforma.dev`, so the go-live trial could run on 2026-11-02 with one SES-verified recipient. The public-route layer adds no transaction beyond APP-073's, which is proven with observed lock waits, but the live repeat is still owed before the beta admits anyone beyond the demo principals.

## What changes

On the running beta, with two SES-verified recipients and a one-slot code issued by the operator, drive two concurrent redemptions through the public API, then an identical retry, then code revocation and entitlement revocation with a request in flight. Retain sanitized API requests and statuses, dispatch counters and database outcomes under `evidence/APP-083/`; no credential, code or full callback URL enters evidence. Coordinate the window so no schema operation runs.

## Acceptance tests

- [ ] Through the public API, concurrent last-slot redemption admits exactly one principal, an identical retry returns the prior result without consuming a second slot, and code or entitlement revocation is refused at the next request and at result delivery; a late response or existing session cannot revive expired/revoked entitlement. (Moved from APP-076 by ADR-010.)
- [ ] The two recipients, the one-slot code and every session created for the run are revoked afterwards; the operator `list` output shows one redemption, one `exhausted` code and the revocations on the operator chain, and `verify` passes.
- [ ] An independent review binds the receipts to the deployed image digest and the run time; the PH01 gate record's ADR-010 limitation for this item is closed by reference.

## Verification

Follow APP-076's verification rules (sanitized requests, dispatch/denial evidence, database outcomes, timings; ledger entry for the run if it reserves anything). Source obligations: ADR-003 ordered-delivery items 4 and 5; ADR-007 D7.1; S06; SR2, SR7.

## Migration and rollback

No schema change. Revoke the test identities and codes after the run; never reuse a consumed code.

## Why

A timed item needs a clock students can see that no browser clock decides, and the organizer needs a ranking by name with a score, projected from his own page, without any student's device receiving another student's data ([APP-193 finding](../../evidence/APP-193/finding-2026-11-14.md), G4 and G5; D7 unchanged).

## What changes

Exactly ADR-020 §4 and §7, in builder B2's files: `app/src/storage/record_components.rs`, `record_components_campaign.rs`, `app/src/query/record_components.rs`, `record_routes.rs`, `app/runtime/record_engine.py`, `test_record_engine.py`, `app/admin/src/record-components/*`.
- `countdown` is a record component: the engine takes the current record (the readable record with the highest commit sequence), `value` = `timestamp_field + offset_seconds` as a contract timestamp or null, `label` = the first text field, `closed` from `closed_when`; the route adds `server_time` to every record-components response; the client ticks from `server_time` and shows `m:ss`, "Closed" or "Nothing is open yet"; `is_record_kind` gains `countdown`.
- The capture adds `creator` to each dataset row and a `creators` label map (`directory::label`), captures every `key_input` an input's components name, and bumps the snapshot domain to `forma:record-components-snapshot:v2`; the engine groups by creator and computes `matches`; the wire projection accepts a timestamp `value` for `countdown` and the optional `label`/`closed`; the ranking limit is 50.

## Acceptance tests

- [ ] A countdown over a shared item list shows the newest item's label and counts down from `server_time` to `opened_at + 30`; it shows "Closed" after the reviewer's close (the `closed_when` guard) and "Nothing is open yet" with no readable item; a browser clock set an hour off changes nothing (the client uses `server_time`); the card re-runs on the work's `record.committed` hint.
- [ ] A ranking `group_by: "creator"` with a `matches` measure against an `own` key list filed by the owner: on the owner's and a reviewer's page it lists every contributor by display name with the count of their responses that match the key, sorted by score, truncated past 50 and saying so; on a contributor's page it lists only that contributor with their own score computed from zero visible key rows; a contributor with no display name shows the neutral label; the receipt's `snapshot` lists both inputs' revisions and validates against the receipt contract.
- [ ] Every D7 check fails with `authorization::BYPASS` set (the contributor's ranking then shows everyone); no contributor page receives a hint for another member's response (APP-191's delivery rule, re-asserted with the ranking card open); the result document carries labels and never principal ids; the `record-components`, `private-entries` and `live-sharing` campaigns stay green.
- [ ] An independent Tier A review (the D7 path, the receipt, the engine's bounds) finds no blocker; the review file is in `evidence/APP-204/`.

## Why

The defensive infra review of 2026-11-14 found the account blind and the edge open, two weeks before 25 remote students sign up:

- **H3.** No CloudTrail trail, no detector, no record beyond the 90-day console history. Whoever gets a key or a session leaves no durable trace, and nothing mails Victor when root is used, a key is created, a trail is stopped, a security group opens, a key is disabled, a bucket is exposed or a database is deleted or made public.
- **H2.** No WAF in front of the one Fargate task. A single host running `hey` against `GET /` or a compromised student session running `POST /v1/compose` (120 s model calls, Anthropic spend) is an outage for the class; the in-process limiter protects only sign-in, invite, callback, lookup and member writes.
- **M1.** The five alarms of `ops/monitoring/alarms.json` see an outage, not an attack: a 4xx storm, a CPU-pinned task, a bounce spike or a flooded fAuth host pass until the 5xx alarm, if at all.

Victor's decision on 2026-11-15 bounds the fix: free observability only (no GuardDuty, Security Hub, Config or Inspector), the WAF at about $7 a month, the M1 alarms at under a dollar, email alerts.

## What changes

Two standalone CloudFormation templates beside `alarms.json`, outside `infra/src`, so the deployment contract and promotion's infrastructure digest are untouched; the beta is reached only through parameters.

- **`ops/monitoring/security-events.json`** (about $0): a multi-region CloudTrail trail of management events (read and write, the free copy, log-file validation on; no data events, Insights or CloudWatch Logs delivery) into a private SSE-S3 bucket (public access blocked, TLS-only, versioned, write permission scoped by `aws:SourceArn` to the trail, Glacier Instant Retrieval at 30 days, expiry at 365, `DeletionPolicy: Retain`); an SNS email topic whose policy admits `events.amazonaws.com` of this account; eleven EventBridge rules with an `InputTransformer` that mails one plain line (who, what, when, from which address): root console sign-in; root mutating API call (`readOnly` false, not service-invoked); console sign-in failure; console sign-in without MFA by an IAM user or root; the fifteen IAM changes; `StopLogging`, `DeleteTrail`, `UpdateTrail`, `PutEventSelectors`; `AuthorizeSecurityGroupIngress`; `DisableKey`, `ScheduleKeyDeletion`; `PutBucketPolicy`, `PutBucketAcl` and the bucket and account public-access-block puts and deletes (the CloudTrail names, not the brief's `PutPublicAccessBlock`); `DeleteDBInstance`, `DeleteDBSnapshot`, `ModifyDBInstance` with `publiclyAccessible` true; a new active IAM Access Analyzer finding; and the free account-level `AWS::AccessAnalyzer::Analyzer`. No pattern names an operation `ops/promotion` calls (the test derives the pipeline's operations from its `aws.call` sites).
- **`ops/monitoring/waf.json`** (about $7.20): a REGIONAL `AWS::WAFv2::WebACL`, default Allow, metrics and sampled requests on, no logging and no managed rule groups (the paid upgrade path is in the template's `Metadata`): rule 1, 2000 requests per address per five minutes on any path; rule 2, 30 per address per five minutes scoped to the model-calling routes (`/v1/compose`, `/v1/ask`, `/v1/shape`, `/v1/act`, `/v1/mcp`, `/v1/widgets/customize`, `/v1/boxes/explain/…`, `/v1/boxes/<box>/apps`, `/brief`, `/ask`; Slack's callbacks left out); both Block with a `429`, a plain body and `Retry-After: 300`; the `WebACLAssociation` with the load balancer ARN as a parameter; two `BlockedRequests` alarms to the trial alarm topic (its ARN as a parameter). The limits are parameters with those defaults. Sizing: a member tab is tens of requests in five minutes; a guest tab on `/s/<share>` is about 250 (an access poll every 2 s, a document poll every 3 s), so 2000 holds for seven guest tabs behind one address; health checks never pass the web ACL.
- **`ops/monitoring/alarms.json`** gains the M1 alarms (eleven) and a `FauthInstanceId` parameter, every other parameter, the budget and its subscribers byte-identical: load-balancer 4xx ≥ 100 and target 4xx ≥ 600 in five minutes; service CPU ≥ 80% and memory ≥ 85% for ten minutes; database CPU ≥ 80% for ten minutes, connections ≥ 12 for ten minutes (the service's pools hold 8), freeable memory < 256 MiB for ten minutes; SES bounce rate ≥ 5% and complaint rate ≥ 0.1%; the fAuth host's status check (missing data breaching) and CPU ≥ 80% for ten minutes. All others `notBreaching`.
- **Tests:** `ops/promotion/test_monitoring_security.py` (new) and `test_monitoring_alarms.py` (updated) pin the resource sets, the patterns, the limits, the scope against the app's route constants and the client's poll cadences, the thresholds, and that `infra/src` owns none of these resources.
- **Runbook:** TRIAL-RUNBOOK §6 and §11.1 (the new parameter, the update of the live stack, sixteen alarms) and the new §11.7 (derived parameters, expected outputs, the email confirmation, roll-back, cost).

## Migration and rollback

No migration, no contract, no `infra/src` change. Roll back the WAF with `aws wafv2 disassociate-web-acl --resource-arn <load balancer ARN>` (a minute) and then `delete-stack forma-beta-waf`; roll back the security events with `delete-stack forma-security-events` (the bucket is retained with its logs); the M1 alarms by redeploying the previous `alarms.json` (the topic, the subscription and the budget survive). None of these changes the beta.

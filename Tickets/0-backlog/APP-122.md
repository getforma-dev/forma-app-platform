## Why

Victor, 2026-10-31: "/card <add the math for me> so it goes to the ai … what if we want to get insights on a card? do we go through the apps or the cards? … the ai is the main question here. It should be for all." Then: "how does the ai know that you want to shape the card … vs when you want to get data and context from it, vs … make me a new card based on this data … do we allow that?"

## Decision

Victor, 2026-10-31, superseding the first draft (one AI entry with four guessed outcomes): "I want a clear separation from changing the look and theme of the app and cards to answering questions about the data. I'm scared a question can be like 'where are all the red so and so' and the agent will make the card red. There are two jobs."

The rules are in [docs/pitch/CANVAS-RULES.md](../../docs/pitch/CANVAS-RULES.md) ("Two jobs: Ask and Shape").

- **Where you type decides the job; the AI never chooses.**
  - **Ask:** the Ask tab, or `?` in the bar. A read-only conversation, answered in text with receipts.
  - **Shape:** `/<card or widget> <words>`, `/shape …`, or the Shape field. Changes look or view through a preview and **Apply**. It never answers in words.
- **Structural, not prompt-based.** These are two endpoints with two output schemas.
  - Ask returns only `{text, receipts, references}`. It runs in a read-only transaction and has no write path.
  - Shape returns only a view spec, applied by the client after the user clicks.
- **The overlap is two explicit buttons.** **Make it a card** on an answer opens a Shape preview. **Ask about this** on a card opens a scoped Ask.
- **The rest of the bar is unchanged.**
  - Do: `/<app> <words>` runs the app's commands, behind a confirm card.
  - Forma: a plain sentence or `/forma` picks or builds an app; folder formation builds from files.
- **Layers.**
  - Records change only through Do or Forma, always confirmed.
  - Cards and widgets change only through Shape: *adapted*, with **Revert**.
  - Answers change nothing.
- **Ownership.**
  - A card made by Shape from an app's data belongs to that app, marked "made by you", and is personal until the owner adds it for everyone.
  - A card that combines two apps is Forma, deferred.

## Fable review (2026-10-31)

Victor asked for Fable's review before implementation. Its verdict: adopt the separation, because it is structural, not prompted. The changes below are applied to CANVAS-RULES.md.

- **The dot is the rule.**
  - `/<app> <words>` is Do; `/<app>.<card> <words>` is Shape.
  - `/<widget> <details>` stays Place, so `/weather Austin` is unchanged. Widgets shape through their Shape field (Restyle renamed: same mechanism, no new code).
- **A plain sentence stays Forma** (the demo's core flow). A question typed there stops at Forma's confirm card; the rules say so.
- **`?` has one meaning.**
  - Outside the bar, `?` focuses the bar with `? ` typed (it was the Shortcuts tab). This amends APP-120 §3.
  - Shortcuts stays reachable by `/shortcuts` and ⋯ → Shortcuts.
- **No per-card Shape field.** ⋯ → **Shape…** puts the card's address in the bar, like the address chip.
- **The *adapted* label becomes *shaped*.**
- **Receipts (I3):** a view spec may filter or hide records; it can never remove receipts.
- **A note's text is not a view.** Shaping a note changes only its look.
- **Ask, asked to change something,** answers with the address to type. It never switches jobs.
- **Demo cut:** the items below. **Make it a card**, personal cards, `@` mentions, removable chips, `/shape`, `/forma`, `/<folder> <words>` and pinned answers move to APP-123.

## What changes

1. **Ask.**
   - `POST /v1/ask` takes `{question, scope}` and returns only `{text, receipts, references}`. It runs inside a `READ ONLY` transaction with read-only queries over the scoped app's records.
   - The Ask tab has an input and a thread. `?` as the bar's first character opens it with the text.
   - Scope is the selected card if any, else the canvas, shown as a chip (not removable).
2. **Shape (cards).**
   - `POST /v1/shape` takes `{address, words}` and returns only a view spec: chart type, colors, columns, filters, computed fields over the app's records. This generalizes the APP-101 transform. The view spec can never drop receipts.
   - The client previews it, then **Apply** (replace) or **Add as new card**, then the *shaped* label and **Revert**.
   - Cards are session-only.
3. **Menu items.** ⋯ → **Ask about this** on cards, and ⋯ → **Shape…** on cards, app frames and widgets (puts `/shape <address> ` in the bar).
4. **Server-side schema rejection, both ways.** Ask rejects a view spec, and Shape rejects prose.
5. **`/shape <address> <words>` for every target** (Victor, 2026-10-31: "what if you want to reshape a widget? … there is no dot for an app").
   - **A card:** the same as the dot form.
   - **An app:** returns an app theme spec (colors, accent, density) applied across its cards. Each card keeps its own view. *Shaped*, with **Revert**.
   - **A widget:** returns the widget's style spec. This is the existing Restyle mechanism (APP-101), now reached through `/shape`. The widget field is renamed Shape.
   - Each target has its own closed schema; none carries prose or records.
6. **Small changes.**
   - `?` outside the bar focuses the bar with `? `.
   - Rename the widget field Restyle to Shape.
   - Add an Ask group to the Commands tab (`? <question>`).

The demo scope is everything above. Demo beat: `? where are the red invoices` returns a list with receipts. Then `/expenses.ledger only red invoices` → preview → **Add as new card**.

## Acceptance tests

- [ ] In Ask, "where are all the red invoices?" lists them with receipts. The canvas state and database row counts are identical before and after.
- [ ] The Ask endpoint cannot write: its transaction is read-only, and a forced write attempt fails.
- [ ] `/expenses.ledger highlight overdue in red` previews a highlighted ledger. Nothing changes until **Apply**; then it is labeled *shaped*, and **Revert** restores it. No records are written.
- [ ] Shape's response schema rejects a prose answer, and Ask's rejects a view spec (validated server-side).
- [ ] `/expenses.total by month` → **Add as new card** adds a computed card whose receipts trace to the source records. A view spec that would drop receipts is rejected.
- [ ] `/shape expenses dark green, compact` previews a theme on every Expenses card. **Apply** themes them all, each keeps its view, and **Revert** restores them.
- [ ] `/shape calculator make it a TI-84` restyles the calculator; `/weather Austin` still places a weather widget.
- [ ] A foreign organization gets the uniform 404 on the ask and shape routes.

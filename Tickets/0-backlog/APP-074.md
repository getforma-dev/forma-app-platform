## Why

The beta must be reachable from anywhere while protecting private data and paid work. This slice proves the real public registration/admission journey, including direct API bypass attempts; it is not a landing-page-only milestone.

## What changes

Serve a native public landing and invitation-entry surface at `https://beta.getforma.dev`. Only a valid invite permits signup. Integrate FormaStack-owned tenant-scoped invite-only email/password registration, real email-verification delivery and its approved recovery policy through the exact `https://beta.getforma.dev/auth/callback` code-flow handoff. An authenticated pre-access session permits only bound admission/logout; APP-073's current membership/entitlement gate must pass before workspace access. Valid codes choose their server-bound isolated organization before signup through a bounded opaque handoff, never a client tenant/role selector.

The proposed provider path is a backend `POST /t/{slug}/oauth/par` with the confidential provider `invite_token` plus PKCE fields; the browser receives only bounded `request_uri`, then final code/state. It remains unaccepted until APP-006 receives the actual source/hosted contract. Phase 1 uses operator-provisioned email/explicit-role-bound provider invites with proposed `delivery_mode: server_only`; no general tenant-management authority is added to the public app. Consume APP-073's remote ID/private handoff and operation state. The provider and GenUI databases are separate: completed identity signup still cannot admit a locally revoked, expired or exhausted code.

Add bounded signup/login/redemption requests, honest pending/invalid/expired/exhausted/rate-limited states and server-side IP, account/admission and global abuse limits. Keep codes, passwords and bearer credentials out of URLs/storage/telemetry. Operator code generation remains APP-073; general administration remains APP-066. LLM execution remains disabled until APP-043 passes. Full imports, generated applications and real-customer pilot readiness remain later work.

Keep this a reviewable L slice of approximately 3–5 focused days. Record exact limits and split if the hosted integration is larger; do not weaken acceptance to a local mock or static page.

## Acceptance tests

- [ ] With public HTTPS ingress, visitors in a second network can reach landing/invitation entry; only an invited recipient can reach and complete email/password registration. Exercise the exact callback, code admission and logout against the actual hosted fAuth contract in installed Chrome, native Safari and Firefox (the agreed matrix; WebKit does not substitute for Safari). Prove actual verification delivery and mailbox activation, using controlled synthetic inboxes if appropriate; do not invent delivery or a verification JWT claim. Record identity/tenant/client/TLS/build receipts and usable keyboard/focus/error states without exposing credentials.
- [ ] Missing/invalid GenUI codes cannot obtain a new signup handoff; missing/invalid/email-or-tenant-mismatched provider invitations cannot create an account through UI or direct registration calls. Anonymous, authenticated-but-unadmitted, expired/revoked and foreign-tenant principals are refused by actual protected page/API routes before storage disclosure or work dispatch. Probe query/import/generation/export/record route families directly; not-yet-implemented capabilities remain denied/unavailable and cannot be counted as an implemented feature. A registered account alone and a pre-access session never mint workspace grants. Operator-preprovisioned trial organizations remain isolated; member invites join only their named existing organization.
- [ ] Wrong/replayed state or code, expired pre-access state, changed destination, client-provided tenant/roles, cross-site redemption and leaked/replayed code outcomes refuse. Verify tenant scope remains server-bound and two unrelated trial organizations cannot read or consume one another's work.
- [ ] Concurrent last-slot redemption, identical retry, code/entitlement revocation and requests already waiting in admission preserve APP-073's real transaction results. A late response or existing session cannot revive expired/revoked entitlement. Record both race orders and restart/reopen behavior.
- [ ] Signup/login/redemption floods hit finite server-side IP and account/admission/global limits, including forged forwarded-IP headers and many account names. Request/body/deadline and pending-account/reservation bounds prevent unbounded work; denied requests invoke no model/provider. Inspect actual dispatch counters and safe logs, not just UI state.
- [ ] If a temporary `/32` infrastructure trial ran, it is over and HTTPS is restored to `0.0.0.0/0`; application denial works from the external test network. Disable signup/admission and exercise safe rollback without exposing a protected route or restoring a revoked entitlement. LLM calls remain disabled before APP-043.
- [ ] Against the accepted provider implementation, inspect actual backend PAR, browser navigation, email delivery, storage and logs: provider invitation capability is server-only/confidential, the explicit email/least-privilege role/destination stay bound, and the browser sees only bounded request URI and final code/state. Detect a deliberately exposed raw invite token or management credential. The old raw-token email URL and implicit administrator role are not accepted defaults.
- [ ] Exercise provider create/revoke timeout and retry, remote revocation propagation, pending reconciliation, and signup completion after local code expiry/revocation/exhaustion. No unknown remote outcome causes blind duplicate invite creation, fabricated rollback success or a GenUI grant; retain the partial identity outcome and reconcile it through the accepted operator/provider procedure.

## Verification

Retain real API requests/statuses with secrets removed, backend dispatch/denial evidence, paired isolated organizations, database outcomes, hosted registration/PKCE receipts and three-browser recordings/assertions in `evidence/APP-074/`. Use the independent observer to detect intentional token/grant/dispatch leakage in a negative control. Current public endpoint existence, a green local auth verifier or a temporary CIDR rule is insufficient. APP-012 later proves an admitted user's actual query/receipt path through this same gate.

Source obligations: [ADR-003](../../docs/architecture/ADR-003-PUBLIC-BETA-ACCESS.md), user beta direction, platform R15/C01/C11 and SR1/SR2/SR7/SR12. [Cross-team handoff](../../docs/planning/CROSS-TEAM-HANDOFF.md) defines FormaStack versus GenUI ownership.

## Migration and rollback

Disable new signup/redemption while retaining opaque-session invalidation and current membership/entitlement checks. Roll back only to a build that denies protected work under the same gate. Keep failed enrollments, scoped outcomes and audit; never substitute an organization picker, return bearer credentials to the browser or grant access because the provider is unavailable.

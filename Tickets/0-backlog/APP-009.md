## Why

A principal, tenant or service-scope mistake can expose another organization’s work; this boundary must be proven before dependent integration. This ticket delivers: implement fauth-backed session lifecycle.

## What changes

PKCE state bound to pre-session cookie, signature/issuer/audience/time/kid verification, tenant membership, opaque secure cookie, idle/absolute expiry, signout/all-sessions and same-origin mutation protection; unknown keys fail closed.

Keep this a reviewable slice: L means approximately 3–5 focused days. Re-estimate before selection and split the ticket if it exceeds five focused days. The estimate is a planning bound, not a delivery date.

Scope excludes production deployment and real customer data; this is a synthetic qualification. Upstream framework/auth changes remain with the FormaStack team.

## Acceptance tests

- [ ] A legitimate back-channel PKCE flow binds state to a short-lived pre-session cookie and mints an opaque Secure/HttpOnly/__Host session only after signature, issuer, audience, time and membership verification.
- [ ] Replayed code, mismatched state, missing tenant, unknown key, forged token and cross-site mutation are refused; JWKS retries are bounded.
- [ ] Absolute/idle expiration, signout and signout-everywhere invalidate subsequent requests through current membership/session state while existing sessions do not depend on a provider call per request.

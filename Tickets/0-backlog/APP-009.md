## Why

A principal, tenant or service-scope mistake can expose another organization’s work; this boundary must be proven before dependent integration. This ticket delivers: implement fauth-backed session lifecycle.

## What changes

PKCE state bound to pre-session cookie, signature/issuer/audience/time/kid verification, tenant membership, opaque secure cookie, idle/absolute expiry, signout/all-sessions and same-origin mutation protection; unknown keys fail closed. Under [ADR-003](../../docs/architecture/ADR-003-PUBLIC-BETA-ACCESS.md), authenticated pre-access state is a separate short-lived opaque session limited to completing its bound admission flow or logging out. Consume APP-073's real current entitlement ledger before minting a workspace session and on subsequent protected requests. Invite validation precedes tenant-scoped registration; no generic public signup or client-selected tenant/role is admitted.

Keep this a reviewable slice: L means approximately 3–5 focused days. Re-estimate before selection and split the ticket if it exceeds five focused days. The estimate is a planning bound, not a delivery date.

Scope excludes production deployment and real customer data; this is a synthetic qualification. Upstream framework/auth changes remain with the FormaStack team.

## Acceptance tests

- [ ] A legitimate back-channel PKCE flow binds state to a short-lived pre-session cookie and mints an opaque Secure/HttpOnly/__Host session only after signature, issuer, audience, time, current membership and active entitlement verification.
- [ ] Replayed code, mismatched state, missing tenant, unknown key, forged token and cross-site mutation are refused; JWKS retries are bounded.
- [ ] Absolute/idle expiration, signout and signout-everywhere invalidate subsequent requests through current membership/entitlement/session state while existing sessions do not depend on a provider call per request.

- [ ] An authenticated but unadmitted identity can only complete its bound admission flow or log out; pre-access cookies cannot read workspace/private metadata, enqueue work or be upgraded by client-supplied grants. The exact beta callback, server-bound organization and intended signup context remain bound across the flow.
- [ ] After actual APP-073 redemption, mint the workspace session once; code/redemption expiry or revocation, foreign identity and both concurrent completion orders cannot mint an unauthorized session. Expired/revoked entitlement invalidates protected requests and late delivery without relying on provider calls per request.

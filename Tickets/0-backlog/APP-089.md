## Why

The beta images shipped with 0 CRITICAL findings but 21 HIGH CVEs remain in the base images (glibc, util-linux, pcre2, krb5, dpkg, zlib, libcap2). ECR basic scanning does not scan OCI image indexes, so scan-on-push on a multi-platform push reports nothing for the index; only a scan of the arm64 child manifest is meaningful. The pinned Debian security package versions in the Dockerfile are exact pins, so they go stale unless bumped together with the base image digest.

## What changes

1. **Triage the 21 HIGH findings** by package: fixed in a newer Debian security release (bump), fixed only upstream (record with the reachability argument), or not reachable in this image (record as accepted with the finding id).
2. **Make scan-on-push effective:** push single-platform manifests (no index) or scan the arm64 child by digest; the release procedure records the scan result per pushed digest and refuses a push whose scan is missing. The `genui-qualification` and service repositories both follow the rule.
3. **Bump the pinned Debian security versions together with the base digest** in one change, with `check_image.py` verifying that the pins match what the base provides; document the bump procedure so a base-digest change never leaves a stale pin.
4. **Rebuild and re-qualify** the service and qualification images on the new base: the local harness, `check_image.py`, and the next managed window's receipts name the new digests.

## Acceptance tests

- [ ] Every one of the 21 HIGH findings has a disposition (fixed by the bump, or recorded with its reachability argument and finding id) in `evidence/APP-089/`, and the new images report 0 CRITICAL and no unexplained HIGH.
- [ ] A scan-on-push result exists for the arm64 child digest of each pushed image (not only for an index), and the release procedure fails when it is missing.
- [ ] The pinned Debian security versions and the base digest change in one commit, and `check_image.py` fails when they disagree.
- [ ] The rebuilt images pass `local_harness.py` and `check_image.py`; an independent review binds the Dockerfile and procedure changes.

## Verification

Reuse APP-075's image tools and the ECR scan output retained in `evidence/APP-078/`. Record the base digest, package versions, scan finding counts per digest and the commands. Source obligations: C01; SR1, SR8; ADR-005.

## Migration and rollback

No schema change. A failed rebuild leaves the running image digest in place; the service keeps the previous digest until the new one passes.

## Why

There is no root `Cargo.toml`: `app/` and its production path dependency `spikes/APP-006` resolve as two graphs, and Cargo honors `[profile.*]` only in a workspace root, so the ADR-012 dev profile has to live in whichever manifest happens to be the root. Docker's builder cache also grows with every image build and nothing in `just clean` reclaims it (the Docker VM disk is the incident ADR-012 names).

## What changes

1. **Root `Cargo.toml`** (D13.3): `resolver = "3"`, members `app` and `spikes/APP-006`, `parser` and the frozen spikes APP-001/003/004 excluded; the `[profile.dev]` of ADR-012 D12.4 moved here from `app/Cargo.toml`; `app/.cargo/config.toml` (`jobs = 3`) moved to `.cargo/config.toml`; `app/Cargo.lock` moved to `Cargo.lock` (package set unchanged); `target/` is the root one, still per checkout.
2. **Images**: the service and qualification Dockerfiles copy `Cargo.toml` and `Cargo.lock` to `/source/` and the members at their paths, mount the target cache at `/source/target`, and build `-p forma-app-platform`; the root `.dockerignore` and the qualification `Dockerfile.dockerignore` admit the root manifests (`app/Cargo.lock` gone). The managed qualification's `SOURCES` binds `Cargo.lock` and `Cargo.toml` (root) instead of `app/Cargo.lock`; `local_harness.py` reads the root names. The operator image builds no app code and is unchanged.
3. **CI and scripts**: `tenant-foundation.yml` runs cargo from the root with `-p forma-app-platform`; `scripts/dev/{check,campaigns,dev,server,clean}.sh`, `scripts/check-foundation.py`, `app/scripts/composer_smoke.sh` the same, `target/` instead of `app/target`; `just check` gains `clippy-dev` (clippy with `--features dev-stand`); `rust-analyzer.linkedProjects` is `Cargo.toml` and `parser/Cargo.toml`; the APP-006 qualifier takes the target directory and lockfile from `cargo metadata` (in the repository it is a workspace member; standalone, in its own image, both stay its own).
4. **`just clean docker`** (step D): also `docker builder prune --filter until=72h` and removes local `genui-{service,qualification,operator}:pitch-*` image sets except the newest three. `compose.dev.yaml` stays PostgreSQL only.

## Migration and rollback

After merging, a checkout's old `app/target` is dead weight: `just clean target` removes it with the new root `target/`. Rollback: revert the commit (the manifests move back).

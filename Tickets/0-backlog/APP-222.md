## Why

What exists is verified on `main` at `164dd573`. Every model call goes through one client, `composer::model::Anthropic`, and first takes a slot of the process-wide `DailyCap` (1,000 a day) and, when `ModelRequest::member` is set, of the member's `MemberDailyCap` (80 a day). Its users are the composer, Ask, Shape, folders, the action path, the widget customizer, MCP (`forma_compose_app` and the folder tools; every other MCP tool runs on the member's own AI plan) and Slack. That single chokepoint is the professional pattern, and it stays.

What falls short of how mature SaaS products meter AI:

1. **The caller is optional.** `ModelRequest::member: Option<String>`. A route that forgets to set it counts only against the organization cap, and nothing fails at compile time.
2. **The counters are in memory.** `OnceLock` statics live in one process. A restart or deploy resets every allowance mid-day, and a second task would double the cap.
3. **Calls, not tokens.** No input or output tokens, no cost, no source. Nobody can answer "who or what spent today's AI, and what did it cost?"
4. **Allowances are compiled or environment values, and nobody is warned.** These are `GENUI_MODEL_DAILY_CALLS`, `GENUI_MODEL_DAILY_CALLS_PER_MEMBER`, and the compiled MCP limits (`MCP_TOKEN` 120/h, `MCP_MEMBER` 240/h, `MINT_MEMBER` 10/h, `mcp/mod.rs`, `mcp/tokens.rs`). Every organization gets the same numbers (follow-up A13: limits are data, not class constants). The first sign of the cap is a member's 429.

## What changes

### Part A: a normal release, next after APP-217 (no migration)

1. **Typed caller, required:** `ModelRequest { caller: Caller, source: Source, … }` with `enum Caller { Member { organization, principal }, System { reason: &'static str } }` and `enum Source { Canvas, Ask, Shape, Folder, Action, Customizer, Mcp, Slack }`. No `Option`: every call site must say who and why, or it doesn't compile. A test lists the `System` reasons in product code, and today that list should be empty.
2. **Usage events at the chokepoint:**
   - each call logs `model.call` (source, outcome, latency, and the `usage.input_tokens` and `usage.output_tokens` from the API's response);
   - `model.usage_threshold` fires once per day at 80 % and 100 % of the organization's and each member's allowance;
   - `model.call_failed` carries the provider status.

   No prompt, content, name or note is logged. These are APP-219's JSON lines, ship with it, and get its metric-filter alarms: the threshold reaching 80 % emails victor@getforma.dev.
3. **Limits become deployment configuration now:**
   - the MCP windows and the AI caps read `GENUI_LIMIT_*` settings, the abuse and infrastructure tier of A13, with today's numbers as defaults;
   - the stack passes them as parameters;
   - a test refuses a value outside a sane range.

### Part B: a schema release (migration 0025), the durable and per-organization half

4. **The usage ledger:** `genui.model_usage_daily (organization_id, principal_id, day, source, calls, input_tokens, output_tokens)`, FORCE RLS per organization. The admission check is one atomic `INSERT … ON CONFLICT DO UPDATE SET calls = calls + 1 WHERE calls < $limit RETURNING`, through a `SECURITY DEFINER` function owned by a NOLOGIN role (the `genui_admit` pattern). So the cap holds across restarts, deploys and several tasks, and N concurrent calls never exceed it. Tokens are recorded after the response. A refused or failed call releases its slot, as `MemberDailyCap::release` does today.
5. **Allowances as plan data, the first step of the tiers (A13):** `genui.organization_allowances (organization_id, key, value, set_by, set_at)` for the usage tier: `ai_calls_per_day`, `ai_calls_per_member_per_day`, `mcp_calls_per_member_per_hour`, `mcp_calls_per_token_per_hour` and `agent_tokens_per_member`. One resolver, `allowance(org, key)`, takes the organization's row, else the deployment setting from Part A, else the compiled default. An audited operator command `admission set-allowance` writes it (a new audit kind). Plans (Free, Pro, Team, Business) later become named bundles of these keys.
6. **Admins can see it:** `/admin` shows today's AI use for the organization and per member (calls, a share of the allowance, and source totals), from the ledger.

## Acceptance tests

- [ ] Part A: every model call site compiles only with a `Caller` and a `Source` (the type change is the proof). A campaign drives each source through the stub model and finds one `model.call` line with the right `source`, tokens and no content. Crossing 80 % fires one `model.usage_threshold` and its alarm once.
- [ ] Part A: the MCP windows and AI caps follow their `GENUI_LIMIT_*` settings in a test (a lowered value refuses sooner). The defaults equal today's numbers. Out-of-range values refuse to start.
- [ ] Part B: the cap survives a restart (take N, restart the service under test, the count persists). Two app processes against one database share one allowance. 50 concurrent calls against a limit of 10 admit exactly 10. A per-organization allowance row overrides the deployment setting, and `set-allowance` is audited.
- [ ] Part B: `/admin` shows the day's usage per member and the organization's total, and a non-admin gets the uniform 404.

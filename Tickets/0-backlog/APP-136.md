## Why

The commands, local state, branch model and beta delivery ladder were spread across ADRs and ticket logs. README and CONTRIBUTING still described the pre-runtime stage, the product guide duplicated setup, and the deploy runbook named TD:8/schema 11 as its latest state even though the tracked release history reaches TD:12. A developer needs one current entry point without treating history as a fresh observation or proposed production as an existing environment.

## What changes

1. Add [DEVELOPMENT.md](../../docs/DEVELOPMENT.md), following ADR-012's eight-part outline: the project/module map, first hour, edit loop, checks and CI/quarantine, campaigns, parser/images, approval-gated beta delivery and rollback, housekeeping and agent rules. Include ADR-013's branch model, common private ledger and delivery diagram; production remains explicitly deferred.
2. Point README, AGENTS, CONTRIBUTING and the product guide at that entry point. Replace stale preparation-only claims with current source guidance and links to retained historical evidence. Keep frozen design and old measurements intact.
3. Correct the runbook's historical state summary using RELEASES.md (TD:12, `3901992`; schema 13 marked inferred, full window not in Git). Require observation before using it. Correct positional window-ID syntax, root-checkout candidate selection, the private directory and exact-check entry point. Preserve per-action approvals, secret handling and recovery requirements.
4. Explain important source behavior: `just images` needs a candidate SHA; `just ci` includes eighteen catalog campaigns but does not replace all remote workflows; a missing MSRV toolchain is a skip; `just check`'s admin build can restart watched servers; `just clean target` deletes dev state and has no running-instance guard; a mutation dry-run may still refuse absent approval words.
5. Remove the duplicate Folder glossary row, correct the library count and link the current pitch/recording documents. Update the release-history prose that previously called the runbook stale, without changing any historical release row.

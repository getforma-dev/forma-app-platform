## Why

Bare sign-in only uses a remembered organization hint and otherwise instructs the visitor to find a link. A stale or wrong hint can take them to a different tenant with no useful recovery. The current clean trial must be preserved.

## What changes

One native workspace-entry form accepts a configured name, opaque handle or exact-origin Forma sign-in URL, submitting directly to the existing secure login start. Remembered/direct destinations are editable; Switch workspace displays an empty input. Keep direct handle POST compatibility, invitation/shared-app destination bindings and current authorization. No anonymous workspace directory or fake email finder. APP-163/164 own those later capabilities. APP-117 owns configured readable addresses and restoring other retained workspaces to the served registry.

## Acceptance tests

- [ ] Bare, remembered, direct-link, switch and failed sign-in pages show usable labeled controls without an intermediate confirmation screen after workspace submission.
- [ ] Names, opaque handles and supported exact-origin links reach the correct existing provider flow; hostile URLs, malformed/duplicate/extra fields and stale/unserved destinations refuse safely.
- [ ] Same-origin enforcement, request/body/rate limits, PKCE, expected tenant/subject and current membership remain enforced; rejected normalization causes no provider request.
- [ ] Existing membership and app-share invitations preserve destinations; guest identity still grants no workspace membership.
- [ ] Native SSR, phone/keyboard behavior, actual session/invite campaigns and independent security review pass with retained evidence.
- [ ] Qualified AWS delivery preserves the existing trial's identity/data/invitations and verifies useful sign-in entry; hosted authentication is claimed only when actually observed.

## Verification

Retain malformed-input and cross-tenant refusals, screenshots and actual release identity under `evidence/APP-162/`. Regenerate/check the board.

## Migration and rollback

No schema, credential, account or data migration. Retain existing routes and cookies. An alias only maps to a preserved organization handle through reviewed configuration. Roll back to a schema-compatible qualified runtime without recreating the trial or replaying invitations.

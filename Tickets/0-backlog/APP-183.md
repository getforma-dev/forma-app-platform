## Why

The standard SaaS split gives each organization's admins an in-product admin area. Victor is the trial organization's admin and needs to see who joined, whether they consented, how active they are, and to remove someone.

## What changes

Migration 0023 adds two SECURITY DEFINER functions owned by a NOLOGIN role:
- `genui_private.org_admin_overview(org, caller)` returns one row per member: membership status, consent, last session, apps, works, records, uploads, code status.
- `genui_private.admin_remove_member(org, caller, principal)` revokes membership and entitlement, bumps the epoch and appends the audit event. It refuses removing oneself or the last admin.

Both require a live membership with organization `admin_policy`. The server-rendered `/admin` page shows the table and a CSRF-protected Remove action. Non-admins get the uniform 404. The canvas shows an Admin link to admins only, and a feedback link to `feedback@getforma.dev`.

## Acceptance tests

- [ ] A member without `admin_policy`, a member of another organization, and a signed-out visitor each get the uniform 404 from `/admin` and its POST, with no data read.
- [ ] An admin sees every member's status, consent version, last activity and counts. The figures match the database in a campaign.
- [ ] Remove revokes access at once: the removed member's session stops working, the audit chain records the removal, and removing oneself or the last admin is refused (409).
- [ ] An independent Tier A review finds no blocker.

## Verification

A new `org-admin` campaign against Postgres, plus the SSR page tests and `just check admin test http-smoke`. Each refusal check fails with its rule removed.

## Migration and rollback

Additive migration 0023 (shared with APP-182). The page is removable without data change.

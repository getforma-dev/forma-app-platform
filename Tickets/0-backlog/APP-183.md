## Why

The standard SaaS split gives each organization's admins an in-product admin area. An admin needs to see who joined, whether they consented, how active they are, and to remove someone.

## What changes

Migration 0023 adds two SECURITY DEFINER functions owned by a NOLOGIN role. `genui_private.org_admin_overview` returns per member: name, code note, status, consent, last active, apps, works, records, uploads. `genui_private.admin_remove_member` revokes membership and entitlement, bumps the epoch and audits it, and refuses removing oneself or the last admin. Both require live organization `admin_policy`. The server-rendered `/admin` page shows the table and a CSRF-protected Remove. Non-admins get the uniform 404. The canvas shows an Admin link to admins only, and a feedback link.

## Acceptance tests

- [ ] A non-admin, a member of another organization and a signed-out visitor each get the uniform 404 from `/admin` and its POST, with no data read.
- [ ] An admin sees each member's name, status, consent version, last activity and counts, matching the database in a campaign.
- [ ] Remove revokes access at once: the session stops working and the audit records it. Removing oneself or the last admin is refused.
- [ ] An independent Tier A review finds no blocker.

The `org-admin` campaign, the SSR tests and `just check admin test http-smoke`.

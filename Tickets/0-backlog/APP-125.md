## Why

Nothing is pinned where cargo, node or python look; four venvs are hand-made and one is borrowed from another clone through a committed symlink (`contracts/.venv`, mode 120000), which is why "Contract qualification" fails on every run; `app/target` holds 33 GB of retained debug objects (inventory §B.7).

## What changes

1. `rust-toolchain.toml` at the repo root (1.93.1, minimal, clippy + rustfmt, wasm32 target); `.node-version` 22.21.0; `.python-version` 3.11.14.
2. `app/Cargo.toml` dev profile: `debug = "line-tables-only"`, `split-debuginfo = "packed"`, dependencies without debug info; `app/.cargo/config.toml` `[build] jobs = 3`.
3. `git rm contracts/.venv`; `scripts/dev/setup.sh` creates every venv per checkout with uv from the existing hashed locks (`--require-hashes`, binary wheels only) and runs `npm ci` in `app/admin` and `infra`.
4. `tools.versions` records the pinned tool versions (AGENTS.md:13).
5. CI's `cargo +1.93.1` lines become plain `cargo` (the toolchain file decides); the MSRV `cargo +1.85.0` check keeps its explicit toolchain.

## Acceptance tests

- [ ] `cargo build` in `app/` uses 1.93.1 without `+` (`rustup show active-toolchain` names the toolchain file).
- [ ] `du -sh app/target` after a clean `cargo build --tests` with the new profile is under a third of the inventory's 33 GB.
- [ ] `contracts/.venv` is no longer tracked; Contract qualification's three commands pass locally against the venv `scripts/dev/setup.sh` made.
- [ ] `scripts/dev/setup.sh` is idempotent and leaves no path into another checkout.

## Verification

Local commands recorded in the log; Contract qualification on the next push of the branch.

## Migration and rollback

No behavior change. Revert the commit to return to the previous state; a checkout that relied on the symlink runs `scripts/dev/setup.sh` (or `just setup`).

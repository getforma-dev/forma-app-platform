## Why

The product claim requires meaningful new apps and edits through supported primitives, with no developer rewriting a second example. This ticket delivers: implement patches, semantic diff and undo revisions.

## What changes

Base revision/target IDs, compare-and-set conflict, calculation/schema/input changes visible, undo produces a new revision; patches never overwrite committed records or unrelated personal state.

Keep this a reviewable slice: L means approximately 3–5 focused days. Re-estimate before selection and split the ticket if it exceeds five focused days. The estimate is a planning bound, not a delivery date.

Scope excludes production deployment and real customer data; this is a synthetic qualification. Upstream framework/auth changes remain with the FormaStack team.

## Acceptance tests

- [ ] A patch names its base revision and target IDs, and its semantic diff exposes input, calculation, command and record-schema meaning changes.
- [ ] Concurrent patching of a stale base returns a conflict with current revision context rather than overwriting the newer draft.
- [ ] Undo creates another immutable revision; committed records, unrelated notes and personal filters/layout remain intact.

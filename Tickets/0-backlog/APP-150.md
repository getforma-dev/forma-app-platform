## Why

After an app is a page, Victor wants sections he can mark and return to. A section is a place: a region of the board, or a part of the app page. It is not a template in the create-app modal. APP-141 already uses "favorite" for a template the member likes. This ticket uses it for a place the member returns to.

## What changes

1. The member marks a section. The mark is this member's, in this browser, with the rest of the layout. It is not a grant and not shared.
2. A favorites list shows those marks. Choosing one moves the view to that section. It does not create an app and it does not change data.
3. Unmarking removes the jump. The section stays. The underlying cards, page, or records stay.
4. This waits until APP-142's page exists, so a section inside an app is a component of that page and not a new object.

No work before APP-142. No product code in the ticket that only records this.

## Acceptance tests

- [ ] The member marks a section of the board or of the app page. It appears in a favorites list.
- [ ] Choosing that favorite moves the view to the section and does not change records.
- [ ] Unmarking removes it from the list. The section remains.
- [ ] A template favorite in the APP-141 modal is a different list and is not mixed into this one.

## Verification

Read APP-141 and APP-142 before building, so the two uses of "favorite" stay separate. Ports 4001–4003 and 4010 stay untouched.

## Migration and rollback

No migration. The marks live in this browser's layout. Clearing them does not drop the app.

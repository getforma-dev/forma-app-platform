## Why

A new customer's first question is "can I just give it my spreadsheet?". The canvas had folders, formation and Ask, but no visible path from a file to a card to an app: the empty canvas offered words and the Library only, and a folder offered formation and a brief. Victor approved (2026-10-31) one visible path, data → card → app, built from the existing concepts.

## What changes

1. **Empty canvas.** A third choice beside "Describe what you need" and "Browse your library": **Drop files or upload** (a file picker and a visible drop target), which makes a folder with the files (the existing folder/upload path).
2. **A folder with files offers three buttons:**
   - **Ask**: the Ask tab scoped to the folder, a read-only question about its tables, answered with text and every row it used (file, SHA-256, sheet, row);
   - **Make a card**: formation constrained to one card, a minimal app named after the folder (or the file) with exactly one card, the most useful view of its data, linked back to the folder, shown with its app address chip;
   - **✨ Make an app**: the full formation (existing).
   Both Make actions show the folder's confirm before anything is created.
3. **Docs.** CANVAS-RULES "Start from your data", a GUIDE "Using the canvas" line, the Shortcuts tab.
4. **Deferred:** cross-app merge (cards from different apps into one app).

## Acceptance tests

- [ ] The empty canvas shows "Drop files or upload"; picked or dropped files make a new folder holding them.
- [ ] A folder with files shows Ask, Make a card and Make an app (the Make buttons for its owner only); the Make buttons send nothing before their confirm.
- [ ] Ask on a folder reads its tables read-only under the folder's authorization and answers exactly `{text, references}`, each reference a file and row from the server; a reply citing a row it was not shown, or carrying a view, is refused; anyone who cannot read the folder gets the uniform 404 with no model call; nothing is written.
- [ ] Make a card creates an app with exactly one card, linked back to the folder, named under a free address.

## Verification

Unit tests, admin tests and the folders Docker campaign; a browser walk on the dev stand.

## Migration and rollback

None: no migration. Ask on a folder is a new read-only route; Make a card is a flag on the folder's existing build route.

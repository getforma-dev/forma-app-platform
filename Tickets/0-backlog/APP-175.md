## Why

Beta auto-promotion refuses any change to the schema manifest or deployment contract ([BETA-PROMOTION.md](../../docs/pitch/BETA-PROMOTION.md), `ops/promotion/runner.py` `bundle`). Each of PR #83 and #84 adds a migration, and `pool.rs` makes the service require the exact schema version, so merging either freezes every later beta release until the database is migrated and the idle promotion baseline admits the new manifest and contract. Schema 20 crossed that gap on 2026-11-04 by hand (snapshot, migration, baseline edit; [APP-167 log](../4-done/APP-167.md)); there is still no reviewed, repeatable procedure on `main`.

## What changes

1. **Read-only preflight**, run against the live beta database before any change:
   - no two organizations share an active `(issuer, provider_tenant_id)` binding (0021's index would refuse the upgrade whole);
   - the recorded schema version and migration hashes equal the reviewed manifest's 1–20;
   - the promotion state is idle, with a fresh budget basis.
2. **Snapshot** the RDS instance under a dated name. This is the rollback point, since migrations are forward-fix only.
3. **Migrate** with the stack's migration task on the candidate image digest. The runner proves each version's catalog as it goes.
4. **Admit the baseline** with a hash-bound, idle-only plan/apply helper in `ops/promotion`, in the shape of `expiry_policy`. It sets only `schema_manifest_sha256` and `deployment_contract_sha256` to the candidate's values, writes an immutable receipt and verifies exact readback.
5. **Promote the image** through the normal packet and Victor's approval.
6. A runbook section in `docs/pitch/BETA-PROMOTION.md` that replaces the by-hand schema 20 steps.

## Acceptance tests

- [ ] The helper refuses a non-idle state, a changed state hash, a manifest or contract other than the reviewed candidate's, and a missing receipt path; tests cover each.
- [ ] The preflight is read-only and refuses on a shared tenant, an unexpected recorded migration, or a stale basis.
- [ ] Independent review of the helper, the preflight and the runbook finds no blocker.
- [ ] On beta: snapshot, migration to 22, baseline admission and one image promotion, each with readback evidence and Victor's approvals; `/health/ready` passes on the new image.

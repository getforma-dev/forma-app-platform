## Why

Victor, 2026-10-30: "a card can be a box where we can upload pdfs and view them in modal by clicking on them … /storage <name> or /storage 1 … a box that has all assets, one can call the agent and be like /storage one create me an app for metrics … we don't want to overload the AI with context … we also want to keep the linkage of the box of data that created the app so we can trace back to the source of truth." And: "what happened with the real data CSVs? Upload, parsed, viewed and organized? That's a real win."

Today member-facing import is not built (APP-016/017/018 deferred by ADR-011); the sealed parser (ADR-009, `app/src/imports/sandbox.rs`, `parser/`) is built and qualified. A box is the member-facing home for files and the shortest path to real data with receipts that point at the uploaded file.

## What changes

1. **Box** (migration 0011: `genui.boxes`, `genui.box_files` under RLS and FORCE RLS; per-member ownership, shareable like a work through the share path): a canvas card holding files, standalone or attached to an app (`app_id` nullable); numbered in the library pane under "Boxes"; `/storage` (alias `/box`) lists boxes, `/storage <name|number>` brings one, `/storage new <name>` creates one.
2. **Upload**: drop or pick files onto the box (PDF, PNG/JPEG/WebP, CSV, XLSX, TXT/MD; ≤ 20 MB each, ≤ 20 files per box; magic-byte checks). Originals are stored as immutable objects under the organization's prefix (SSE-KMS with the tenant key, If-None-Match, SHA-256 recorded) through the tenant role; the file row records name, type, size and digest; uploads are audited commands.
3. **View**: each file is an icon tile; click opens the focus modal (APP-106): PDF in the browser viewer from an authorized same-origin route (`Content-Disposition: inline`, `Content-Security-Policy: sandbox`, `X-Content-Type-Options: nosniff`), images inline, CSV/XLSX as a typed preview table, text as plain text; no editing.
4. **Real data**: a CSV/XLSX in a box runs the sealed parser (one process per job, no network), shows inferred column types for the member to confirm (APP-018 lite), and registers an immutable source revision (APP-016 lite) whose original is the box file. It is then available as an input for apps, with receipts naming that revision.
5. **App from a box**: `/storage <box> create me an app for <purpose>` sends the composer a capped context — file names and types, each confirmed CSV/XLSX schema with at most 20 sample rows, at most 3 data files; PDFs contribute their names only in this version (DS entry) — and the model proposes a typed definition whose inputs are bound to those source revisions; admission as for every definition (I5); labeled generated.
6. **Provenance**: the resulting app carries `derived_from_box` (box id and the file digests used); its card shows "Built from box: <name> · 3 files" linking to the box; every receipt's source revision links to the box file it came from; the box lists "Apps built from this box". Sharing the app grants the teammate read access to those source revisions and the box's files used (not the whole box unless shared).

7. **Naming** (Victor, 2026-10-30): the member-facing noun is **Folder** (one constant: `boxes::NOUN`, `box-api.ts NOUN`); "box" stays the internal term (tables, routes `/v1/boxes`, code). Commands: `/folder` (aliases `/folders`, `/storage`, `/box`, `/boxes`; one list each side); the AI keyword is **formation**: `/folder <name|number> formation <instruction>` or `/folder formation <instruction>` (the active folder).
8. **No commands needed** (Victor): clicking or focusing a folder card makes it the **active folder** (highlighted card, a removable "📁 <name> ×" chip in the intent bar, placeholder "Ask about <name>, or build something from it…"); plain sentences then go to that folder ("build a metrics app and explain it", "brief me"); ×, Esc or a click on empty canvas clears it. Buttons on the folder card: "✨ Formation" (one editable prompt), "Brief me", rename by clicking the title (audited). "+ New folder" in the library pane's Folders group and the toolbar; files dropped on empty canvas create "Untitled folder". `@` in the intent bar picks a folder by name ("build a metrics app from @Q3 metrics").
9. **Auto-parse and ad hoc data**: a CSV/XLSX is parsed by the sealed parser at upload and shows inferred types and a preview at once (defaults pre-accepted, adjustable). A CSV/XLSX dropped on the canvas or the intent bar outside a folder goes to the member's implicit "Uploads" folder (`/folder uploads`) and becomes a **data card** (its totals and rows, with receipts, header naming the file, rows and columns); the card's notice offers "Adjust types", "Make an app from this" and "Keep as card", and the sheet offers "Add to app…" (the smallest honest version: the file is copied into the member's folder attached to that app and its data card is grouped with the app; no new app revision).
10. **Explanation card** on apps built from a folder: "AI summary · numbers from receipts". The fast model sees only computed results (view titles, column names, at most 20 result rows) and answers 1–5 findings whose text names every number as a placeholder (`{view.column[n]}`); the server refuses any digit outside a placeholder, unresolvable refs and markup, fills each placeholder from the governed result (formatted by type, carrying that view's receipt) at every read, stores only the template, and shows "No summary" on a refusal; "Regenerate". Shared with the app (the teammate sees the same values, run under the teammate's authority).
11. **Brief card** per folder: "AI brief · cited from your files": an overview, a paragraph per file, key points. Data numbers are placeholders filled from the data cards' receipts (same digit rule). Small PDFs (≤ 10 pages, ≤ 5 MB, at most 3) go to the model as Messages `document` blocks with citations enabled; each cited statement keeps its file and page (a "file, p. N" chip opens the viewer at that page); an uncited sentence with a number is dropped; larger PDFs are listed "too large for the brief in this plan" (APP-111). Stored as typed data, rendered as text.
12. **Every surface**: `POST /v1/act` takes `box_id` (the active chip or an @-mention) or a folder named in the words ("from the Q3 metrics folder", "from folder 1"); one match acts, several answer a chooser, none falls through. Slack `/forma folder <name> formation …` and plain sentences naming a folder; MCP tools `forma_list_folders`, `forma_folder_formation {folder, instruction}`, `forma_folder_brief {folder}` (attribution "via <label>", app link, origin and folder provenance). Answers carry per-step `timings` (parse, context, generation, admission/publish, total; views and summary for explanations; data, PDFs, summary for briefs).

## Acceptance tests

- [ ] Upload a PDF, an image, a CSV and an XLSX to a new box; each appears as a tile; clicking opens the right viewer in the focus modal; a foreign organization's member gets the uniform 404 for the box, each file and the view route.
- [ ] A CSV with the wrong magic bytes, a 25 MB file or a 21st file is refused with a neutral message; nothing is stored.
- [ ] Confirming a CSV's column types registers a source revision; a view over it shows numbers whose receipt names that revision and links to the original file in the box.
- [ ] `/storage 1 create me an app for metrics` produces an admitted app bound to the box's revisions, labeled generated, showing "Built from box"; the model request contains no more than the capped context (logged sizes only).
- [ ] Sharing the derived app lets the teammate open it and follow receipts to the files used, but not see other files in the box.
- [ ] Reload: boxes, files and the derived app's provenance persist.
- [ ] The explanation of a derived app shows only numbers equal to receipt-carrying results; a hostile model reply with an invented number is refused ("No summary").
- [ ] The brief cites the PDF by page; an uncited number is dropped.
- [ ] "build a metrics app from folder 1" (canvas action path), `/forma … from the Q3 metrics folder` (Slack) and `forma_folder_formation` (MCP) build the same kind of app from the folder.

## Verification

Unit tests for the routes and refusal order; a Docker campaign (upload → parse → register → derived app → share → isolation); the real-Haiku derived-app smoke (sizes and latency only); browser walk with screenshots.

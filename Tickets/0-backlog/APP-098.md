## Why

Victor, 2026-10-30: "Anything that is limited or needs to be hardened or expanded put it into a ticket so we can revisit later; mock or hard code those things to get the demo polished and the vision out there." This ticket is that register. It makes ADR-011's visible debt one list with one switch, so that nothing mocked can drift into the platform unnoticed.

## What changes

1. One switch, `GENUI_DEMO_MODE`: off by default in code, on only in the pitch deploy's task environment. Every demo shortcut reads it and no other flag; with it off, no shortcut path runs.
2. Real stays real in every mode: sign-in, permissions, audited commits, receipts, live updates. Demo data stays labeled synthetic, and anything the shortcuts fake is labeled in the product (retrieved, adapted, generated, or demo).
3. Every shortcut and known limit is an entry below with what it fakes or limits, where (file), why, the proper fix and the owning follow-up ticket. New shortcuts are added here before they merge.

Where: `app/src/composer/commands.rs`, `storage/queries.rs` (`named_works`). Why: No migration (pivot/mcp and pivot/slack add migrations). Proper fix: A `name` column (or a work-alias table) with a uniqueness constraint per organization and member, and a rename command. Owner: APP-097.
- **DS-56** (Shortcut). Fakes or limits: Receipt images are parsed and discarded; the record notes `receipt: attached` and the card shows a client-side thumbnail, but no image is stored. Where: `app/src/actions/receipt.rs` (the bytes live in the request's memory for one vision call; the log carries media type and length only), `app/admin/src/canvas/receipt.ts`, `actions.ts`. Why: Storing receipts needs an evidence-grade object path, retention and access rules. Proper fix: Receipt objects in the evidence bucket under the record's authorization, with retention policy. Owner: APP-097.
- **DS-57** (Shortcut). Fakes or limits: Inside the demo organization the rehearsed receipt fixture (`docs/pitch/receipt-fixture.png`, synthetic store "Greenleaf Bowl Co.", matched by SHA-256) parses deterministically, with no model call; the member's words still override it. Where: `app/src/actions/receipt.rs` (`FIXTURE_SHA256`, `fixture_values`), `docs/pitch/receipt-fixture.png`. Why: Stage latency. Proper fix: Real vision parse first, rehearsed as a timeout fallback, then delete. Owner: APP-097.
- **DS-58** (Debt). Fakes or limits: The expense ledger aggregates client-side over the newest 200 live records; older records are not counted. Where: `app/admin/src/canvas/ledger.ts` (ledger card; SSR first paint `app/src/query/canvas_ledger.rs`). Why: Phase 1 views read source inputs only (DS-47). Proper fix: Engine views over records inputs with receipts (PH02 Track C). Owner: APP-097.
- **DS-59** (Debt). Fakes or limits: The canvas's "via Slack" origin chip comes from an in-process map of the record versions Slack committed (`crate::origins`), not from the audit chain; a restart forgets the marks (the chip disappears, the audited record and its actor are unchanged). Where: `app/src/origins.rs`, `app/src/actions/routes.rs` (`records_document`), `app/admin/src/canvas/records.ts`. Why: The audit event body has no actor-detail field and widening it changes every chain's hash input. Proper fix: A channel/actor-detail column on the command outcome (or the audit event, with a chain version bump) written in the commit's transaction. Owner: APP-097, APP-100.
- **DS-60** (Debt). Fakes or limits: A Slack link binds the Slack user who ran `/forma link` to whichever member opens the URL while signed in and confirms; nothing checks that the Slack profile and the member are the same person (the page names the Slack user id and workspace first). Where: `app/src/slack/link.rs`. Why: The pitch links three known demo people by hand (DS-51). Proper fix: Before writing the row, match the Slack profile's verified email (`users.info`, `users:read.email`) against the member's provider identity, or bind the link to an OAuth "Sign in with Slack" assertion. Owner: APP-097, APP-100.
- **DS-61** (Debt). Fakes or limits: "The approver" for the Slack DM is derived, not stored: every linked member who now holds `record_write` on the work, did not file the record and finds it at a declared `from` state is DMed once per record version (an in-process set), on `record.committed` or `app.shared`; the filer's DM is sent only for decisions made in Slack. Where: `app/src/slack/notify.rs`, `app/src/actions/resolve.rs` (`pending`). Why: The expense schema has no approver field and the canvas shares to the named approver with `record_write`. Proper fix: An approver (reference) field or an approval-request row naming the member, a durable notification outbox (DS-52), and filer notifications from any origin. Owner: APP-097, APP-100.
- **DS-65** (Planned shortcut). Fakes or limits: The weather widget serves fixture data inside the demo organization (and whenever Open-Meteo is unreachable), labeled. Where: `app/src/widgets/` weather route. Why: Stage reliability; no network dependency on stage. Proper fix: Connector broker with caching and per-organization egress policy. Owner: APP-097.
- **DS-66** (Planned shortcut). Fakes or limits: Widget customization is a closed set of skins, palettes and fonts; rehearsed sentences map to fixed states without a model call in the demo organization. Where: `app/src/widgets/`, `app/admin/src/canvas/widgets/`. Why: The model must never write CSS or markup (I5); the pitch needs instant restyles. Proper fix: Generated themes as typed design tokens through admission. Owner: APP-097.
- **DS-68** (Debt). Fakes or limits: No canvas performance regression harness: the earlier canvas's pan/zoom/drag event-cost and settle budgets (`forma-generative-ui/scripts/performance-regression.ts`, 17 budgets) are not ported, so the pitch canvas's DOM-level fixes (reflow batching, parked-card containment, pan transition suppression) are unmeasured. Where: `app/admin/src/canvas/`. Why: Pitch time; the default board is now small (library pane). Proper fix: A Playwright 90-card fixture with the earlier budgets in CI. Owner: APP-097.

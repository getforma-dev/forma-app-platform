## Findings

### Blocker

None.

### Major

**M1. The operator refuses an omitted provider role but accepts any non-admin-named role; least privilege is not enforced.**

- Controlling text: APP-073 acceptance 6 (`APP-073.md:45`): operator provisioning "requires the intended email and explicit least-privilege provider role"; ADR-003:37: "GenUI's operator must select the verified provider's explicit least-privilege identity role … omission is refused by the operator workflow".
- Implementation: `admission_operator.py:53` (`ROLE = [a-z][a-z0-9_]{0,63}`) and `:217` refuse only `admin`, `administrator`, `owner`. Probe R3 (`op.validate` on real argument vectors): `tenant_admin`, `superadmin`, `org_owner` and `member` are **accepted**; only the three listed names are refused.
- The provider's vocabulary is not the one the tests assume. In the FormaStack source GenUI is tracking (`Forma/work/FORMA-367/gatewasm` at `1bf5d3b`, `crates/server/src/handlers/management.rs:1694-1712`, `hosted_code.rs:74`), a `server_only` invitation requires a role, and the built-in roles are `role_admin` and `role_user` plus tenant-defined roles; there is no built-in `member`. The operator tests record `member` (`test_admission_operator.py:83,299`), which the provider would refuse as `invalid_role`, and a tenant-defined role of any name could carry administrator rights. The record is `pending` and no provider call is made in this slice, but this column is exactly what APP-074 will send.
- Fix (`admission_operator.py`): replace the denylist with an allowlist pinned to the least-privilege role of the contract under acceptance, and refuse everything else until APP-006 accepts the contract:

```python
# ADR-003:37 / APP-073 acceptance 6: the provider's least-privilege identity role only.
# FormaStack server_only built-in roles are role_admin and role_user (gatewasm 1bf5d3b);
# widen only by an APP-006-accepted contract, never by operator input.
PROVIDER_ROLES = ("user",)
...
            require(args.provider_role in PROVIDER_ROLES, "provider_role_refused")
```

  Drop `ROLE`. Change `test_admission_operator.py:83,299` (and any campaign use) from `member` to `user`, and add `tenant_admin`, `superadmin`, `member` to the refused cases of `test_issue_argument_bounds`. Record the allowlist and its source digest in `README.md` §D7.17 defaults.

**M2. The three audit hash columns are `text`; ADR-007 D7.8 now requires `genui.digest`.**

- Controlling text: D7.8 as amended in `db1ad04` (on `phase-one-spikes` before the `581fd57` merge): "Every hash is written in the `sha256:<64 lowercase hex>` form and typed `genui.digest` (`previous_hash`, `hash`, `head_hash`) … (0003 review m4)" (`ADR-007…md:64`). The README defers m4 to the coordinator's ADR change (`README.md` §Review fixes); that change has landed and states the typing as a requirement.
- Implementation: `0003_admission.sql:103` (`head_hash text NOT NULL`) and `:112` (`previous_hash text NOT NULL, hash text NOT NULL`). Probe R7 reads `text` for all three from the catalog; `outcome_digest` is already `genui.digest`. The hash input `previous_hash ‖ canonical bytes` has no separator, so its unambiguity rests on a fixed length that no constraint enforces; today the superuser could write `head_hash='not-a-digest'`.
- Fix, while 0003 is still editable in place (it has not been applied outside disposable databases; APP-076 will freeze it): at `0003_admission.sql:103` write `head_hash genui.digest NOT NULL`; at `:112` write `previous_hash genui.digest NOT NULL, hash genui.digest NOT NULL`; regenerate `catalog-v3.json` and `catalog-v4.json`, re-pin `manifest.json` (0003, catalog-v3, catalog-v4) and add one schema-campaign assertion that the three columns are `genui.digest`. No body, grant or policy changes: probe R8 applied exactly these types to a v4 database and then ran backfill, issue, reserve → pending → admit (`admitted`), revoke-entitlement, revoke and `verify` (`verified: true`, admission chain 2 events, operator chain 3), and a malformed head write was refused (`CheckViolation`). The campaign's own synthetic events already use digest-shaped values (`qualify_tenant_schema.py:614-615`). (R8 also confirmed a positive control: the unmodified command refuses the altered database at its catalog proof, before any write.)

### Minor

**m1. `verify` reports `audit_chain_mismatch` for an intact chain when an admission appends concurrently.** `admission_operator.py:467-499` reads each head, then that chain's events, in separate READ COMMITTED statements; an append committed between them makes the tail exceed the head. Probe R1 (an `admission.pending` committed right after `verify` read the admission head): READ COMMITTED → `refused: audit_chain_mismatch`; the same interleaving under REPEATABLE READ → `verified`; a fresh `verify` → `verified`. It fails closed, but an operator would read it as tampering. Locking heads `FOR SHARE` is not an option for `genui_owner` (the RESTRICTIVE UPDATE policy limits row locks to the operator head). Fix: first statement of `verify`, before `begin(c, org)`: `c.isolation_level = psycopg.IsolationLevel.REPEATABLE_READ` (import `psycopg` where `connect()` does), so the head and event reads share one snapshot; add the R1 interleaving as an operator test.

**m2. An identical retry after the member's entitlement or membership was revoked still returns `Admission::Admitted`, with the post-revocation epoch.** `0003_admission.sql:343-351` returns `replayed` from the stored redemption without looking at current status, and `admission.rs:365-369` maps it to `Admitted { principal, epoch, entitlement }`. Probe R2: admitted at epoch 1; after `revoke-entitlement`, the identical retry answers `replayed` with epoch 2; after `revoke-membership`, `replayed` with epoch 3 (stored state: membership `revoked`, entitlement `revoked`). No data is reachable (precheck requires an active membership and entitlement), and ADR-006:33 has the callback fence before minting, but the typed answer tells APP-009 "admitted" for a revoked member, which is the "late response" ADR-003:51 says must not revive access. Fix (`admission.rs:365`): for `"replayed"`, in the same transaction run `SELECT 1 FROM genui.memberships m WHERE m.organization_id=$1::text::uuid AND m.principal_id=$2::text::uuid AND m.status='active' AND EXISTS (SELECT 1 FROM genui.entitlements e WHERE e.organization_id=m.organization_id AND e.principal_id=m.principal_id AND e.status='active' AND e.expires_at>clock_timestamp())` (both readable by `genui_workspace` through 0002 and 0004 under the installed scope) and answer `Admission::Refused` when it returns no row; add the R2 sequence to the admission campaign.

**m3. Slots held by duplicate or lapsed pending admissions are neither bounded per identity nor visible to the operator.** (a) `record_pending_admission` (`0003:293-299`) inserts a second live pending admission for the same identity and code, and `admit_redemption`'s `already_member` branch (`0003:360-362`) leaves the loser live, so one invitee repeating the callback can hold every slot of a multi-use code for 24 hours (README choice 15 accepts this as bounded; the bound is 24 h × all slots). (b) A pending admission that lapses with no later sign-in stays `state='live'` forever and `list` reports nothing (probe R5: row `live`, list entry `live_pending_admissions: 0`, status `active`), while ADR-006:43 says a pending admission that outlives its 24 hours "is denied and recorded for operator reconciliation". Fix: (a) in `record_pending_admission`, after the `already_member` check, if a `pending`, `live`, unexpired row exists for `(p_org, v_code_id, p_issuer, p_provider_tenant, p_provider_subject)`, mark the presignup consumed and return that row's id and expiry as `pending` without inserting; (b) add to `list_codes` per code `lapsed_pending_admissions` (`kind='pending' AND state='live' AND expires_at<=now()`) and `denied_for_reconciliation` counts, and state in the README that this listing is the reconciliation record for lapsed rows.

**m4. ADR-007, the plan and the operator text still carry the pre-0004 numbering.** D7.12 permits renumbering, and adding 0004 for D7.3's entitlement reads is the right reading of the 0003 review's observation, but D7.12's planned list and Consequences (`ADR-007…md:80,112`), D7.7 (`:60`, "0006"), plan Task 6 (`PHASE-1-EXECUTION-PLAN.md:155`: `0004_definition_work_grants.sql`, `catalog-v4.json`, now a collision), Tasks 7 and 10 (`:171-180`, `:221-234`), the Phase 2 plan and ADR-009's `0006` references, and `admission_operator.py:276,279,285` ("migration 0006") all predate it. Fix: renumber APP-010 → 0005/catalog-v5, sessions → 0006/catalog-v6, commands and `organization_sequences`/`query_receipts` → 0007/catalog-v7 in those places (README open question 1).

**m5. "Trial extension" exists only as code extension, and `extend` can shorten.** ADR-003:51 and acceptance 5 ask for explicit, bounded, audited "trial extension or reissuance". Reissuance is a new `issue`; `extend` (`admission_operator.py:410-425`) moves a code's expiry; there is no entitlement (trial) extension for an admitted member, and D7.8's closed operator kinds have none. Probe R4: `extend --expires-days 1` on a 14-day code moved its expiry from 2026-11-12 to 2026-10-30 and was audited as `code.extended`. Fix: either record in ADR-007 D7.19 that Phase 1's trial extension is code extension plus reissue (no entitlement extension), or add `entitlement.extended` to D7.8 and a subcommand; and in `extend` refuse a new expiry that is not later than the current one (select `expires_at` in `lock_code` and `require(new > current, "expiry_not_extended")`).

**m6. Plan Task 5's seed obligation is neither done nor dispositioned.** `PHASE-1-EXECUTION-PLAN.md:140` lists `tenant_seed.py (seed one active trial code and one expired code per fixture organization, digests only)`; the slice instead seeds synthetic entitlements (a necessary, well-labelled change) and seeds no codes, and the README's choices do not mention the omission. Fix: add the two digest-only codes per fixture organization, or record the disposition (the campaigns issue their own codes through the command) in the README and the plan.

**Nits (no change required for acceptance).**
- `0004_entitlement_reads.sql:17` grants `entitlements.entitlement_id`, which no code in this slice reads (APP-009's session reference will); D7.3 says grants arrive with the ticket that uses them. Drop it here or note it in D7.3.
- `admission.rs:358-362` maps any residual 23505 to `AlreadyMember`. After M2 of the 0003 review the identity key cannot raise it; a future unique key would be misreported as a business fact. Prefer `Error::Unavailable` (the transaction is rolled back either way).
- `connect()` (`admission_operator.py:226-232`, as `runtime.migrate`) does not set `gssencmode="disable"`; libpq prefers GSSAPI encryption over TLS regardless of `sslmode` when Kerberos credentials exist, and does not use TLS for a Unix-socket `PGHOST`. Add `gssencmode="disable"` and refuse a `PGHOST` starting with `/` to make "always verify-full" literal.
- `--provider-email` arrives in argv (process list, shell history). Read it from stdin or an environment variable.
- The intended-email digest is an unkeyed SHA-256 of a normalized address; it is pseudonymous (guessable from a candidate address), not secret. Say so in the README.
- The forged-identity checks (`admission_qualification.rs:970-997`, `test_admission_operator.py:362-374`) assert refusal but not its reason; probe R6 shows it is `operator_identity_refused` for `genui_workspace` and `genui_worker`. Assert the reason. The revocation-first fence check (`admission_qualification.rs:~645-652`) proves the wait with a 75 ms sleep rather than an observed lock wait.
- `Transaction::begin_nonmember` (`authorization.rs:132`) is reachable from any `storage` module; "only from `admission.rs`" is a convention. A comment at the definition is enough.

## Claims I tried to refute and could not

1. **`VerifiedNonmember` and `TrustedRequest` cannot be built outside `storage`.** Fields are `pub(super)`, no constructor, `Default`, `Clone` or `Deserialize` exists, and the only constructions are in `#[cfg(test)]` modules. The compile probe shows the doctests are not vacuous (the import resolves, the literal fails E0451).
2. **The nonmember entry cannot gain member authority.** `begin_nonmember` requires the workspace pool and installs a blank principal and epoch (`authorization.rs:132-135`); `precheck` and `fence` call `member()` first and return `Denied` without a request (`:159-161,189-190,234-235`), so no `Permit` can be produced; `lock_member_authority` and `advance_member_epoch` would refuse the blank GUCs anyway; the only non-definer SQL on that path is the scoped binding read (`admission.rs:221-228`).
3. **Entitlement precheck/fence races.** Precheck and fence both require `status='active' AND expires_at>clock_timestamp()`; the fence re-reads after taking the member `FOR SHARE`, and the operator's entitlement revocation takes the member `FOR UPDATE` and advances the epoch before its event, so both orders resolve at the fence (campaign checks 11, 12, 14 reproduced locally and in CI). Code revocation leaves an admitted member's entitlement active (check 13).
4. **Operator command.** Identity (`session_user = current_user = genui_migration`, database `genui`) is checked before any read beyond `SHOW` (R6); the reviewed latest catalog is proved before any write (R8 positive control); `sslmode=verify-full` with a required CA file; `SET LOCAL ROLE genui_owner` with FORCE RLS and explicit `genui.organization_id`; lock orders org → code or member → operator head match D7.1 and cannot cycle with the admission functions (different head rows); the secret is produced only from `issue`'s return value after `COMMIT`; every refusal is a fixed code (argparse's `error` is overridden and inherited by the subparsers); no logging, no value echo.
5. **Operator audit chain.** `append` follows D7.8 (head `FOR UPDATE`, sequence + 1, `previous_hash = head_hash`, domain-separated SHA-256 over sorted-key canonical bytes with whole-second UTC `occurred_at`), byte-compatible with the SQL bodies; `verify` recomputes from the genesis formula, checks sequence continuity, tail = head and the m5 redemption set; the tamper positive control fails as expected (operator test). Only the concurrency false alarm (m1) was found.
6. **SQLSTATE containment.** `query_classified` exists only on the `pub(super)` `Transaction`; the public surface returns `storage::Error` (five variants, fixed text) or typed outcomes.
7. **0003 review fixes landed.** M1 (`0003:363-377`, schema campaign three cases, count 4), M2 (`0003:383-386`, race case 4), m1 (`admission.rs:387-407`, campaign check 20), m2 (`0003:187`), m3 (`0003:268-270,326-329`, `admission.rs:221-228`, campaign check 21), m5 (`admission_operator.py:493-497`, schema campaign), m6 (`schema-0003/README.md` header, choices count, observations). m4 is M2 here; m7 was record-only.
8. **CI step.** Exact test name with `--exact`, one test passed on `581fd57`, report path under the uploaded artifact directory, report carries no code; runs after the native campaign in the same venv, inside the time limit.

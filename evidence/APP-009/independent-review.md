## Findings

### Blockers

None.

### Major

**M1 — The sign-in page's CSP `form-action 'self'` blocks the `POST /signin/{handle}` → `303 {auth_origin}/t/{slug}/auth/authorize` hand-off in Chromium and WebKit.** Observed header on `GET /signin` from the built binary: `Content-Security-Policy: … form-action 'self'; …` (forma-server's strict default, `forma-server-3.2.0/src/csp.rs:137`). Chromium and WebKit evaluate `form-action` against every response in a form submission's redirect chain, so the cross-origin `Location` of `app/src/auth/routes.rs:173` is refused ("Refused to send form data to … because it violates … form-action 'self'"); Firefox does not enforce it on redirects. The local campaign cannot see this: it drives the router in-process and never renders the SSR page in a browser. Nothing in ADR-006 or the design pins this directive for the sign-in page; design TH25 pins `frame-ancestors 'none'`, which stays. Fix (one place): render the sign-in page with the auth origin added to `form-action` — in `app/src/main.rs:74-86` give `SsrPages` the configured `auth_origin` and use `RenderCtx::new().with_title("Sign in").with_policy(PolicyExtensions::new().form_action(auth_origin))` (`forma_server::PolicyExtensions::form_action`, `csp.rs:348-352`, whose own doc example is exactly an IdP origin); leave the pending, denied and workspace pages at `'self'`. Add the directive to `auth_pages_render_typed_props_without_javascript` and have APP-074's Chrome/Safari run confirm the hand-off with the console open. If the auth origin is unknown at render (no `GENUI_AUTH_CONFIG_FILE`), keep `'self'`: the POST fails neutrally anyway.

### Minor

**m1 — A new arrival does not supersede the browser's existing workspace session (P4, P5).** `callback()` (`routes.rs:346-356`) destroys the browser's earlier *pre-access* record but ignores an existing `__Host-genui_session`: a Pending or Denied arrival leaves the earlier session cookie live (two identities in one browser; `/workspace` answers as A while `/auth/pending` answers as B), and a Workspace arrival replaces the cookie but leaves the earlier row and its vault entry live until the idle hour or sweep. No cross-user boundary is crossed (the browser legitimately held both cookies; login CSRF needs the pre-login cookie), so this is session hygiene, not a hole. Fix: read `cookies::SESSION` beside `PRE_ACCESS` at `routes.rs:348`; on any `Ok(arrival)` call `stores.workspace.sign_out(&earlier_session)` (advancing the epoch, as a sign-out does) and `auth.revoke`, and add `cookies::clear(cookies::SESSION)` to the Pending and Denied responses (`routes.rs:358-376`). Extend campaign check 6 with "a second sign-in in the same browser ends the first session".

**m2 — `/signin/{handle}` path-extractor rejections bypass the uniform contract (H1).** `Path<String>` (`routes.rs:88,151`) rejects invalid percent-encoding with axum's plain-text `400 Invalid URL: Invalid UTF-8 in \`handle\`` without `no-store`, `nosniff` or `application/problem+json` (D7.15; ADR-006 "uniform neutral failure"). Anonymous page, nothing disclosed beyond the framework. Fix: take `path: Result<Path<String>, axum::extract::rejection::PathRejection>` (or `RawPathParams`) and answer `neutral_failure`/`not_found()` on `Err`; add `/signin/%ff` to `anonymous_routes_refusals_and_release_router_without_harness`.

**m3 — `Auth::origin()` returns `""` when no provider is configured, and an empty `Origin:` header matches it (H2).** `csrf::same_origin` (`csrf.rs:18-19`) compares bytes, so `Origin:` (empty) with no `Sec-Fetch-Site` passes when `auth.origin()` is `""` (`mod.rs:335-340`). Browsers never send an empty `Origin` and the configured production origin is non-empty, so no browser CSRF results, and the cookie-tied tokens still guard the session forms; it is a latent sentinel bug. Fix: `matches!(origins.as_slice(), [value] if !origin.is_empty() && value.as_bytes() == origin.as_bytes())`, and a unit case with `origin = ""`.

**m4 — Limiter keys are retained 24 h regardless of their windows, so the fail-closed `MAX_KEYS` refusal outlives the sign-in windows (L1).** `limits.rs:88-98` prunes only entries whose last event is older than 86,400 s, while `SIGNIN_ADDRESS` windows are 60 s and 3,600 s; once 20,000 keys exist every *new* address class is refused with 429 for up to 24 h. Not reachable through sign-in alone: refusals record nothing and the 600/hour global window caps new keys at 14,400 per 24 h; resend keys need a provider login each. Defense in depth: keep the longest configured window per key (store `keep` beside the `VecDeque`, or prune with `max(window.period)` of that key's windows) so the retention equals the budget.

**m5 — Vault entries have no time bound; a cancelled callback leaks one.** `arrive()` inserts the vault entry (`routes.rs:271`) before `mint_pre_access` commits (`routes.rs:280-292`); the 5 s `http::deadline` or a client disconnect drops the future inside that window and the entry is then referenced by no row, so no path removes it until a restart (`vault.rs` has no TTL or sweep). `MAX_ENTRIES` is 10,000, after which every sign-in fails. Rare per event, unbounded over a long-lived task. Fix: record `created_at` in `Tokens` and have `Auth::sweep()` (`mod.rs:356`) drop entries older than `SESSION_ABSOLUTE_SECONDS`; the row-referenced entries are always younger than that.

**m6 — `runtime.py serve` still injects `GENUI_AUTH_QUALIFICATION_CONFIG_JSON` as a file and sets `GENUI_AUTH_QUALIFICATION_CONFIG_FILE` on the child (`app/runtime/runtime.py:50-66,570-581`), which the release binary now refuses before binding.** Setting that variable on the managed task therefore produces a terminal crash loop rather than a harness; the qualification image runs the `cargo test` executable, not `runtime.py serve`, so the path serves nothing. Fix: remove `take_qualification_json`/`QualificationFile` from `serve` and refuse the variable with a fixed reason (`smoke_supervisor.py` already expects the refusal). Open question 6, judged below.

**m7 — `evidence/APP-009/README.md` carries pre-merge counts.** `catalog-v6` `14ef47cf…` (now `2db0b8db…`), schema campaign 334 (now 341), `SOURCES` 47 (now 57), lib tests 77 (now 82). One amendment paragraph citing `9a1e8c4` keeps the record truthful.

### Nits

**n1** — The denied (403) and neutral-failure (400) pages are served at `/auth/callback?code=…&state=…`; a reload re-submits the consumed code and lands on the neutral failure, and the consumed code stays in history. Harmless (single-use, already exchanged or refused); a `303 /auth/denied` would need an ADR-006 route amendment, so leave it unless the UX bothers.

**n2** — `sweep_expired` (`sessions.rs:822-841`) iterates `registry.organizations()`; rows of an organization later dropped from the registry are never swept. They are dead anyway (`registry.agrees` fails at every resolve), so this is storage hygiene only; `SELECT DISTINCT organization_id` from the three relations under the migration identity, or an operator cleanup, closes it.

**n3** — Cookie values are `base64url(organization ‖ 32 random bytes)` (decision 1), so the HttpOnly value discloses the organization UUID to its holder; ADR-006 says "opaque random identifiers of at least 128 bits". The 256 random bits and digest-only storage keep the security property (campaign 9, probe P9), but ADR-006 §Principals should record the prefix as the D7.5 scope selector.

## Open-question judgments

1. **Pending lookup (D7.3).** Closed by `4433246`: the ADR-007 amendment's column list equals `0006_sessions.sql:113-114` exactly (no `code_id`, no context digest, no write), the schema campaign asserts it column by column, and consumption stays inside `admit_redemption`. Agree with the column grant over a seventh definer: it reads only the identity's own rows under RLS and keeps the definer set at six.
2. **Refresh-token reference vs the plan's `refresh_token_ciphertext bytea`.** The reference is correct. ADR-006 §Storage consequences ("storing only a reference to a process-memory-encrypted value") and D7.11 ("referenced from the session row") both say reference, and ADR-007's preamble makes the ADR control over the plan where they differ. The plan's Task 7 line should be corrected to `refresh_token_ref uuid`.
3. **A restart signs every member out.** Consistent with D7.18 ("a brief outage that signs every member out, accepted … recorded as a limitation") and D7.11; it also guarantees that no live GenUI session exists without its provider-logout capability. Campaign 15 shows the orphaned provider refresh tokens remain refreshable until fAuth's own idle timeout, which ADR-006 accepts ("fAuth's own 30-minute idle timeout bounds any orphaned token"). Accept; no change.
4. **Sign-out scope: sessions use the current epoch, so signing out one browser leaves the others alive.** Consistent with ADR-006, whose rows distinguish `POST /auth/signout` ("deletes the GenUI session record") from `POST /auth/signout-all` ("deletes every GenUI session of the identity") while both advance the epoch; binding sessions to `membership_epoch_at_mint` would make the two routes identical. Probes P1–P3 show the advance fences in-flight authority without disturbing the other sessions' reads. Recommend one sentence in ADR-006 §Principals: the membership epoch fences in-flight work and is not a session validity input; sessions end through expiry, deletion, membership or organization status, entitlement and registry checks. `membership_epoch_at_mint` stays informational.
5. **Delivery of `GENUI_AUTH_CONFIG_FILE` to the managed task.** Out of APP-009's scope and correctly deferred: the same private-file channel as `GENUI_IDENTITY_REGISTRY_FILE` (APP-076/078). `runtime.py serve` passes the environment through (`os.environ.copy()`), `AuthConfig::load` enforces the same 0600/0700/no-link rules as the registry, and without the file the binary stays neutral (observed: `POST /signin/{handle}` → 400 neutral, protected routes 404).
6. **`runtime.py` injection path.** Remove it (m6). Keeping it for a feature-built executable buys nothing: the qualification image executes the test binary directly, and in the product image the path can only crash-loop the task.
7. **Page status codes.** 400 for the neutral sign-in failure and 403 for the denial are reasonable and disclose nothing across users (the identity learns only its own standing); pin both in ADR-006's routes table in one line so APP-074's browser checks have a target. Optional: a `303 /auth/denied` route (n1).
8. **`VerifiedIdentity` has public fields, so storage trusts its caller.** Not exploitable from outside the process: `mint_pre_access` also needs a `FlowRecord`, which only `complete_flow` constructs from a consumed, state-matched flow, and the only production caller is `arrive()` after `Verifier::verify` with the registry's expected tenant. The exposure is a future internal misuse. Low-priority request to the APP-006 owner: make the fields private with getters, or return a sealed newtype from `verify`; the storage concurrency check (campaign 14) would then construct identities through a `#[cfg(test)]` constructor.

## Claims I tried to refute and could not

- **State/PKCE/code replay and mix-up.** Delete-first single-use flow (`complete_flow`), constant-time state digest compare, cross-tenant code refused by PKCE and tenant (P6), concurrent duplicate callbacks mint once (P7), replay never reaches the token endpoint (campaign 7).
- **Cookie forgery, fixation and cross-organization re-scoping.** 256 random bits, digest-only storage per domain (`forma:*-cookie:v1`), the organization prefix only selects RLS scope; a re-scoped or cross-domain value finds nothing (campaign 9, P9); duplicate, oversize or non-token cookie headers are no cookie (H3).
- **A pre-access session reaching a workspace route or minting without verification/membership/entitlement.** `PreAccess` has no conversion (compile-fail doctest), `mint_session` requires `email_verified`, registry agreement, the member fence, the active entitlement, the active binding and the pre-access row consumed `RETURNING` exactly one (campaign 13, 14).
- **Epoch handling.** Revocation mid-session (P8, campaign 14), sign-out racing a request (P2), two concurrent sign-outs and sign-out-all racing sign-out (P1, P3): no deadlock, correct counts.
- **CSRF.** Fetch metadata or exact Origin on every POST, anonymous forms included; per-form HMAC tokens tied to the cookie value and process key (campaign 10, restart in 15); `Sec-Fetch-Site: none`, duplicate headers, `null` Origin refused (H3, unit tests).
- **Open redirects.** Every `303` target is constant or built from the configured auth origin plus a validated `urn:…request_uri:` suffix; the routing-hint handle is shape-checked and must resolve to the same organization before it names a redirect (campaign 12).
- **Handle enumeration and timing.** Handles are 128-bit random; `GET` pages are identical with no lookup; `POST` differs only for an existing handle, which the ADR accepts as non-secret routing.
- **Uniform 404.** Protected, unknown, method-mismatched and harness paths answer the same body and headers (H3, campaign 4).
- **Body limits and deadline.** 4 KiB → 413 before any hashing or storage; 5 s middleware on every route.
- **Trusted proxy.** Rightmost `X-Forwarded-For` hop, unparseable hop → `unknown` class; the known limit (direct connections can choose their class) stands until APP-074.
- **Log and telemetry leakage.** Every `tracing` field is a fixed enum, a code or an epoch; `Token`, `FlowStart`, `FlowRecord`, `PreAccess`, `AdmittedMember` and `VerifiedIdentity` redact `Debug`; no request URI, cookie, code, state or token appears in a log line; campaign 17 finds no issued capability in 149 responses outside the authorize redirect.
- **Harness and loopback absence.** `#![cfg(feature = "qualification-harness")]`, release refusal before binding (re-run), `cargo tree -e normal` shows the verifier with no features in the release graph; `Client::loopback`, `Auth::loopback` and the synthetic issuer are `cfg(test)`.
- **`TrustedRequest` constructible only in `storage/sessions.rs`.** Fields are `pub(super)`; every other constructor is in a `#[cfg(test)]` qualification module; the compile-fail doctest guards the public API.

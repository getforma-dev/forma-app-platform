### Minor

- **m1 (names, W1's file).** `directory::usable_name` (`directory.rs:103-108`) rejects control characters (Cc) but admits Unicode format characters (Cf: U+200B zero-width space, U+202A–U+202E and U+2066–U+2069 bidi controls). A member can take a name that visually impersonates another in the admin table, share lists, Ask and Slack. Not XSS: escaping is proven (`main.rs` SSR tests: `Ana &lt;b&gt;bold&lt;/b&gt;`, `value="Ana &lt;María&gt;"`; `slack/text.rs:11` and `fields` escape label and value; no `innerHTML` sink in `app/admin/src`). Reject Cf and require one alphanumeric character. Route to W1.
- **m2 (UX).** `POST /me/name` answers 422 `invalid_name` as `problem+json` to a plain form post (`member_name.rs:112`). A browser that gets past `required`/`maxLength`/`pattern` (a pasted control character does) shows raw JSON. A `303 /canvas?notice=invalid_name` from a closed set, as `/admin` does, would match.
- **m3 (coverage).** `org_admin_routes_campaign.rs` has one organization, so APP-183's "a member of another organization" case is not exercised at the route layer. The session binds the organization (`is_org_admin` judges the request's own org) and W1's `org_admin_campaign.rs:312` covers it in storage, so the risk is low. Add the case or state the split in the ticket.
- **m4 (comment vs value).** `limits.rs:52-55` says "a room of 25 fits" for `LOOKUP_FAILURE_ADDRESS`, whose minute window is 15. It counts only `Lookup::Absent` and unregistered-organization cookies (`auth/routes.rs:148-150`, `:637-639`); an ended session after the Nov 28 restart is `Lookup::Ended` (uncounted), and `/canvas` never uses this window. Safe for the class; fix the comment or raise the minute window to the sign-in minute window.
- **m5 (cosmetic).** `/admin` offers Remove on the admin's own row (`org_admin.rs:420`); storage refuses it as `self` and the page explains. `removable` could also exclude `mine`.

## Answers to the review questions

- **Authorization.** `GET /admin`: session (uniform 404) → `?notice=` from a closed set (else 404, `org_admin.rs:89-97`) → `is_org_admin` → overview (`:245-252`). Non-admin, `Denied` and signed-out all get the uniform 404 before any member read (test `:605-619`; campaign checks 1–2, byte-identical to an unknown path). `POST .../remove`: same-origin (`csrf.rs:13`, the codebase's order) → session → path id → `is_org_admin` → 4 KiB form of exactly `csrf` + at most one `confirm` → token bound to form and cookie (`:320-327`) → storage, which re-fences `admin_policy` (`storage/org_admin.rs:162-165`). Nobody can set another member's name: `set_display_name(request, name)` takes no principal (`storage/org_admin.rs:198`), and the form accepts exactly `csrf` + `name` (`member_name.rs:94`). The remove outcome is honest: `self`/`last_admin`/`not_member` become plain notices, an unknown outcome is `Error::Unavailable` → 503 (`storage/org_admin.rs:173`), `Denied` → 404; a removed member's next request on `/canvas`, `/admin` and `/me/name` is 404 (campaign check 4).
- **The cap.** One `OnceLock` static (`model.rs:110-121`); every `Anthropic::new` binds it (`:319`) and only `cfg(test)` can swap it (`:324`). The five production clients (composer ×2, parser, customizer in `main.rs:289-328`; Slack's parser `slack/mod.rs:173`) all go through `Anthropic::from_env`; `x-api-key` appears nowhere else. `admit` runs inside `send` (complete, complete_with_image) and `complete_with_documents` before any HTTP (`:487`, `:573`); a call's retries share one slot (test `:846-891`). Midnight is UNIX-day arithmetic (`:88-99`, tested at 2026-11-30T00:00Z); a backward clock keeps the latest day; a forward jump resets early, bounded to one extra day. The count is in-process, so a restart resets it: acceptable under ADR-007 D7.18 (one task) with the Anthropic monthly limits behind it (D10). The 429 carries `Retry-After` to midnight (`:140-147`); the text says "your apps and entries keep working" (`model.rs:136`, `daily-limit.ts:5`, `daily-limit.test.ts`). Mapping is consistent across compose, Ask, Shape, customize, act (words and receipt), assistant, folder ask/explain/apps/brief, MCP and Slack; the one gap is M3.
- **The limits.** `POST /signin/{handle}` is a PAR start toward fAuth, so 40/min and 150/hour per address guess no code. Invite validation keeps 5/min per address (fAuth's burst) and goes 20 → 100/day per address; the 200/day global and the digest lookup stand, so code guessing is unchanged per minute and still negligible per day. Callback = sign-in + invite (45/min, 250/hour). The test pins all four values (`limits.rs:312-320`) and the auth tests derive their budgets from the constants (`482bdd52`). Operational dependency: 25 codes redeemed in one classroom minute would 429 at 5/min, which is why the code email must say "redeem at home" (go/no-go item 6).
- **The canvas reads.** `member_facts` (`canvas.rs:1665-1680`) runs the two fenced reads with `tokio::join!` and maps either failure to no Admin link and no prompt, logged at info. `asks_for_name(stored, known)` (`member_name.rs:37`) takes `known` from `directory::display_name` (`canvas.rs:1836-1839`), which returns the member's own cached name or, only when `demo::is_demo_org`, the DS-44 persona (`directory.rs:190-199`). Outside demo organizations the only suppression is the member's own stored name.
- **Tests.** Unit tests prove the order, the token binding, the closed notice set, the cap arithmetic and the 429; the SSR tests prove escaping and no script; the routes campaign proves the four route rules over real rows; the composer campaign's D10 phase proves router-then-refused with nothing sent and no row. D10 phases for actions, box, MCP, Slack and pitch exist (`actions_campaign.rs:2074`, `box_campaign.rs:1703`, `mcp_campaign.rs:1169`, `slack_campaign.rs:1158`, `pitch_qualification.rs:2706`); I did not run those five. Break proofs: M1.

The acceptance's own scenario is cross-member: a teammate sees another member's agent commit. ## Limits

- **When the chip appears:** the chip with tool and duration is drawn only with timings on, and only for a live new version (`showActivity` returns unless `on`; `renderRecords` needs a previous version). The always-visible "via" chip carries the call only in its title.
- **Matching edge cases (display only):** if one token commits two versions of a record in the same second, both show the first call's duration. A replayed `forma_commit` can match only if it is the first `forma_commit` in that second.
- **What the tests cannot catch:** the campaign's `via_tool == "forma_commit"` holds once any commit row matches, and `via_ms` is checked only by range. A wrong match among several commits would pass. The `records.ts` wiring has no direct test.
- **Query cost:** the lateral lookup scans the token's access-log history per attributed record; the only index is `(organization_id, token_id, chain_sequence)`. That is fine at current volumes. An index on `(organization_id, token_id, tool, occurred_at)` is the fix if a busy token makes it slow; a new migration needs its own release.

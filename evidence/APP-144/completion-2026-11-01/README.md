## Result

The member document at `/w/{app}/{work}` now reads every admitted part and its `default_layout`: notes, each exact declared form, summary/status/detail pairs, tables/filters, and qualified charts/timelines. Parts retain declared row/column order through native HTML and live updates. Finite renderer-owned grid classes replace arbitrary layout strings. Empty row gaps compact; overlapping placements flow to a new row so controls cannot cover each other. Narrow screens stack in reading order. A part outside the existing query engine's qualified scope stays visible with an explicit unavailable state; no query or result is invented.

Source views run with admitted defaults on initial entry, or restore a valid work/session-bound run cookie. The global window is optional but must be complete, and controls only appear where the source fields support them. Money and decimals remain exact formatted values with raw value strings and receipts. The current chart primitive plots qualified integer results; other shapes retain exact tables instead of a misleading plot.

Each form names its admitted command. Update forms select an actual current record with a closed, CSRF-protected POST body; ordinary create forms receive a new record identity. The legacy transition-style create command can select an existing record or create a new one. Fresh form detail must match the listing's publication, definition, work version and write permission. The whole document is reauthorized after query execution. No authority or audited-command rules changed.

The generated Reading List issue is fixed in form metadata: the first unconditional initial enum rule narrows a new field to its declared value, while retaining the full original schema and backend command rules. Guarded rules are not guessed from an empty draft. Existing records retain their current value, including a later enum option in native HTML.

Live updates retain unsent form nodes and command identity. Uncertain outcomes freeze their payload for same-key replay. Selector changes are generation-bound, and an accepted refresh rebuilds the selection map so a removed form cannot leave a stale selector that breaks future reads. Contextual Ask uses the separate APP-143 lightweight adapter; source queries/static notes receive an explicit unsupported-scope message rather than unrelated record answers.

Shared recipients and connected-app placements now use the same ordered layout and released query cards, projected to a narrower read-only type. Notes, chart/table content and form labels remain in place. The shared type carries no command action, form fields, record selector, member route or Ask context. Existing guest access release and the five-second authority monitor remain unchanged. This is rendering parity, not a grant or guest-write change.

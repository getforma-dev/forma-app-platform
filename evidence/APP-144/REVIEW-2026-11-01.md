# APP-144 bounded document implementation — November 1, 2026

Branch `codex/app-144-document`, isolated worktree `forma-app144-review`, based on the reviewed pivot integration `d49ab483`. No deployment, migration, new grants, or owner-port use. Local browser stand used ports 8801–8803. Every dependency and build output came from this worktree's `just setup`; no borrowed runtime/build directories.

## Implemented and reviewed

- The existing `/w/{app}/{work}` serves native HTML containing admitted create forms, current record tables/provenance, and its existing source-query views/receipts. The united canvas header links to it; the document links back to that work on the canvas.
- `Data::work_reads` provides outline/records under one authorization and pin. Each form comes from a fresh `read_record_detail`/`commands::view`; mismatched publication, definition, work version, or write permission fails assembly. After all potentially long query runs, the entire document is reauthorized and its pin checked before either HTML or JSON is released. Denial is the uniform 404.
- The same GET with `Accept: application/json` returns typed, snake_case props, `Vary: Accept`, and `no-store`. There is no new read or write address. Native HTML retains the complete PageResponse and Trusted Types/CSP; live updates build a closed DOM vocabulary with `createElement` and text, never parse HTML or accept model markup.
- The small registered enhancement uses the existing audited command/idempotency transport and existing session event stream. Only exact-work hints, lag/reconnect, browser-online, visibility, manual refresh, and a 30-second visible-page fallback trigger reauthorized reads. Unsent forms keep their nodes, values, and server-minted keys. Successful submissions replace only their own form after a fresh read. Uncertain submissions freeze their original payload for same-key recovery. A denied read removes all app records/forms; loss of write permission or revision invalidates the form while retaining the draft.
- Isolating the shared UUID validator removes an accidental live-module import of the canvas implementation. The final document bundle is 33,392 bytes gzip, below the standard 75 KiB page budget; it is not declared a heavy canvas route.

Backend and frontend source were independently reviewed by the shell/create agents and parent reviewer. Review fixes covered delivery-time revocation, form-refresh races, uncertain payload edits, obsolete write controls, and persisted-page recovery.

## Remaining APP-144 acceptance

The ticket remains **Backlog**. This slice uses the existing qualified source-view outline and admitted collection helpers. It does **not** yet render the full `default_layout`, interleave every declared form/view/note/status, or cover every additional renderer primitive. Those require an explicit general document model and additional qualification. Existing native no-JavaScript record submission still falls back to the record page; the in-place outcome behavior is provided by the enhancement. The record listing is bounded and truthfully reports truncation. Source views retain the existing explicit query-run form and run-cookie behavior.

Existing-member access is retained; no anonymous page, permission expansion, or share/invite/onboarding journey is introduced. APP-139 and predecessor gates remain separate. CSV/XLSX ingestion was not exercised in this stand; a sealed parser was not built for this document-only verification.

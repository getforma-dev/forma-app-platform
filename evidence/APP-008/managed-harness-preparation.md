## Proposed coordinator: existing database, no control service

Use **run-scoped session advisory-lock phase beacons plus actual PostgreSQL lock observations**, with a fixed finite state machine. This is a proposal requiring slice3's local proof, not an implemented protocol. Both actors must be running, armed and idle before a timed transaction begins. A canonical run UUID and fixed case/phase numbers derive bounded advisory keys; reject a pre-existing/conflicting owner. Beacons convey readiness/phase only, never SQL, credentials, permissions or a successful case result.

The application actor reserves one lease from the existing workspace pool for coordination; the tested data transaction uses its own normal lease. The operator actor uses two bounded migration connections: one writer and one observer. Observe the expected backend relationship with `pg_blocking_pids`/`pg_locks`, matched to the privately retained actor/backend identities. A sleep or an ECS task launch is not proof of contention. The application-first case holds its real authority fence while the writer is observed blocked; the writer-first case commits the changed epoch/state before the waiting application's fence resumes. Apply the ADR's organization→membership→work writer ordering and the existing nonfinal-precheck/final-fence distinction.

The native author confirmed these constraints: the reserved workspace lease leaves one of that role's two slots; the total application transport cap stays eight; acquisition still has its five-second absolute deadline. Release coordination before the full-capacity batch. Operator connections are separate test infrastructure and must be counted explicitly. Never extend a three-second application transaction for remote coordination. Poll only inside a short case deadline; absence/loss of a beacon, connection loss, unexpected owner or timeout aborts the case. `DISCARD ALL` and disconnect remove session beacons, so disappearance cannot mean success. Finally rollback/close both actors and verify owned locks/transports are gone.

Advisory keys are not an authorization boundary. A conflicting actor may cause a refusal, never grant access or select a mutation. Every actor executes only its pre-reviewed named case and still verifies current database facts. No permanent coordination table, application DML grant, extra network listener, S3 message channel or new IAM permission is proposed.

## Packaging and unresolved decisions

The qualification supervisor should reuse `runtime.refresh/load/atomic_write` with the existing task-local0700 directory and0600 credential format, supervising one exact test executable and refreshing until it exits. `runtime.serve` launches the service without test-selector arguments and is not the qualification supervisor. Keep the application task free of the migration password; keep the operator task free of application role-assumption grants. Combining both actors in one Fargate task would share its task/execution identities and defeat that separation.

Bake the reviewed harness into a distinct immutable image rather than shipping a large executable/script through ECS overrides. The recent [schema-one preflight](../APP-006/hosted-callback/schema-one-sequence/sql-preflight/README.md) demonstrates both constraints: the complete override must fit8,192 bytes, and `entryPoint` must match the selected command. Its compact script is a packaging example, not the schema-two runner. There is no new dependency selection needed for slice1.

Before slice3 is considered ready, resolve and prove: bounded cross-process phase timing under the existing transaction deadlines; actual visibility of needed lock/actor facts under the approved RDS roles; exact operator seed package/validator paths; recovery for a partially completed fixture mutation; and the concrete target for managed catalog-drift trials. Do not weaken catalog normalization or add privileged grants to make a trial pass. Fresh budget, task-time, image/task/registry pins, snapshot/restore/cutover compatibility and future stop scheduling remain root-owned launch work. No dated reserve or expired schedule is reused by this preparation.

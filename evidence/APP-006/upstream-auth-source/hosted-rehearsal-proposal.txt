# FORMA-247/248 — proposed hosted rehearsal

Prepared 2026-10-28. **No resources have been created or restored.** This is a bounded synthetic test proposal following Victor's deletion of the unused GateWasm environment. The source and local evidence can be reviewed independently. Hosted acceptance remains open.

## Proposed window and owner

- One FormaStack operator, Codex `/root`, with GenUI coordinating its callback and integration check. No concurrent deployment/rotation operator.
- One six-hour window in `us-east-1`, including provisioning, a real one-hour next-key publication interval, rotation/expiry checks and teardown.
- Proposed operating budget: **$5**, with expected low-traffic resource charges below $1 and a conservative $2 planning allowance for logs, image storage, requests and deployment overhead. This is an operator stop budget, not an AWS-enforced hard billing cap; usage/billing reports can lag.
- Synthetic Northstar/canary users only. Do not admit a real organization during this rehearsal.
- Approval must include the exact GenUI public origin and OAuth callback, the start window, the spending limit and cleanup of the newly created rehearsal resources. These inputs have been requested and remain pending.

Set `gatewasm:staging:kmsKeyring` to the reviewed manifest before synthesis; no file-key branch may be selected. The deleted production environment stays deleted. AWS allows existing App Runner customers to create new resources despite closing to new customers. The actual account's historical `GatewasmServiceStack` was created on 2026-03-04 and is now `DELETE_COMPLETE`; a fresh `ListServices` read returned an empty list. This supports existing-customer eligibility, but it is not proof that a future `CreateService` call will succeed. If creation is denied, stop and report the provider result; do not silently introduce a different hosting architecture. See [AWS availability policy](https://docs.aws.amazon.com/apprunner/latest/dg/apprunner-availability-change.html) and `app-runner-eligibility-readonly.json`.

The deployment consists of one private Single-AZ PostgreSQL `db.t4g.micro` with 20 GB GP3, one `t4g.nano` NAT instance and public IPv4 address, and App Runner 0.25 vCPU/0.5 GB with minimum one and maximum two containers. Runtime image deployment is explicit; automatic deploys are disabled. New KMS keys provide current, next and dedicated SSF signing; promotion adds a new next key while retaining the previous access key. All signing keys are AWS-generated `ECC_NIST_EDWARDS25519`, `SIGN_VERIFY`, with immutable ARNs. No file signing key is restored or granted to the service role.

Create fresh rehearsal app/management secrets rather than restoring every deleted production secret. Use email-only tenant configuration; external OAuth provider secrets can contain empty provider values and no provider login is enabled. SMTP and MFA secrets are omitted for this explicit synthetic scope. Passwords and platform/tenant management values enter the approved secret environment without command-line arguments or evidence logging. The runtime role receives only exact referenced secrets; the operator's provisioning/rotation role receives only the rehearsal prefix.

## Cost model

The following estimates assume six hours, up to two continuously active App Runner containers, 20 GB database storage, four KMS keys during rotation and eight small managed secrets. Taxes, unexpected external traffic and retained resources are not included.

| Item | Verified rate | Six-hour estimate |
|---|---:|---:|
| App Runner, two at maximum size | 2 × (0.25 × $0.064 + 0.5 × $0.007) / hour | $0.234 |
| PostgreSQL instance | $0.016 / hour | $0.096 |
| NAT instance | $0.0042 / hour | $0.0252 |
| One public IPv4 | $0.005 / hour | $0.030 |
| 20 GB RDS GP3 | $0.115 / GB-month | about $0.019 |
| Four KMS keys | $1 / key-month, prorated hourly | about $0.033 |
| Eight secrets | $0.40 / secret-month, prorated hourly | about $0.027 |
| 10,000 asymmetric KMS requests (allowance) | $0.15 / 10,000 | $0.150 |

Subtotal is about **$0.72**, before NAT disk, logs/alarms, registry storage, DNS and transfer. The $2 planning allowance is intentionally above this low-volume subtotal; the proposed $5 authorization is not a promise of a hard cloud spending stop. RDS/EC2/KMS price API responses are retained in `rds-pricing.json`, `ec2-pricing.json`, `rds-storage-pricing.json`, and `kms-pricing.json`. Public provider references: [App Runner pricing](https://aws.amazon.com/apprunner/pricing/), [KMS pricing](https://aws.amazon.com/kms/pricing/), [Secrets Manager pricing](https://aws.amazon.com/secrets-manager/pricing/), [IPv4 pricing](https://aws.amazon.com/vpc/pricing/). No free-tier credit is assumed for asymmetric signing.

# APP-006 local hosted-callback preparation

This is an operator-gated, identity-only qualification harness in the real native GenUI HTTP service. It creates no app principal, membership, entitlement, workspace session or protected work. APP-006 stays Blocked for its remaining hosted/integration acceptance. APP-009/073/074, real-mail activation and public beta readiness are not implemented or passed here.

The production callback imports `genui-auth-verifier` directly from `spikes/APP-006`; its implementation is not copied. The production constructor always selects the canonical HTTPS/access-only verifier. The private `IdentityCheck` interface has a `cfg(test)` fixture only in the test module; no runtime option, config field or public insecure constructor can select it.

## Operator API

All endpoints below exist only when the explicit private qualification configuration is supplied at startup. The exact receiving callback remains `https://beta.getforma.dev/auth/callback`.

1. The operator's test runner sends **POST `/auth/qualification/start`**, with an empty body and `Authorization: Bearer <operator_token>`. No query/body fields are accepted. There is no caller-selected tenant, client, role, callback or invitation. The server generates fresh state, PKCE verifier and browser-binding cookie. It returns **303** with a provider authorize `Location` and `__Host-genui-qualification` cookie, `Path=/; Secure; HttpOnly; SameSite=Lax; Max-Age=300`.
2. Use a browser context's Node-side API request with redirects disabled, sharing that context's cookie store. Read the 303 Location privately and navigate the same browser to it. The operator credential goes only in the Node-side request header to the exact GenUI start/status endpoint, never a global browser extra-header setting. Do not print/store the authorize URL, cookie or response headers in a public receipt. For invited signup, the browser URL contains only the client ID and bounded PAR request URI; the invitation and verifier stay on GenUI's backend.
3. The actual provider redirects the browser to **GET `/auth/callback?code=…&state=…`**. GenUI checks canonical query shape and its cookie, removes the pending flow before exchange, verifies state/expiry and performs the backend exchange. A matching-cookie, valid-shape continuation is consumed even when its state fails or the provider later fails. Malformed queries are refused before state lookup. Repeated or concurrent consumed continuations cannot exchange again. HEAD is refused. The browser receives **303** to the fixed clean `/auth/qualification/result`, and the qualification cookie is cleared.
4. The result is a fixed neutral text page: it does not expose identity, a success grant or a provider error. The authorized runner reads **GET `/auth/qualification/status`**, with the same operator Authorization header and no body/query, to obtain the actual outcome. The response has a configured shared run ID, external fAuth tenant/client/issuer, declared source pins, counters and at most twelve exchange receipts. A receipt contains its local attempt number, completion time, verified subject when available, separate mailbox boolean, qualification outcome and logout acknowledgement. It contains no email, roles, invitation, state, PKCE verifier, code, token or cookie. No endpoint accepts credentials from a URL.

The source pins in the receipt are explicitly **configured** pins. They require independent deployed source/image/health receipts and are not runtime attestation. The current reviewed provider source is `dfba787295b880816fd95295b507a4527c51e62f`, PR19 merge `4d70f198546cc7a009512244c2009e814ccc5f12`; [the retained auth-team contract](../upstream-auth-source/GENUI-IDENTITY-CONTRACT-2026-10-28.md) supplies the actual provider semantics.

## Private configuration and limits

Absent `GENUI_AUTH_QUALIFICATION_CONFIG_FILE`, every harness route is absent. An invalid/empty configured value or invalid file stops startup. The file is read once, with an absolute path, regular file/no final symlink, current process ownership, no group/other permission and maximum 8 KiB. Its immediate directory must have current process ownership and no group/other permission. In the local image, the process UID is 65532: provision a separate 0600 file in a 0700 owned directory, such as `/run/genui/qualification.json`. The existing runtime credential generator does **not** create this file. Root owns any later secret-store/task wiring; none is deployed here.

The JSON object has exactly these supported fields:

| Field | Contract |
| --- | --- |
| `run_id` | Server-configured nonsecret correlation ID, 1–64 ASCII letters/digits/hyphens. Use a fresh ID for each process/configuration segment and correlate it with the auth campaign externally. |
| `app_source_revision`, `provider_source_revision` | Explicit 40-hex source pins; verify them against the source/image/deployment receipts. |
| `expires_at` | Unix seconds, future and no more than six hours from startup. Also bound to a monotonic process deadline; no reload/extension endpoint. |
| `max_attempts`, `max_flows` | 1–12 starts and 1–3 simultaneous pending flows, respectively; flows may not exceed attempts. There is also a fixed 256-request lifetime budget for start/callback handling. |
| `synthetic_tenant` | Must be `true`. This harness is not real-organization admission. |
| `auth_origin` | Explicit HTTPS origin with no credentials/path/query/fragment; planned value `https://auth-staging.getforma.dev`. The exact callback above is hardcoded. |
| `tenant_slug`, `tenant_id` | Trusted provider slug and actual `ten_<UUID>` returned by provisioning. A bare app organization UUID is refused. No internal-organization grant or mapping is inferred. |

The operator provisions an explicit least-privilege, server-only provider invitation outside GenUI and supplies its capability here. This harness has no management key, invite issuance, tenant creation or generic registration API. After signup consumes that invitation, later existing-user login requires an explicit configuration with the verified subject and null invitation. Separate tenant/configuration runs supply Northstar/canary negative evidence; users cannot select tenant identity.

Run one GenUI service process/task for this bounded in-memory rehearsal. All flow state, receipts and counters disappear on restart; old cookies cannot resume it. Save the sanitized operator receipt before a deliberate restart/shutdown and reconcile any unresolved provider outcomes through the auth owner. This is not APP-009's persistent session/admission implementation.

## Provider boundary and honest cleanup

Invited signup sends a backend form to `/t/{slug}/oauth/par`; only the bounded returned URI reaches the browser. Existing-user login builds the reviewed authorize query. Backend JSON `/t/{slug}/auth/token` carries `grant_type`, `code`, `code_verifier`, `client_id`, exact `redirect_uri`. Only the canonical verifier releases an external identity in production. Its tenant must equal trusted configuration; token-response `user.id` must match verified subject, and email/mailbox metadata must match the configured fixture. There is no `user.tenant_id` or JWT mailbox claim. Provider response cookies are neither forwarded nor stored in a cookie jar.

Every provider response is bounded to 32 KiB, checked for expected status/JSON shape and refused on content encoding, unexpected fields, redirects or transport failure. Provider connect timeout is one second; each PAR/token/logout operation has a three-second whole-operation deadline. The canonical verifier retains its own two-second bound. Flow/rehearsal expiry is rechecked before recording success. No automatic provider request retry, proxy, response decompression, redirect following or background identity release is enabled.

After any parseable token response, the harness requests `/t/{slug}/auth/logout` with the refresh token in backend JSON and access token in backend Authorization, then drops both. It reserves `cleanup_unknown` **before** the token request and retains that unresolved count on timeout, malformed response or cancellation at any await; only logout acknowledgement clears it. Provider logout204 is **not** proof of refresh revocation: the reviewed handler suppresses a database update error. The operator receipt always says `provider_revocation_proved:false`; actual subsequent refresh denial or provider management reconciliation remains the auth owner's acceptance. Issued access JWTs may remain valid until expiry. No app access was granted at any point.

All harness responses use no-store, no-referrer, nosniff and a deny-all CSP. The callback does not log queries, headers, payloads or Location. Actual ingress/proxy/query logging and real browser-history privacy still require hosted inspection. The current no-SMTP provider plan cannot prove mailbox delivery; its verification page returns to fAuth platform login without a GenUI continuation. A successful identity-only receipt must not be promoted to verified-mailbox activation or public signup acceptance.

## Local verification

Run `python3 evidence/APP-006/hosted-callback/qualify.py` from the repository root. Add `--image-tag genui-app006-callback:local-20261028` to build and inspect a local image and run its binary in an isolated network namespace with a read-only root and synthetic configuration. This never publishes an image or deploys resources. The root Docker context allowlist excludes evidence, private state, credentials, generated assets, dependencies and caches; it includes the canonical verifier source beside app sources.

`local-checks.json` records actual commands, outputs, source hashes and results. The callback suite's `cfg(test)` identity fixture covers state, bindings and actual loopback token/PAR/logout HTTP transport; it does **not** prove integrated canonical cryptography. The separate unchanged verifier's 23 tests cover real Ed25519 signatures, claims and bounded loopback transport. `http_probe.py` exercises the real native listener, disabled-default404, enabled callback303, unauthorized/malformed start403, protected-route404, managed-ready503 without a real probe, restart and output privacy.

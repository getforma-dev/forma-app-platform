# Independent APP-006 callback review

**Verdict: no remaining blocking finding in the reviewed app/build sources after the cancellation and Docker-context repairs.** This approves the local source preparation, not hosted identity, mailbox delivery, provider revocation, membership, entitlement, application sessions or deployment acceptance. The reviewed uncommitted source hashes and exact checks are in [independent-review.json](independent-review.json).

The reviewer did not author or edit the callback, its tests, Cargo files, Dockerfile or ignore rules. Review covered `app/src/auth_qualification.rs`, its tests, `lib.rs`/`main.rs` wiring, Cargo manifest/lock, Dockerfile, root ignore rules and the app instructions. The canonical verifier's production constructor and the final FormaStack `GENUI-IDENTITY-CONTRACT.md` were also inspected. No credentials or AWS resources were accessed.

The harness is disabled when its configuration path is absent and refuses invalid explicit configuration before listening. A private, owned, bounded configuration fixes the provider endpoint, callback, external tenant/client identifiers, expected identity, operator capability, expiry and attempt limits. Start/status require the operator capability. Runtime construction exposes only the canonical verifier; the callback tests' noncryptographic identity fixture remains behind `cfg(test)` and cannot be selected through production configuration.

Each flow uses independent random cookie/state/PKCE material. The `__Host-` cookie is Secure, HttpOnly and SameSite=Lax; code exchange occurs only on the backend. A valid-shape callback identifying a cookie removes its flow under a mutex before provider I/O, including on state mismatch; simultaneous and sequential replay cannot exchange twice. Malformed input is refused before identifying a continuation and is not claimed to consume an otherwise unknown flow. Expired/restarted flows refuse.

Provider requests have fixed destinations, no redirects/retries/proxies/cookie jar, bounded connection/total deadlines and response-size/type checks. The canonical verifier separately bounds key retrieval and verifies tenant/issuer/audience/signature/lifetime. Callback logic also binds signed subject to response `user.id`, configured tenant and optional expected subject, validates explicit mailbox metadata, and rejects unsupported token/authentication shapes. No role, email or successful identity check becomes application authority.

Browser callback responses clear the local flow cookie and redirect to one fixed token-free result route. Provider tokens, cookies, invitation capabilities and response URLs are not forwarded or logged. Operator receipts expose only bounded counters and selected non-secret identity/run metadata. Configured source pins are explicitly declarations that still require deployment/image receipts. Provider HTTP204 remains an acknowledgement; every status receipt retains `provider_revocation_proved:false`.

Two findings were repaired during review:

- **Cancellation accounting:** previously, dropping the callback future after exchange began could leave remote refresh material unresolved while `cleanup_unknown` stayed zero. The author now reserves unresolved cleanup before the first exchange await and clears it only after logout acknowledgement. Tests abort both during exchange and while verification is pending, then verify that unresolved cleanup remains recorded and replay still cannot exchange again.
- **Docker context privacy:** the original parent-directory exceptions re-included broad descendants. An actual scratch `COPY .` transferred 2.64 GB before the reviewer's timeout. The author added descendant exclusions after each parent exception and exact filename exceptions. A new actual export completed with **exactly 24 allowed files**, no missing/unexpected files and matching source hashes. The temporary export was removed. [Successful inventory](independent-context.json) and [initial failure](independent-context-initial-failure.json) remain separate. Root owns the workflow invocation's required repository-root context.

Independent validation: `CARGO_BUILD_JOBS=2 cargo test --manifest-path app/Cargo.toml --locked auth_qualification -- --test-threads=1` passed **11 tests**, including cancellation, concurrent replay, PKCE, tenant/subject binding, response leakage, token/logout timeouts and provider-failure cleanup. `git diff --check` passed. The successful Docker inventory verifies context selection, not a new deployed image. The author's broader app/canonical-verifier/native-HTTP/local-image evidence was inspected separately; it is not presented as an independently repeated campaign.

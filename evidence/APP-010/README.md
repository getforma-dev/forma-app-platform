## How each operation works

- **Re-admission inside storage.** `AdmittedDefinition` has public fields, so storage never takes one on trust: its canonical content is wrapped in an envelope under the trusted organization and the path's app and admitted again, whole; the result must equal the caller's value (digest, bytes, edition, registry versions). Input contracts (`forma:input-contract:v1`) and record schemas (`forma:record-schema:v1`) are derived from the admitted bytes. Phase 1 stores edition 1 only (0002 `CHECK (schema_version=1)`): an edition-2 definition admits in `crate::admission` but storage refuses it with `Denied` and writes nothing.
- **Draft** (`create_definition_revision`, workspace, READ COMMITTED): provider-identity confirmation, precheck `edit_definition` on the app, `lock_member_authority` fence, then the revision, its inputs and record schemas and one `definition.drafted` event (outcome digest = the definition digest).
- **Publish** (`Control::publish`, SERIALIZABLE): the policy's newest version selects the authority — `owner_publish`: the app owner with `edit_definition` is author and approver; `independent_review`: a member other than the owner with `review_publish` approves the owner's revision. The stored revision is re-admitted and its contracts must equal the stored rows; the envelope is the edition-1 `publication` document (`input_contract_digests` in definition order, `record_schema_digests`, registry versions 1, `admission_digest`, policy, author, approver and epoch, whole-second `published_at`), stored canonically with its `publication_inputs` and `publication_record_schemas`, then one `publication.published` event. A 40001 at any statement or at COMMIT rolls back whole and is retried once in a new transaction; a second is `Stale` naming the app's newest publication, read under the publisher's current authority.
- **Save work** (`create_work`, workspace): precheck `run` on the app; every published input bound exactly once; a source binding needs `source_read` on that source (re-read after the fence), a live revision and a `contract_digest` equal to the published input's; a records binding names a published record schema whose `fields` equal the input's; one collection per published record schema; `saved_work` at version 1; one `work.saved` and one `work.bound` per binding (outcome digest `forma:source-binding:v1` over the binding document). No grant on the new work is written (permission rows are the operator channel's, D7.3).
- **Read back**: `read_definition` (`edit_definition`), `read_publication_detail` (`discover`; envelope plus each published input's canonical contract), `read_work` (`record_read`, which also needs `run` and `source_read` on every dependency); canonical bytes bounded at 262,144.
- **Audit (D7.8)**: lock the role's own head `FOR UPDATE`, sequence + 1, `previous_hash` = head, `hash` = SHA-256(`forma:audit-event:v1` ‖ 0x00 ‖ previous ‖ forma-json-v1 of every column but `hash`), insert, advance the head; event id and whole-second UTC time come from the database. A missing head is `Configuration`. The operator `verify` command recomputes both chains.

## Decisions made in this slice (for review)

1. **`admission_digest` is the admitted digest.** Design §6.2 and its glossary say admission "fails whole or produces an admitted digest"; the publisher re-admits the stored content and records that digest, so in edition 1 `admission_digest == definition_digest`. A separate admission-record identity would need a new digest domain (an ADR-002 contract change).
2. **Author is the app owner.** `definition_revisions` has no author column; the publication's `author_id` is `apps.owner_principal_id`. `owner_publish` requires the owner with `edit_definition`; `independent_review` requires a non-owner with `review_publish` (the 0002 CHECK enforces author ≠ approver).
3. **`create_work` takes `context`** (the 0002 column, ≤2000 characters) in addition to the plan's signature.
4. **Own-chain head reads** are RESTRICTIVE SELECT policies (D7.3 "audit_heads (own chain)"), in addition to D7.8's INSERT and UPDATE bindings; the qualifier now expects ten non-`tenant_scope` audit policies.
5. **All 0005 grants are column-level**, as 0003/0004, so table-level privilege probes (`reset_trial`, the qualifier) still see no application write.
6. **Owner-chain event outcomes:** `definition.drafted` and `publication.published` carry the definition digest, `work.bound` the `forma:source-binding:v1` digest of the binding document, `work.saved` none.

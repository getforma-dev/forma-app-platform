- Commit reviewed: `6ed4898` on `pivot/pitch-mvp` (merges `11761a8` composer and `efff3ed` library). Read-only: a `git archive 6ed4898` copy in the session scratchpad ran every command; this file is the only write in the clone, uncommitted.
- Reviewer: Claude (Fable 5.1), 2026-10-30. No AWS, no real model key, other sessions' Docker containers untouched (container set identical before and after each campaign).
- Context applied: ADR-011 §3 invariants (I1 verified identity, I2 isolation and uniform 404, I3 receipts, I5 model output is data entering only as a typed definition through admission and labeled, I6 no secrets in evidence), AGENTS.md, ADR-007 D7.3 (operator-only grants and app creation, creator authority), ADR-009 (engine lockdown, receipts, release at delivery).

## Verdict

**Pass with conditions (no blocker).** The authority seams hold: model text reaches storage only as an `AdmittedDefinition` produced by `admit_definition` under an envelope whose organization and app come from the session, never from the model; the router can only pick an index of the catalog it was shown; every source input is pinned to a contract the member holds `source_read` on and re-checked at `create_work`; publication needs the member to own the app under the organization's `owner_publish` policy; a foreign organization's library is never offered; the key leaves the process only as the `x-api-key` header; no log carries the intent, a definition or the key; the engine's typed path refuses every field-type confusion with a code, keeps integer/money math exact and leaves receipts and release-at-delivery unchanged; `GET /v1/library` lists only works the member may open; `seed-library` is exact-match idempotent and fixture-organization-scoped.

Five majors must be fixed or recorded before the pitch deploy: an anonymous request can hold the 120 s route deadline at the body read (M1); generation and adaptation publish onto the member's lowest-id owned app, which in the seed is a **library** app, so the library entry disappears from the composer's catalog after one generation (M2); the workspace/library listing cap of 50 saved works, ordered by `app_id`, is crossed after ~37 compositions and silently drops library apps (M3); money columns are rendered as digit-grouped minor units (M4); the ALB idle timeout (60 s default) and the per-attempt budgets (192 s) are inconsistent with the 120 s route deadline (M5, partly recorded as debt in the ticket).

## Findings

### Blocker

None.

### Major

**M1. Anonymous requests hold the 120 s compose deadline at the body read.** `app/src/composer/routes.rs:509-518`: the order is fetch-metadata → `to_bytes(body, 4096)` → `member()`. `sec-fetch-site: same-origin` is a free header for a non-browser client, so an anonymous caller that sends one body byte and stalls is held by the handler until `long_deadline` (120 s, `app/src/http/mod.rs:190-194`) instead of the 5 s the rest of the service enforces, without any session, store or limiter cost to the attacker. `axum::serve` sets no header/body read timeout (`app/src/main.rs:648`).
Probe P6 (`review_probes::p6_anonymous_slow_body_is_held_past_the_handler_deadline`): a stalled body on `app_without_store` is still pending after 7 s (> `HANDLER_DEADLINE` 5 s).
Fix: resolve the session (and apply the member limiter) before reading the body, and bound the read: `tokio::time::timeout(http::HANDLER_DEADLINE, to_bytes(body, COMPOSE_BODY_LIMIT))` → 413/408-as-uniform-404. The long deadline should start only once the member is known.

**M2. Generated and adapted definitions are published onto a library app and displace it in the composer's catalog.** `app/src/storage/composer.rs:225-234` picks the authoring app as the member's lowest-`app_id` owned app with `edit_definition`+`run`. Every library fixture (`contracts/fixtures/library/*.json`) and Northstar are owned by principal `…0066` and published `owner_publish`, so for the demo author the authoring app is `…000065` (Northstar) or `…001001` (expense-review) when Northstar is not seeded. `draft_publish_save` (`routes.rs:304-322`) publishes a new revision there; `composer_context` reads **the newest publication per app** (`composer.rs:285`), so after one generation the catalog the router sees no longer contains that library app's definition, and `Decision::Retrieve` on it now instantiates the generated definition. The campaign confirms the mechanism ("one more publication on APP"). `GET /v1/library` is unaffected (it pins the seeded work's publication, `queries.rs:935`), so the two catalogs diverge.
Fix: seed one dedicated authoring app per demo author (an `apps` row with `edit_definition`+`run`, no publication) and in `composer_context` prefer an owned app whose newest publication digest is not a library sidecar digest; or exclude apps whose current publication is a library digest from the authoring choice and record the consequence in APP-097.

**M3. The 50-work listing cap is crossed by compositions and silently hides library apps.** `app/src/storage/queries.rs:769` (`LISTING_CANDIDATES = 50`) and `:800` (`ORDER BY app_id, work_id LIMIT 50`). Every composition inserts a `saved_work`; generated/adapted works land on the authoring app, whose id (`…000065`) sorts before every library app (`…001001`+), so after about 37 compositions in an organization the 13 library works fall off `openable_works`, hence off the canvas (`query/canvas.rs:471`), `GET /workspace` and `GET /v1/library` (`queries.rs:921`). With 6/member/hour this is one rehearsal afternoon. Pre-existing cap (APP-076 G9); the composer makes it reachable.
Fix: order candidates by `created_at DESC` (or page them), and let `library_catalog` select saved works whose pinned `definition_digest` is a sidecar digest directly instead of going through the capped listing.

**M4. Money and decimal columns are displayed as digit-grouped minor units / coefficients.** `app/src/query/worker.rs:785-787` (`integer_type` = integer | money | decimal) feeds `WorkView::integer_columns` → `page.rs:143 display` and `app/admin/src/canvas/render.ts:25`, which only group digits. The expense-review `totals` view therefore shows `26,262,004` for $262,620.04 (engine probe: `sum(amount)` = 26262004 minor units, exact against the DuckDB oracle). The math and the receipt are exact (I3 holds); the visible number is wrong by 100× and carries no unit. The sidecar and the contract carry `money {currency, minor_unit_exponent}` and `decimal {scale}` per field.
Fix: carry the column value type (or a per-column format) from `typed_integer_columns` to the page/island: money → insert the decimal point at `minor_unit_exponent` with the currency; decimal → at `scale`; keep integers grouped. Until then, exclude money/decimal from `integer_columns` so the raw minor units are at least not presented as a grouped count.

**M5. Deadline arithmetic and the ALB.** (a) `infra/src/stack.ts:276` creates the ALB without `idleTimeout`; the default 60 s is below `COMPOSE_DEADLINE` 120 s (`composer/mod.rs:69`), so a generation that takes over a minute is answered 504 by the ALB while the service continues (or is cancelled when hyper drops the connection), leaving a published revision without a work and a consumed rate-limit slot. The ticket records this as debt (4); it is a deploy precondition. (b) `ROUTER_BUDGET` 12 s + `MAX_GENERATION_ATTEMPTS` 3 × `GENERATION_BUDGET` 60 s = 192 s > 120 s (probe P8), so the third attempt can never run and a slow second attempt is cut by the outer timeout as 503 `unavailable` rather than the neutral 422; a cut between `publish` and `create_work` (`routes.rs:312-343`) leaves the published revision (acknowledged as debt (5)).
Fix: `alb` `idleTimeout: Duration.seconds(130)`; `GENERATION_BUDGET` ≤ 35 s or skip a retry when the remaining route budget is below one attempt; consider the stale-publication cleanup in APP-097.

### Minor

**m1. Free-text members are admitted unscanned; the renderers are the only line of defense for model-written and intent-written text.** `app/src/admission/validate.rs:484-495` (`text`: "bounded but never searched, since it is data"). Probe P1: a reply with `title = "<script>alert(document.cookie)</script>"`, `description` with `onerror=`/`javascript:`/SQL and a view title with `</h3><a href=…>` is admitted and the title is returned in the compose response and stored. Probe P2: the adapted path writes the raw intent into the published description (`routes.rs:168`) and the router's `title` into the title. This is admission's documented design (I5 is about executable members, not text), and no `innerHTML`/`insertAdjacentHTML` exists under `app/admin/src/canvas/` (titles are JSX text children, `app.tsx:185,220,286`; SSR goes through the Forma renderer). Two consequences worth recording: the ticket's acceptance line "hostile model output … never rendered" is true only for executable members, and the model-written `description` of a published app becomes the `purpose` other members' router prompts see (`prompt.rs:183`), a prompt-injection channel bounded to a catalog index. Suggested: a canvas/page test that renders a work whose title and note text carry markup and asserts textContent, and truncate/sanitize what reaches `router_user`.

**m2. `runnable_view` differs from `outline`'s rule.** `app/src/composer/prompt.rs:140-159` accepts a data view whose one input is a `records` input; `storage::queries::outline` (`queries.rs:691`) requires a `source` input and `run_query` denies it. Probe P3: a generated Spend Review whose first data view counts the `decisions` records input passes `require_runnable`, is admitted, published and saved; the view is never listed (shown as nothing, never a number). Fix: in `runnable_view`, require the input id to name a `source` input of the content.

**m3. No organization or service window on compose.** `routes.rs:52,528-531`: 6/member/hour keyed `compose:{org}:{principal}` only (probe P7). Worst-case spend is 6 × members × (1 Haiku + up to 3 Sonnet at 8000 output tokens) per hour; the limiter is in-process (D7.18) and resets on restart. Fix: add a service-wide window like `SIGNIN_GLOBAL` (e.g. 60/hour) and check both keys in one `admit`.

**m4. Engine literal parsing hardening.** `app/runtime/query_engine.py:141,145,149`: `int()` on a non-digit `value`/`minor_units`/`coefficient` raises `ValueError`, which `main` reports as `failed/engine` instead of `refused literal_not_qualified`; `int()` also accepts Unicode digits (`"١٢٣"` → 123). Unreachable through an admitted definition (the contract grammar is ASCII digits) and the only client parameter is the text `destination`; still cheap to close with `re.fullmatch(r"-?[0-9]+", …)`. Every other confusion probed (money vs integer literal, wrong currency, sum over text, time_bucket over text/date, window over a non-timestamp `time`, undeclared field, other input, reference-typed field, extra field key, 33 fields, duplicate field, post-aggregate filter, limit not last, 17 operations, SQL-shaped measure/output ids) is refused with a fixed code. A contract/file type mismatch (operator-caused) produces a DuckDB binder/conversion error → `failed/engine`, never a number.

**m5. No route-level test for `GET /v1/library`.** `app/src/query/routes.rs:144-172` is covered only through `Data::library_catalog` in the campaign; anonymous, wrong-method and store-outage answers of the route itself are untested. Fix: add to `route_tests.rs` beside the query route cases.

**m6. Candidate caps in `composer_context`.** `composer.rs:36,38`: 24 publications and 64 source revisions, ordered by id; beyond them the composer silently omits apps/sources. Adequate for 13 + a few; record it with M3.

**m7. `seed-library` is fixture-organization-only.** `app/runtime/tenant_seed.py:15,90` (`ORGANIZATIONS` = the two fixture ids). The beta organization must be one of these or APP-096 must extend the allowlist deliberately; the command itself is exact-match idempotent (`put` ON CONFLICT + equality, campaign: second run `changed: false, rows_inserted: 0`) and scoped by `begin`/`lock_organization`/`set_config('genui.organization_id')`.

## Claims I tried and failed to refute

1. Model output enters storage only through `admit_definition` with the envelope's `organization_id`/`app_id` taken from the session (`plan.rs:207-219`); the router reply only selects a catalog index and an ≤80-char title (`plan.rs:46-77`); `reason` is dropped. No path from model text to SQL, markup, FMIR, URL fetch, grant or permission row: the campaign footprint shows zero app/permission/grant rows written for retrieved, generated and adapted compositions.
2. Sources: `pin_sources` replaces every `source` input with the member's exact readable contract or refuses (`plan.rs:162-188`); `bindings` match by contract digest within `context.sources` (SourceRead-filtered, `composer.rs:245-281`); `create_work` re-checks `source_read` and the revision's `contract_digest` (`definitions.rs:800-804`). Library source contracts are pairwise distinct (only the shared `decisions` records schema repeats), so a binding is never ambiguous.
3. Publication: `publish_once` requires the policy kind `owner_publish`, `edit_definition` on the app and `owner == request.principal` (`definitions.rs:1040-1050`); the policy id is the organization's newest `owner_publish` row. A member who owns no app cannot generate or adapt (`no_authoring_app`; adapt falls back to retrieve).
4. Retrieval is closed to the member's library: publications scoped to the organization under RLS and filtered by `discover`+`run` per app, kept only when bindable now (`composer.rs:285-315`); campaign check 1: the foreign organization never sees the other's apps; the stranger composes nothing before any model call.
5. Rate limit and deadline for a signed-in member: 6/hour/member admitted before `compose_for`; at most six concurrent 120 s requests per member per hour; nothing in the handler loops beyond `MAX_GENERATION_ATTEMPTS` × `MAX_ATTEMPTS` with per-call budgets.
6. Logging: every `tracing::` call in `composer/` carries ids, codes, counts, digests, durations and the model name only; `ApiKey`/`Anthropic` `Debug` redact; the key is read from `ANTHROPIC_API_KEY` in `composer/model.rs` alone; engine children run `env_clear()` (`supervise.rs:185`); `composer_smoke.sh` exports the key from a gitignored `.env` without printing it; `evidence/APP-094` carries no key, address or e-mail pattern. The intent is stored as `saved_work.context` (by design, ≤ 2000 chars), not logged.
7. Engine: `fields` and `input_id` come from the re-admitted definition in the Rust parent (`worker.rs:526-528`), never from the client; the child re-parses them (`parse_fields`, 32 max, closed key set, column types only); the client chooses only `view` and the closed `window`/`destination`/`filter_epoch` parameters, which `Parameters::apply` refuses unless the input has a timestamp `time` / text `destination` (`queries.rs:336-358`). POLICY, the one-file allowlist, the read-only private database, the 501-row bound and the deadline are unchanged; `run_query`/`release_result` pin and re-check publication, work version, definition digest, policy epoch, binding and dependencies exactly as before (`queries.rs:519-634`).
8. `GET /v1/library`: `library_catalog` is `openable_works` (discover + record_read after the member fence) filtered by sidecar digest; the sidecar is compiled-in public fixture metadata (`queries.rs:855-978`); campaign: the reviewer without grants gets an empty list and is denied before any engine.
9. `seed-library`: validates every fixture's sha256 against the catalog before the first write, `ON CONFLICT DO NOTHING` plus equality check, refuses whole on a differing row, no audit event (D7.8 names no kind), fixture organizations only.

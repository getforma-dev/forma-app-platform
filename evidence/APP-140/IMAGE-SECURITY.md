# APP-140 runtime image security follow-up

Observed November 1, 2026. The immutable Linux ARM64 children of the service, qualification and operator images for `0ec5e94838dfc0a85c41f4d1735747bdf9042fdd` each had **0 critical, 25 high, 19 medium and 5 low** findings. All three ECR scans completed; this is not a zero-vulnerability result. The sanitized [triage record](image-security-triage.json) records their exact index/child digests and every finding.

The user requested fixes for available findings. The three runtime Dockerfiles retain the existing OpenSSL, GnuTLS and Perl fixes from [APP-078](../APP-078/window/README.md) and now pin all available Bookworm fixes for this scan: **14 high, 9 medium and 2 low findings** across 14 binary package updates. This supersedes the earlier blanket deferral for findings with available fixes. No new base distribution, unreviewed repository, unpinned general upgrade, package removal or scanner suppression was introduced.

At this record, only package availability and dependency resolution have been verified. The next clean commit must build and qualify all three images, then the pushed ARM64 child digests must be scanned again. Expected counts based on Debian status are not a substitute for those scan results. The remaining **11 high, 10 medium and 3 low** findings are vendor-open in Bookworm; applicability is assessed below without calling them fixed.

## Findings retained without a Bookworm fix

These are deployment-scope assessments, not general claims that a vulnerable package is safe. Current entry points run as UID/GID `65532`, and the ECS definitions use a read-only root filesystem. The service exposes no user shell, package installation, namespace/mount operation, raw SQL execution or environment-setting API. The runtime probe confirmed ARM64, `LANG=C.UTF-8`, no `LANGUAGE`, an empty effective `/etc/fstab`, and no `sqlite3` executable. It also found 11 setuid/setgid binaries inherited from the base image, so this review does not claim their absence.

## Evidence and validation

- [ARM64 package versions](arm64-apt-policy.txt) and [additional medium/low packages](arm64-other-apt-policy.txt): fresh APT indexes read inside a disposable, read-only container of the exact qualified service image, with only temporary APT directories writable.
- [Dependency resolution](arm64-security-upgrade-plan.txt): `apt-get -s install --no-install-recommends --only-upgrade` with the exact new pin set succeeded: 14 upgraded, zero new packages, zero removals. The previous four security packages remain at their fixed versions.
- [All18 AMD64 package pins](amd64-package-pins.txt) and [libcap candidate](amd64-libcap-policy.txt): each exact runtime pin is available for the CI image architecture, including the architecture-sensitive binary rebuild suffix.
- [Runtime applicability probe](runtime-applicability.txt): the original immutable ARM64 image was inspected without changing it.
- Operator package suite: 39 tests ran, 33 passed and six image-dependent tests skipped. Those six remain required in the rebuilt-image qualification. `git diff --check` passed; all three runtime package blocks were compared and are identical.
- Production configuration references: `infra/src/stack.ts`, `infra/src/shared-broker.ts`, `app/runtime/query_engine.py` and the three Dockerfile entry points. Static review does not prove every transitive library call unreachable.

No registry scan was started by the reviewer; ECR scan-on-push had already completed. No AWS runtime was changed. The old images are retained as evidence and are not the corrected deployment candidate. Registry findings may change as vendor data changes; rerun the exact-child scan review after the replacement images are pushed.
